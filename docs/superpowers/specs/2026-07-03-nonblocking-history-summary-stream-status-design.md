# 阶段 6：非阻塞历史摘要与流式状态反馈设计

## 目标

长对话达到摘要门槛后，当前问答不等待摘要模型；流式问答在答案 token 到达前向用户展示明确的处理阶段，并在所有结束路径清除临时状态。

## 范围

- 历史压缩默认在 20 轮后触发，保留最近 8 轮，摘要继续使用 `helper_llm_model`。
- 摘要仅使用进程内缓存，不实现持久化。
- 后台摘要全局最多并发一个任务。
- SSE 增加向后兼容的 `status` 事件。
- 前端状态只存在于运行时消息，不写入聊天记录。

## 后端设计

### HistoryCompressor

`compress()` 保持同步接口，但只做门槛判断和缓存读取：

1. 关闭 `enabled` 或历史未超过门槛时，原样返回历史且不创建任务。
2. 缓存命中时，返回摘要与最近 8 轮历史。
3. 缓存未命中时，立即返回完整原历史，并尝试启动后台摘要任务。

缓存、运行中任务标识和失败冷却截止时间由同一把锁保护。任务启动前在锁内检查：当前是否已有任务、当前 key 是否已缓存、全局冷却是否有效。任一条件不满足均不启动。后台任务成功后写入缓存；失败后设置 300 秒全局冷却；无论成功失败都清理运行中标识。

缓存 key 沿用现有历史指纹逻辑，摘要生成沿用现有增量摘要能力与 `helper_llm_model`。首次缓存未命中的请求使用原历史，后续相同历史请求才使用摘要。

### 流式状态协议

`stream_query()` 根据处理进度发送事件：

1. `正在理解问题...`
2. `正在检索知识库...`
3. `正在整理答案...`

状态事件使用内部结构 `{type: "status", data: string}`。SSE 路由将其编码为具名 `status` 事件，同时保留 JSON `data` 结构，使忽略未知事件的旧客户端继续工作。

问候分支只需要“正在理解问题”；知识不足分支在检索后结束；异常分支发送已经实际进入的阶段后再发送错误 token。不会为未执行的阶段伪造状态。

## 前端设计

`queryKnowledgeStream()` 新增可选回调 `onStatus?: (status: string) => void`，SSE 解析器识别 `status` 事件并调用该回调，其他事件保持现有行为。

消息类型新增可选 `status` 字段。它仅用于当前助手消息：

- 收到状态事件时更新助手气泡。
- 气泡在没有正文 token 时展示圆点与状态文案。
- 首个 token、正常完成、异常、用户取消、SSE 不可用后切换非流式请求时清空状态。
- 历史映射和本地存储不包含该字段。

## 配置

历史压缩默认值调整为：

- `enabled = true`
- `trigger_rounds = 20`
- `keep_recent_rounds = 8`
- `failure_cooldown_seconds = 300`

开发与生产示例配置均补齐这些项目。`enabled` 是紧急关闭开关，关闭后不读取摘要、不创建后台任务。

## 测试

后端测试覆盖：

- 20 轮以内不触发摘要。
- 超过门槛且缓存未命中时立即返回原历史。
- 同一时间只启动一个后台任务，相同任务去重。
- 后台摘要完成后，后续请求命中摘要。
- 摘要失败后 300 秒内不重试。
- `enabled = false` 时完全不创建任务。
- 正常、问候、无知识和异常分支的状态事件顺序。
- SSE 对 `status` 事件的兼容编码。

前端验证覆盖 SSE 状态解析、助手消息更新及所有结束路径的清理。若现有前端未配置单元测试框架，则以 TypeScript 类型检查与生产构建验证集成为主，并将可独立测试的 SSE 解析逻辑放入现有测试方式中。

## 非目标

- 不持久化摘要缓存。
- 不引入外部任务队列或新的线程池框架。
- 不改变聊天记录存储格式。
- 不并发运行多个摘要模型请求。
