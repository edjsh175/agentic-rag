# 文档分类树与层级治理系统 · 产品需求说明书（PRD）

| 文档版本 | 修改日期 | 修改人 | 修改内容 |
|---------|---------|--------|----------|
| V1.0 | 2026-07-28 | 数据治理组 | 初稿创建：树形文档分类表结构、路径推断与前端管理 |


## 一、项目概述

### 1.1 项目背景

目前系统中的文档分类（`doc_category`）仅支持静态的平铺字符串（如 `StampTools`、`StampServer`）和基于配置文件的死板映射，无法满足复杂 GIS 产品线多层级手册（如 `系统全景 / 部署运维 / 数据库配置`）的管理需求：
* **难以层级检索**：无法按照父分类一键检索其下所有子分类的文档。
* **业务人员无法管理**：缺少可视化界面让管理员新增、重命名或调整分类层级树。

### 1.2 项目目标

构建**文档分类树与层级治理系统**：
1. **树形关系存储**：使用 `doc_categories` 数据表存储树形分类（支持无限级嵌套与 materialized path 快速检索）。
2. **动态自动挂载**：文档入库时能根据路径自动与分类树节点进行匹配挂载。
3. **可视化管理界面**：提供专用的前端分类管理视图（树形节点拖拽、合并、重命名、排序）。

### 1.3 系统角色定义

| 角色 | 职责 |
|------|------|
| **系统管理员** | 维护文档分类树（增删改查、移动节点、排序） |
| **业务审核员** | 在上传文档或审核 Chunk 时选择具体分类 |
| **检索服务** | 按照分类节点路径（Path）执行子树混合检索过滤 |

## 三、数据层详细设计

### 3.1 关系数据库表结构：`doc_categories`

| 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `id` | VARCHAR(36) | 是 | UUID | 主键 |
| `parent_id` | VARCHAR(36) | 否 | NULL | 父分类ID（根分类为 NULL） |
| `name` | VARCHAR(100) | 是 | — | 分类名称（同级节点不可重复） |
| `path` | VARCHAR(500) | 是 | — | 冗余物化路径（如 `/系统全景/部署运维`），用于高效前缀检索 |
| `sort_order` | INT | 是 | 0 | 同级显示排序序号 |
| `description` | TEXT | 否 | '' | 分类描述 |
| `icon` | VARCHAR(50) | 否 | 'folder' | UI 前端矢量图标名 |
| `created_at` | TIMESTAMP | 是 | Current | 创建时间 |
| `updated_at` | TIMESTAMP | 是 | Current | 修改时间 |

### 3.2 预置基础分类数据（Seed Data）

## 四、功能详细设计与后端 API

### 4.1 自动路径更新与子树检索逻辑

* **节点移动/重命名**：当修改节点 `name` 或移动 `parent_id` 时，系统递归更新该节点及其所有子节点的 `path` 字段。
* **子树过滤匹配**：检索时若选择父分类 `/系统全景`，SQL 查询会自动使用 `path LIKE '/系统全景%'` 包含其下所有子类知识块。

### 4.2 API 接口定义

#### 接口 1：获取完整分类树
* **HTTP 请求**：`GET /api/categories/tree`
* **Response**：
```json
{
  "categories": [
    {
      "id": "cat-root-1",
      "name": "系统全景",
      "path": "/系统全景",
      "children": [
        {
          "id": "cat-sub-1",
          "name": "部署运维",
          "path": "/系统全景/部署运维",
          "doc_count": 42
        }
      ]
    }
  ]
}
```

#### 接口 2：创建/修改分类节点
* **HTTP 请求**：`POST /api/categories`
* **Request Body**：
```json
{
  "parent_id": "cat-root-1",
  "name": "环境要求",
  "description": "硬件与软件环境要求手册"
}
```


## 五、前端交互与页面设计

### 5.1 文档分类管理页面 (CategoryAdminView)

1. **左侧分类树 (Tree View)**：支持展开/折叠、拖拽节点改变层级关系、右键弹出“新增子类/重命名/删除”。
2. **右侧明细面板**：点击树节点后展示：
   * 节点基本信息修改（图标、描述、排序）。
   * 该分类下包含的已上传文档列表及关联 Chunk 统计数。


## 六、业务流程说明

```
【添加新分类】 ──> 输入名称与父节点 ──> 计算物化 path ──> 存入 doc_categories
                                                          │
【扫描新文档】 ──> 提取相对路径 ──> 匹配最长 path 的分类 ──> 写入 Chunk metadata.doc_category
```


## 七、非功能性需求与界面规范

* **界面与内容禁用 Emoji 规则**：前端 UI 界面、树形节点图标、分类说明、对话框提示及系统日志中，一律禁止使用 Emoji 表情符号，图标统一使用 UI 组件库内置的 SVG/矢量图标。
* **层级深度**：最大支持 5 级分类深度。
* **数据一致性**：删除包含文档的分类节点时，提示“无法删除：请先迁移该分类下的文档”。


## 八、实施优先级与验收标准

* **验收标准**：
  1. 前端可在线新增节点并拖拽调整顺序。
  2. 检索勾选顶级分类“系统全景”时，能自动命中子分类“部署运维”下的所有 Chunk 知识块。
  3. 分类树与 UI 组件中严禁出现任何 Emoji 字符。
