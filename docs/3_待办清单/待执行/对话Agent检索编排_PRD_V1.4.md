## 一、 项目背景与问题根因

### 1.1 V1.3 实施暴露的核心痛点
在 V1.3 版本的运行中，系统在多轮对话（尤其是用户反问、质疑、否定）场景下，表现出严重的“呆板管线化”现象：
1. **决策大脑静默掉线**：调用本地 Ollama 决策时未传递全局 `num_ctx`，超过 4096 tokens 即报 HTTP 400，导致系统直接降级到写死的 `_decide_heuristic()` 规则流水线；
2. **工具存在强状态副作用**：`link_entities` 抓取到关键词后直接篡改全局 `head_entity`，即使用户在反问，也被强行锁定错误实体；
3. **生成规则形成“Prompt 绑架”**：System Prompt 严苛要求“只要有证据池就必须转述”，导致大模型即使在 CoT 中看懂了用户的质疑，也被迫打印无关表格；
4. **工具粒度割裂（空转工具）**：将“语境理解”和“查询改写”作为外部空工具注册，为了让前端展示步骤，导致 1 次提问需要经历 3 轮大模型 HTTP 往返，既拖慢响应速度，又增加了断裂风险。

### 1.2 V1.4 核心改进目标（四大收敛）
```text
┌────────────────────────────────────────────────────────────────────────┐
│                        V1.4 四大收敛架构                              │
├────────────────────────────────────────────────────────────────────────┤
│ 1. 底座全链路大窗口  ──→ 消除 4096 截断与决策掉线，杜绝假 Agent 降级  │
│ 2. 工具去副作用化    ──→ link_entities 纯只读返回候选，LLM 决定是否采纳│
│ 3. Prompt 意图分流   ──→ 技术知识依证据，对话释疑与纠偏还给大模型自由  │
│ 4. 标准流式 ReAct    ──→ Thought 内化理解改写，Action 直指真实外部工具 │
└────────────────────────────────────────────────────────────────────────┘
```

## 二、 第一性原理与架构设计

### 2.1 第一性原理（Principle A1–A14）

| # | 原则 | 详细说明 |
|---|------|------|
| **A1** | **LLM 负责思维与控制流，Harness 负责边界治理** | LLM 负责在 Thought 中进行语境理解、意图识别、改写推导、证据评估与下一步动作决策；Harness 负责工具鉴权、Schema 校验、循环步数预算与证据门禁，**不替大模型编排业务步骤**。 |
| **A2** | **Dialogue ≠ Evidence，但 Dialogue 享有会话解释权** | 对话上下文不可作为客观技术知识的依据；但当用户进行元对话（反问、质疑、纠偏、状态确认）时，LLM 有权基于 Dialogue 历史直接作答，不强套知识库证据。 |
| **A3** | **工具必须是纯函数/无隐式副作用（Pure Observability）** | 工具只负责“输入查询 → 输出观察结果”，**严禁在工具执行体内部修改 `ConversationContext` 的全局状态**（如锁死 `head_entity`）。状态迁移由 Agent 决策大脑裁定。 |
| **A4** | **思考流式直出，动作直指真实工具（模式 B ReAct）** | 语境理解与改写推导是 LLM 的内置思维过程（Thought），不包装为空转工具；每一次 Action 必须指向真正产生外部交互的工具（检索/图谱/反问/环境）。 |
| **A5** | **前端感知无损（Full ReAct Trace）** | 前端继续完整接收并呈现 `思考 1 → 动作 1 → 观察 1 → 思考 2 → 动作 2...` 的流式体验，消除空转工具带来的延迟浪费。 |
| **A6** | **底座透明大窗口** | 底层 LLM 通信必须全局默认携带 `num_ctx` 配置，杜绝任何内部调用点因漏传参而退化到 4096 限制。 |
| **A7** | **否定与纠偏具备主动防御（Negative Assertion Guard）** | 识别用户对前文实体的否定与质疑，主动切断实体继承，防止实体污染扩散。 |
| **A8** | **证据足即停（One-Shot Finish）** | 单次检索若已充分覆盖问题，立即决策 `finish`，严禁无意义地跑满补检预算。 |

## 三、 工具注册表收敛设计（Tool Registry）

### 3.1 废除空转工具，聚焦真实外部能力
在 V1.4 中，正式将 `understand` 与 `rewrite` 从 Tool Registry 中废除，内化为 Agent 决策的 `Thought` 阶段：

```text
【V1.3 工具列表】                        【V1.4 收敛后工具列表】
- understand (废除：内化为 Thought)       - retrieve_kb (知识库定向检索)
- rewrite    (废除：内化为 Thought)       - link_entities (图谱实体检索与消歧，纯只读)
- link_entities (只读化重构)             - clarify (会话级反问卡片暂停)
- clarify                               - reuse_evidence (复用前序已引证据)
- retrieve_kb                           - web_search (外部网页检索)
- reuse_evidence                        - environment.* (环境状态读取/操作)
- web_search
- environment.*
```

### 3.2 工具规范详细定义

#### 1. `retrieve_kb`（知识库检索）
- **输入 Schema**：
  ```json
  {
    "type": "object",
    "properties": {
      "query": {"type": "string", "description": "精准改写后的检索查询词"},
      "mode": {"type": "string", "enum": ["hybrid", "vector", "bm25"], "description": "检索模式"},
      "doc_category": {"type": "string", "description": "可选的文档分类过滤"},
      "gap_type": {"type": "string", "description": "补检缺口类型（仅补检时填写）"},
      "recovery_strategy": {"type": "string", "description": "补检恢复策略（仅补检时填写）"}
    },
    "required": ["query"]
  }
  ```
- **输出**：写入 `EvidencePool`，返回 `{"ok": true, "chunk_ids": [...], "count": n, "summary": "召回 n 个片段"}`。

#### 2. `link_entities`（图谱实体检索与消歧 · 纯只读）
- **职责**：仅根据 query 查询知识图谱，返回候选实体、置信度及一跳关系。
- **严格约束**：**不得在工具内部执行 `conv.head_entity = ...`**。仅作为 Observation 提供给模型参考。
- **输出**：`{"candidates": [{"canonical_name": "...", "confidence": 0.85, ...}], "relations": [...]}`。

#### 3. `clarify`（反问澄清卡片）
- **职责**：当问题极度宽泛多义且无法通过上下文消歧时，向前端派发澄清卡片并暂停当前请求。

#### 4. `reuse_evidence`（复用上一轮证据）
- **职责**：在连续直接追问且未发生切题或实体冲突时，将上一轮引用 chunk 提升为本轮可用证据。

## 四、 标准流式 ReAct 运行循环（模式 B）

### 4.1 单步决策与流式派发时序
```text
  [用户请求输入]
         │
         ▼
┌────────────────────────────────────────────────────────┐
│ AgentLoop: 构建决策 Prompt (携带 Context, History, Pool) │
└────────────────────────┬───────────────────────────────┘
                         │
                         ▼
┌────────────────────────────────────────────────────────┐
│ LLM 生成决策：流式输出 Thought                         │
│ 边推理语境、意图、改写 query，边决定 Action             │
└────────────────────────┬───────────────────────────────┘
                         │
        ┌────────────────┴────────────────┐
        ▼                                 ▼
   【action = "tool_call"】          【action = "finish"】
        │                                 │
  Harness 鉴权与 Schema 校验               进入 Answer Gate
        │                                 │
  执行外部真实工具 (如 retrieve_kb)          结合 EvidencePool 生成最终回答
        │                                 │
  生成 Observation (观察结果)              结束本次会话
        │
  回填 History，进入下一步循环
```

### 4.2 决策数据契约（JSON 格式）
Agent 决策大脑每一轮输出严格的结构化决策：
```json
{
  "thought": "分析用户当前问题包含代词指代，上一轮讨论的是管线数据结构，结合上下文改写为具体查询：PipelineBuilder 线表 字段规范。规划调用 retrieve_kb 检索知识库。",
  "action": "tool_call",
  "tool": "retrieve_kb",
  "arguments": {
    "query": "PipelineBuilder 管线线表 字段规范",
    "mode": "hybrid"
  },
  "gate": null
}
```

- **前端事件流映射**：
  1. `thought` 字段内容 → SSE `{"type": "thinking", "data": "..."}` 实时展示在前端“思考”步骤；
  2. `action="tool_call"` → SSE `{"type": "tool_start", "data": {"name": "retrieve_kb", ...}}` 呈现“动作”步骤；
  3. 工具执行完毕 → SSE `{"type": "tool_end", "data": {"ok": true, "summary": "召回 3 个文档片段"}}` 呈现“观察”步骤。

## 五、 生成提示词与意图分流规则

### 5.1 事实与会话分流规则
更新 `_AGENT_SYSTEM_PROMPT`，明确划定事实与会话的边界：

```markdown
## 事实与来源规则

1. 【知识库事实严格受限】：关于产品功能、配置参数、操作步骤、代码与技术规范等客观知识，必须严格来自 <evidence_pool>，每项事实后标注对应引用编号 `[编号]`。
2. 【会话元对话与反问释疑】：若用户提问是关于前序对话历史、会话状态的澄清、反问、质疑或纠偏（如“我没问过这个”、“我啥时候说是X了”等元对话），模型应优先基于对话历史以自然语言客观解释会话语境与原因，无须强行套用知识库证据池，严禁机械输出无关的技术表格或免责声明。
3. 【证据部分覆盖】：证据池仅覆盖部分内容时，先写出已有依据的实质回答并引用，再说明未覆盖部分。
4. 【无证据与非会话问题】：证据池为空且用户是在咨询具体知识时，原样输出：“当前知识库中未查询到相关内容。”
```

## 六、 验收标准与测试指标

| 验收项 | 目标指标 | 验证方法 |
|:---|:---|:---|
| **首字/检索延迟** | 相比 V1.3 降低 **50%~60%**（减少 2 轮空转工具 RTT） | SSE 耗时埋点与 `qa_trace` |
| **反问与纠偏表现** | 面对*“我啥时候给你说是X了”*，100% 走会话释疑，0% 机械打印 X 表格 | 自动化对话测试集 |
| **底座稳定性** | 长会话多轮场景下 Ollama 400 超限报错率为 **0%** | 多轮极限压测 |
| **前端体验完整性** | 前端完整呈现“思考 → 动作 → 观察”，无截断、无闪烁 | Web 前端视觉验收 |
| **客观知识准确性** | 严守 EvidencePool 事实，无幻觉与无依据编造 | 知识库基准回归测试集 |
