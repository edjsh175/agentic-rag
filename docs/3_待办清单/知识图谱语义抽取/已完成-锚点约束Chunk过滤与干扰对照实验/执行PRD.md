## 1. 背景与问题陈述

### 1.1 现象

用户口语问题（典型：「怎么用管线工具」）在锚定层可正确落到 `PipelineBuilder`，但 Hybrid 仍常召回并被回答采用**干扰 chunk**，例如：

| 错误来源 | 章节 | 为何被捞到 | 为何不算正确证据 |
|----------|------|------------|------------------|
| `2ca727efa70847b49f0f67528544d210.pdf` | `… > 管线更新服务` | 正文含「管线工具」字样 | 讲的是服务端增量更新，不是 PipelineBuilder 用法 |
| `StampServer用户手册_Rocky9 .docx` | `运维管理配置 > 数据配置 > 工程配置` | 「三个文件由管线工具配置产生」 | 讲的是服务工程配置引用，不是「怎么用管线工具」 |

同时，**正确证据**（如 `StampTools用户手册.docx` → `PipelineBuilder > …`）可能未进入引用，或进入了但仍与干扰并存，导致 LLM 引用不稳定。

### 1.2 根因判断

```text
口语 → soft_match / 改写 → canonical=PipelineBuilder ✅
              ↓
         Hybrid 全文检索（BM25 + 向量）
              ↓
    干扰文档因共享「管线工具」等表层词进入 top-K ❌
              ↓
    图谱未约束 chunk 入选（enabled=false）
              ↓
    回答 LLM 在污染 context 中选错引用 ❌
```

要点：

1. **锚定成功 ≠ 证据正确**：改写只增加正确 query，无法禁止干扰词命中。
2. **图谱只进 LLM、不进 Chunk 筛选**：关系摘要/改写无法剔除已召回的错误块。
3. **换回答模型优先级低**：多数情况下只改变「在污染 context 里选谁」，治不好入口污染。

### 1.3 与既有工作的边界

| 工作 | 关系 |
|------|------|
| 主干锚定 A1/A2 | 已解决口语→canonical；本 PRD 承接其后的 **chunk 筛选** |
| 覆盖集 v5 | 测全库召回分布；本 PRD 用 **小语料+干扰** 归因，不替代 v5 |
| 第 4 轮 GraphRAG | 全库开图 chunk 融合前，须先用本实验证明「约束召回」可行 |

## 4. 实验设计

### 4.1 语料集合（最小）

**正例（须能回答「怎么用管线工具」）：**

- `StampTools用户手册.docx` 中 `PipelineBuilder` 相关章节（工程设置 / 数据设置 / 值域映射等）

**干扰（含「管线工具」表层词，但答非所问）：**

- `StampServer用户手册_Rocky9 .docx` → `运维管理配置 > 数据配置 > 工程配置`（管线配置三文件说明）
- `2ca727efa70847b49f0f67528544d210.pdf` → `… > 管线更新服务`（服务端更新）

可选再加 1～2 个弱相关块（仅含「管线」无「工具」）作对照噪声。

> 实现上优先在 **现有 live 库** 上用固定题 + 人工判定引用源；若需更干净归因，可再建隔离小集合（fork collection），本 PRD 不强制。

### 4.2 固定题集

| ID | 问法 | 期望锚点 | 期望引用主体 |
|----|------|----------|--------------|
| T1 | 怎么用管线工具 | PipelineBuilder | StampTools / PipelineBuilder 章节 |
| T2 | PipelineBuilder 怎么用 | PipelineBuilder | 同上 |
| T3 | 管线工具发布要配什么 | PipelineBuilder | PipelineBuilder 配置/工程设置类章节 |
| T4（对照） | 管线更新服务是做什么的 | （可为服务实体或无强锚） | 管线更新服务正例，而非 PipelineBuilder 教程 |

成功时：T1–T3 **不得**以干扰表中的两段作为主要引用；T4 不要求命中 PipelineBuilder。

### 4.3 对照条件

| 条件 | 配置 / 行为 | 目的 |
|------|-------------|------|
| **A. Baseline** | `enabled=false` + 现行锚定改写 | 复现现状 |
| **B. 锚点硬约束（优先）** | soft_hit 有 canonical 时：对检索结果按 `source` / `section_path` / doc_category 与锚点对齐做 boost 或过滤 | 验证「不靠图 chunk、只靠锚点元数据」是否够 |
| **C. 图扩召回小开（可选）** | 仅对 PipelineBuilder 等允许实体打开 `entity_chunk_links` 融合；仍不默认全库 | 验证图侧 chunk 是否优于 B |
| **D. 回答模型对照（附加）** | 同一检索 context 下换 1～2 个回答模型 | 证明问题主要在检索入口而非成文模型 |

**实施顺序**：A → B →（B 不足再）C → D 可选。

### 4.4 锚点硬约束（条件 B）建议规则

当 `backbone_canonical` 非空时（以 PipelineBuilder 为例）：

1. **优先保留**：`section_path` 含 canonical 名，或 `source`/`doc_category` 与主干实体所属产品线一致（如 StampTools）。
2. **降权或剔除**：仅因表层别名「管线工具」命中、但 `section_path`/`source` 指向 Server 运维/更新服务的块。
3. **失败降级**：若过滤后为空，回退到未过滤列表并打日志（不阻断问答）。
4. **开关**：独立配置项（建议名如 `anchor_chunk_filter_enabled`），默认 false；实验与生产可分开。

禁止：为过题硬编码文件名白名单写死进主路径（应用「锚点实体 → 产品线/章节模式」的通用规则；PipelineBuilder 作为首个验收实体）。

## 5. 成功标准

### 5.1 定性（必须）

- [x] T1–T3：锚定 `canonical` 稳定为 `PipelineBuilder`（soft_hit 不被改锚）
- [x] T1–T3：主要引用落在 StampTools / PipelineBuilder 正例章节（**条件 C**；B 在 T3 仍正例缺失）
- [x] T1–T3：干扰两段 **不作为主要 cited 来源**（B/C 干扰率 0；A 的 T1 仍有干扰）
- [x] 条件 B 相对 A：干扰引用率下降（0.33→0）；正例率持平 0.67；C 正例率升至 1.0
- [x] 改写/过滤失败时主问答不崩溃（空结果回退）

### 5.2 定量（小样本，人工可判）

对 T1–T3 各跑 ≥3 次（或固定 temperature=0 跑 1 次 + 抽检）：

| 指标 | 目标 | A | B | C |
|------|------|--:|--:|--:|
| 正例章节命中率 | ≥ 2/3 | 0.67 | 0.67 | **1.0** |
| 干扰章节主引用率 | = 0 或显著低于 A | 0.33 | **0** | **0** |
| 空答 /「无可验证引用」率 | 不高于 A | 0 | 0 | 0 |

详见 [实验记录-2026-07-24.md](实验记录-2026-07-24.md)。

### 5.3 Go / No-Go

| 结果 | 下一步 |
|------|--------|
| **B 足够** | 将锚点 chunk 过滤做成可配置能力；第 4 轮图 chunk 仍可延后 |
| **B 不足、C 明显更好** | 进入小范围 allowlist 图扩召回设计，再开第 4 轮准备 |
| **B/C 都不够** | 回头查正例入库/切块是否缺失，或干扰词权重；不扩大图召回范围 |

**本轮裁定（2026-07-24）**：**B 不足（T3 正例未入选）、C 明显更好**。  
已落地：`anchor_chunk_filter_enabled` + `anchor_graph_chunk_enabled`（生产模板默认 false；本地可开）。**第 4 轮其后已 PASS**；生产默认 on 仍未批准。

```text
1. 固定 T1–T3（+T4）题集与正例/干扰清单，跑条件 A 基线（人工记 cited）
```

## 8. 风险与注意

1. **live 库并发**：实验脚本只读 Chroma；改配置需重启后端。
2. **过滤过猛**：正例元数据不规范（无 section_path）时可能误杀 → 必须有空结果回退。
3. **别名污染面广**：「管线」出现在 Server/更新/WebGL 等多处；约束必须以 **canonical + 产品线/章节** 为准，不能只靠别名字符串。
4. **与 v5 调参并行时**：本实验归因优先；全库分数波动不作为本 PRD 成败依据。
