## 1. 梳理口径

本次以截图中的 STAMP 产品架构为主干，按“数据处理 → 数据存储 → 三维服务 → 三维渲染 → 业务应用”的产品链组织关系。

PPT 与白皮书作为补充依据：

- PPT 确认 `StampGIS Tools`、`StampGIS Server`、`StampGIS Client`、`StampGIS 二次开发` 等产品体系入口。
- PPT 确认 Tools 主要构成：`Terrain Builder`、`Vector Builder`、`Model Builder`、`Pipeline Builder`、`Visual Editor`。
- PPT 确认 Server 主要构成：基础服务、矢量服务、数据库服务、管线服务、规划服务及授权服务等。
- 白皮书确认系统五层结构：工具集、系统数据、系统服务、业务应用和客户端。

## 4. 当前 JSON 草案处理原则

- `belongs_to` 已按产品主干需要支持 `Tool/Service/Module → Module`，用于表达“层级 → 分支 → 叶子”的树状归属。
- 五个主干层级仍归属于 `StampGIS三维产品`，具体工具、数据、服务、渲染和业务应用分别归属于对应层级。
- 五层之间的链式依赖用 `requires` 表达，避免扩展 schema。
- 数据存储层实体当前暂按 `Module` 写入；若后续要表达真实数据对象，可再扩展图谱 schema。
- `.so` 文件、支持格式、部署组件、操作系统/中间件等暂不进入产品关系主干。
