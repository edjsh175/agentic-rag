## 一、项目概述

### 1.1 背景与问题

图谱语义抽取已具备规则管线、LLM 抽取、候选 staging、审批 apply，以及 StampTools 等品类上的试点经验。当前矛盾集中在三点：

| # | 问题 | 表现 |
|---|------|------|
| P1 | **LLM 缺稳定「正例」** | 无 few-shot 时，跨品类输出风格漂移：叶子 Procedure/Command 漏抽，或把章节标题、模块文件名乱挂成主干边 |
| P2 | **规则与 LLM 职责不清** | 纯规则易漏语义叶；纯 LLM 不稳定。需要「LLM 主抽叶子 + 规则兜底」而不是双轨各抽一套再硬合并 |
| P3 | **抽取仍依赖外部模型，本地接不住** | 开发习惯用 `config-mix`（Gemini 等）；目标运行时是本地 Ollama（`config-local` / `qwen3.5:9b` 等）。同一套 exemplar + prompt 下，本地 JSON 失败率极高 → **策略 B 在目标环境名存实亡**，无法宣布本地化完成 |

另外，试抽 StampServer 时观察到：即便 LLM 失败，规则兜底仍会产生 **多 Service → 同一「Apache服务配置」** 的 `has_procedure` 扇入——违反「最小主干」，审图时像「全部平铺挂接」。本地未达标时，规则就是唯一路径，此病必须先治。

根因不是「再加一个品类开关」或「做个切换器」，而是缺少：

1. **可版本化的单一示例学习契约**（仅 universal pattern，占位符覆盖 Tool/Service 等）——专门把**本地**模型教会、指导**所有** `doc_category`
2. **明确的主路径 / 兜底边界**（策略 B），且兜底也满足最小主干
3. **本地抽取达标定义与退出外部依赖的阶段门**（不是长期双轨对照；也不是按品类叠专包）


### 1.2 第一性原理（设计公理）

| # | 公理 | 含义 |
|---|------|------|
| A1 | **最小关系主干** | 图只保留产品/服务导航必需的实体与边；配置片段、长命令参数、叙述性说明仍以 chunk 文本召回为主 |
| A2 | **一套 pattern 指导所有类** | 全体 `doc_category` 共用同一套 universal exemplar；用 `{Tool}`/`{Service}` 等占位，不按品类再叠专包；教模式不教穷举 |
| A3 | **层级优于平铺** | `服务部署 → 具体 Service`、文档 `Section` 树清晰；禁止 N 个叶子共用同一父章节名当 Procedure 目标形成扇入 |
| A4 | **证据可核对** | 实体/关系须能对照 chunk 原文或 `section_path`；无证据不进 pending 主干边 |
| A5 | **本地为唯一交付运行时** | 图谱抽取的默认与验收环境是本地 LLM；外部模型仅迁移期临时使用，达标后停止依赖 |
| A6 | **失败可降级且不污染主干** | 本地 LLM 单 chunk 失败不阻断整批；规则兜底必须仍满足 A1–A3，禁止「失败就胡挂」 |
| A7 | **事实通道不变** | 回答事实仍来自检索 context；图用于导航/消歧/扩召回（受既有 GraphRAG 开关约束） |

违反 A1/A3/A5 的方案（例如用外部模型结果冒充本地验收通过，或为提高召回把所有正文标题挂成 `has_procedure`）不在本 PRD 接受范围内。


### 1.3 目标

1. **示例学习功能**：维护**唯一** Exemplar Pack（`pattern_universal_v1` 或其后继版本）；全品类只注入这一套；预算可控——**以本地模型能跟样为准**。
2. **策略 B 管线**：默认 LLM 主路径抽导航叶；ChapterLeaf / ServerLeaf 仅对缺失叶子做去重兜底；CLI 可强制 `--no-llm` / `--include-llm`。
3. **全面本地化**：抽取 LLM 最终只跑本地（Ollama + 项目约定模型）；通过配置与流程**逐步停用** mix/外部抽取路径。
4. **本地达标验收**：固定 chunk 集在 `config-local` 下达到 JSON/可用候选/主干审阅门槛；外部摸底结果不计入通过。
5. **Server 主干收口**：消除规则侧章节名扇入与 FA 倒挂（允许部分叶子无 Procedure）；在同一套 universal 下本地扩面（不新增专包）。
6. **传输层可观测**：本地抽取失败可区分输出截断与真语法错；S6 只认 raw 解析成功率。

### 1.4 非目标

| 非目标 | 说明 |
|--------|------|
| 长期 local / mix 双轨并行验收 | **明确不做**；mix 不是产品形态 |
| 全库自动 apply / 免审写入 | 仍走候选 review + apply 确认三件套 |
| 生产默认打开 `graph_retrieval` | 第 4 轮结论仍有效；本 PRD 不批准生产开图 |
| 把关系 / evidence 当回答正文事实 | 与既有回答契约一致 |
| 按品类维护多套 exemplar 专包（Tools/Server/…） | **明确不做**；差异用 universal 占位符与规则兜底表达，不叠专包 |
| 动态相似 chunk 检索 exemplar（RAG-for-exemplar） | 可列为后续；本轮用静态单一 JSON 包 |
| 管理后台可视化编辑 exemplar | 本轮以文件维护；UI 另案 |
| 为每个数字单独加配置爆炸 | 预算常量可代码内固定；环境差异走 ini |
| 用更强外部模型掩盖规则或本地缺陷 | 规则在 `--no-llm` 下也须满足最小主干；本地未达标不得结项 |


### 1.5 成功标准（总览）

| 编号 | 标准 | 度量方式 |
|------|------|----------|
| S1 | 任意 `doc_category` 的 LLM prompt 均注入 **同一** universal pattern（非 `(none)`；无品类叠加差分） | 单测 + 本地实抽抽查 |
| S2 | 多品类（至少 Tools + Server）在仅 universal 下，叶子命名/挂接可人工勾选为「符合最小主干」（**本地开 LLM**） | 跨品类定向审阅表；**依赖 S6「可用」之后**，此前不强制勾选 |
| S3 | LLM 已产出叶子时，规则兜底不重复造同键实体/边 | 单测 `leaf_fallback` |
| S4 | `--no-llm` 与默认开 LLM 行为可预期；配置缺省 `enabled=true` | CLI + config 单测 |
| S5 | 同一批 StampServer「服务部署」chunk：`--no-llm` 下 **无**「多 Service → 同一 Apache服务配置」扇入；**允许**「授权服务」类叶子无 Procedure（仅 Section/Service reuse） | 批次关系计数 + 原文对照 |
| S5b | Phase 1 后无新增 `Service::祖先段` FunctionArea（如 `授权服务::服务部署`） | 实体名扫描；**不要求**本阶段自动补齐 `Service → 服务部署` 的正确 belongs_to |
| S6 | **本地开 LLM** 定向批：以 **raw `json.loads` 成功率**（不含 D4 repaired）对照档位；失败不阻断；降级仍满足 S5 | `config-local` + diagnostic（含 `done_reason` / raw 长度） |
| S7 | **本地化退出门**：默认抽取配置指向本地；操作指南不要求 mix；外部仅遗留说明 | 配置审查 + 操作说明 |
| S8 | 不默认 apply；正式写入有人工审与 confirm | 流程检查 |

**S6 阶段门槛（本地，操作定义）**

| 档位 | 条件 | 是否可进入下一阶段 |
|------|------|-------------------|
| 未达标 | 可用 LLM 候选 ≈ 0，或 **raw** JSON 成功率 &lt; 30% | 否；须继续 Phase 2 |
| 可用（**V1.7 已达**） | 同题集 **raw** JSON 成功率 ≥ 70%，且主干人工抽检无系统性扇入/倒挂 FA | 可做跨品类本地扩面；此后才严肃验收 S2 |
| 达标可结项（**V1.7 已达本 PRD 范围**） | 固定题集达「可用」，且 S5/S5b/S7 勾选 | 可宣布抽取路径本地化完成 |

**补充实测（2026-08-11，侧路复现）**：授权服务 chunk + `qwen3.5:9b`，prompt ≈13k 字符，返回 ≈277 字符，断在 `"confidence": 1.0,` 之后 → **输出截断**为主证；短 prompt 冒烟 4b/9b 均可 PARSE_OK。`qwen3.5:4b` 同题 4/4 仍 JSON 失败，降参不是出路。

**根因收口（2026-08-11，受控对照实验，详见 §2.4）**：等价线上参数下 `done_reason=length`、`prompt_eval_count=4052`、`eval_count=44`（**4052+44=4096**，正中 Ollama 默认 `num_ctx`）；仅显式 `num_ctx=16384` 一变量即翻转为 `done_reason=stop`、输出 1005 token 完整合法 JSON。**V1.7**：D2 落码后同批 Server/Tools 定向试抽 raw JSON 达 S6「可用」档；机理已定——**不是模型不会 JSON，是窗口没给输出留位置**。

### 2.3 现行数据流（抽取）

```text
chunk（含 doc_category / section_path）
  → 结构规则（Section / FunctionArea / …）
  → LLM（prompt 含 {extraction_exemplars}；失败 → diagnostic）
  → leaf_fallback（ChapterLeaf / ServerLeaf，对已有叶子去重）

  →（人工）review → apply（须 confirm；本 PRD 默认不自动走）
```

目标稳态：上述 LLM 步**仅**调用本地 endpoint。迁移期内若临时指向外部，纪必须标注「非验收、不结项」。

### 2.4 本地 JSON 失败根因实证（2026-08-11 受控实验）

> 一次性复现脚本已按仓库卫生要求删除；方法与参数完整记录于此，可按下述步骤重做。

**方法（三步）**：

1. **失败样本形态分析**：从 `extraction_candidates` 读取本地两批（`6fa625fc-…` 11 条、`11517ef4-…` 4 条）`llm_extraction_failed` diagnostic。全部报错为 Unterminated string / Expecting ',' / Expecting property name / Expecting value 四类——均为 **JSON 文档在中途戛然而止** 的 EOF 形态；报错位置集中在 **char 117–557**（不同 chunk 正文长度不同 → 剩余输出预算不同）。
2. **Ollama 侧探测**（`/api/version`、`/api/show`）：Ollama `0.32.6`；`qwen3.5:9b` Modelfile **未设** `num_ctx`/`num_predict`（默认生效），模型本身 `context_length=262144`（非模型上限问题）；Modelfile 自带采样默认 `temperature=1`、`top_k=20`、`top_p=0.95`、**`presence_penalty=1.5`**（线上调用仅覆盖 temperature，其余泄漏生效）。
3. **受控对照**（真实 `LLMGraphExtractor.build_prompt`，`config-local` / prompt_version=v3，「授权服务」部署样文 470 chars；完整 prompt **13507 chars**：v3 模板 7687 + backbone_context 2996 + universal exemplars 2396 + 正文与拼装）：

| 组 | options（其余与线上 `_chat_ollama` 全等：`format="json"`、`think=false`） | done_reason | prompt_eval / eval | 结果 |
|----|----------------------------------------------------------------------|-------------|--------------------|------|
| A（线上等价） | `temperature=0` | **length** | 4052 / **44** | 123 chars 半截 JSON，Unterminated string |
| B | A + `num_predict=2048` | **length** | 4052 / **44** | 与 A 逐字节相同 → **单加 num_predict 无效** |
| C | B + `presence_penalty=0` | **length** | 4052 / **44** | 与 A 相同 → presence_penalty 非主因 |
| D | B + **`num_ctx=16384`** | **stop** | 4052 / 1005 | **3134 chars 完整合法 JSON**（7 实体 + 6 关系），耗时 ≈37s |

**结论**：

1. **根因 = Ollama 默认 `num_ctx=4096` 的窗口挤压**：抽取 prompt 固定开销即 ≈4k token（样例 4052），输出只剩 44 token 便触发 `done_reason=length`。4052+44=4096 为直接算术证据。
2. `format:"json"` 语法约束**一直在生效**（截断前的前缀均为合法 JSON 前缀）——「本地模型不会写 JSON」不成立。
3. 样例 prompt 恰好装进 4096（未被前向截断）；**正文更长的真实 chunk 会连 prompt 一起被 Ollama 前向截断**（丢失模板头/backbone/示例），属同一根因的加重形态（算术推论，未单独实验）。
4. 代码缺口：`llm_http._chat_ollama` 仅透传 `temperature`/`num_predict`，**没有 `num_ctx` 通道**——修复必须动 `llm_http`（见 Phase 2 / D2）。

**副发现（不改变 S6 判定，但须记录）**：

- **主问答路径同病**：主 QA / 流式调用同样不传 `num_ctx`（`[context_budget] context_window=32768` 攒的长 context 到 Ollama 侧仍被默认 4096 静默截断）。影响面超出本 PRD，**另立任务**处理，本 PRD 只修抽取角色。
- **修复截断后暴露的第二层质量缺陷**（D 组输出实例）：tar 包/unit 文件路径被判为 ConfigItem、`ConfigItem -[runs_command]-> Command` 非法端点、`configured_by` 方向颠倒、未抽出「安装/配置/验证」Procedure 叶子。其中非法端点/方向类会被 `early_check_relation_endpoints` 与类型 guard 拦截为 diagnostic，但**可用候选率会打折**——这是 D3/FR-E3 的调优对象，也再次说明 S6 达标不能只看 JSON 合法率，还看可用候选。
- **Modelfile 采样参数泄漏**：`presence_penalty=1.5` 等默认随调用生效（仅 temperature 被覆盖）。C 组证明其非截断主因；作为**廉价保险**，D2 落码时可一并显式归零（诚实标注：收益未实证）。


## 三、功能需求

### 3.1 示例学习（Exemplar Pack）

#### FR-E1 包格式与存放

- 路径：`data/extraction_exemplars/*.json`（纳入版本管理；非 runtime 乱写）。
- 根对象字段建议：`id`、`version`、`description`、`exemplars[]`。
- 单条 exemplar：`section_path`（可选）、`doc_category`（可选）、`input_excerpt` 或场景说明、`expected`（实体/关系示意）、`notes`（为何这样挂 / 勿挂什么）。
- Universal 包使用跨品类占位符，避免写死单一产品名导致 Server/Tools 串味。

#### FR-E2 注入策略（单一包）

| 优先级 | 内容 | 说明 |
|--------|------|------|
| 1 | 始终且仅注入 `pattern_universal_v1`（或其版本后继） | 全品类同一套 |
| — | **禁止**按 `doc_category` 再追加专包 | 新品类不新建 `*_v1.json` 映射 |

预算：以单一包总长可控为准（当前实现量级约 3200 chars 内；专包预算槽位取消后全部留给 universal）。

代码收敛要求：清空或停用 `exemplar_pack._CATEGORY_PACKS`；`format_exemplars_for_prompt` 不再读取品类文件。有价值的 StampTools 正例应**改写为占位符后并入** universal，而不是继续叠文件。

#### FR-E3 示例内容原则

- **要教**：叶子命名、`belongs_to` 层级、`has_procedure` / `runs_command` 的合法端点、与文本召回的分工（细节不进图）；用 `{Tool}`/`{Service}` 等覆盖 Tools 与 Server。
- **不要教**：把整段配置、全部 `.so`、全部正文小标题抽成实体；不要示范「多服务共用一个父章节 Procedure」。
- **不要**为 StampServer / StampTools 各维护专包；品类差异靠占位符 + 规则兜底，不靠第二份 few-shot。
- 正例起草若曾借助外部模型，须经人工改写为「最小主干」风格后写入 **universal**；**不得**把外部原始 JSON 整包当 exemplar。

#### FR-E4 与 prompt 版本关系

- Exemplar 注入与 `prompt_version` 正交：换 prompt 不得悄悄关掉 universal。
- **环境对齐**：当前 `config-local.ini` 为 `prompt_version = v3`；对照/减负纪要必须写明实际加载的版本，禁止文档默认写成 v4 却用 v3 验收。若升 v4，须在 local 同题复测后再改默认。
- 变更 exemplar 或 prompt 任一侧，须用同一固定 chunk 集在 **`config-local`** 做前后对照。
- **P1 与截断的关系**：输出截断未消除前，无法验证「universal 是否教会本地」；S2 必须在 S6「可用」之后勾选（见 §1.5）。

### 3.2 规则兜底与最小主干

#### FR-R1 叶子兜底

- LLM 已产出同名 Procedure/Format/Command（及对应关系）时，规则跳过同键。
- LLM 全失败时，规则可全量兜底，但 **仍受 FR-R2 约束**。

#### FR-R2 Server 叶子收紧（待实现；V1.6 按第一性重写）

**根因（已代码核查）**：`server_leaf_extractor.py` 除路径叶子外，还**逐行扫描正文**，凡命中 `_is_procedure_title()`（`…安装|配置|部署$`）就造 Procedure。手册正文常复述祖先章节名（如「Apache服务配置」），于是每个叶子 Service chunk 都产出同一 Procedure + `has_procedure` 扇入。

**第一性（先于具体补丁）**：

| # | 命题 | 推论 |
|---|------|------|
| T1 | 规则只做**导航骨架**，细节留给文本召回 / LLM（A1） | 规则不应从正文小标题「尽量多挖」Procedure |
| T2 | `section_path` 已编码「我在哪 / 本块关于什么」 | 对本 chunk，**唯一结构真源是路径叶子**；祖先段是语境，不是本块工序名 |
| T3 | 正文里的 shell 行是 Command 证据，标题复述是大纲回声 | **Command 仍从正文抽**；**Procedure 标题不得从正文扫行产生** |

因此：扇入的根因不是「少一张黑名单」，而是**错误地把正文标题扫描当成 Procedure 源**。正确修复是**取消该源**，不是在错误源上再叠过滤名单。

**修改方案（`server_leaf_extractor.py`）——结构规则，非产品名硬编码**：

1. **Procedure 唯一来源 = 路径叶子**（外加既有 `_PROCEDURE_WHITELIST` 仅当标题 **等于当前叶子** 时生效，避免白名单变成第二套正文扫描）。
   - 叶子通过 `_is_procedure_title(leaf)` 或（叶子 ∈ 白名单）→ 产出该 Procedure，并可作 `runs_command` 的 primary。
   - 叶子不合法（如「授权服务」）→ **0 个规则 Procedure**（允许；导航靠 Section + Service reuse）。
2. **删除「逐行扫描正文造 Procedure」**（含因此需要的「祖先禁入」「泛名黑名单」）。不再维护 `_PROCEDURE_BLOCKLIST` 作为主方案——名单是补丁，不是根因修复。
3. **Command 提取逻辑保留**（正文 `systemctl`/`yum`/…）；有 primary Procedure 时挂 `runs_command`，无则只出 Command + link（或仅 link，与现行为最小偏差处保持「有 cmd 仍可挂实体」）。
4. `resolve_path_owner` 不动；有 owner 且有 Procedure 时才挂 `has_procedure`。

**刻意不做**：

- 不为「正文里另起的真实子步骤标题」用规则补 Procedure（交给 LLM / 文本召回，A1）。
- 不写 `if title == "Apache服务配置"` 之类产品特例。
- 不用编辑距离模糊匹配祖先（误杀面大）。

**预期行为**：

| 路径叶子 | 规则预期 |
|----------|----------|
| `… > HTTPD服务配置` | Procedure = 叶子；不因正文里再出现「Apache服务配置」而扇入 |
| `… > 授权服务` | 0 Procedure；无 `has_procedure` 扇入 |
| 任意叶子 + 正文复述祖先名 | 祖先名**不会**成为 Procedure（因为根本不扫正文标题） |

**验证**：单测覆盖上表；`--no-llm` 同批过 S5。ChapterLeaf 仅冒烟（其源是固定标题表，不是同一 bug）；若无祖先扇入则不动。

#### FR-R3 不做的规则扩面

- 不在本轮用规则批量制造 ConfigItem 洪水。
- 不把 Service 直接 `belongs_to` Product 以绕过「服务部署」等中间层（已有 backbone 冲突诊断应保留）。
- **本阶段不修改**「每个 owner `belongs_to` Product」既有边（与 FR-R4 解耦）。
- **不引入** Procedure 泛名黑名单主路径（V1.6 起）。

#### FR-R4 FunctionArea 路径 containment 同构（待实现；与 FR-R2 同阶段）

**根因（已代码核查）**：对路径中**每一个**非 owner 段生成 `{primary_owner}::{段}`，而 `primary_owner` 取路径上**最后一个** Tool/Service。当 Service 在路径末端时，**更靠前的祖先段**被 scope 到该 Service 下 → `授权服务::服务部署` 倒挂（违反 A3）。

**第一性**：

| # | 命题 | 推论 |
|---|------|------|
| T4 | 图上「A 下的功能区 B」必须对应文档里 B 在 A **之下** | FA 的路径段索引必须 **>** owner 段索引（路径顺序 = containment） |
| T5 | 伞层「我在哪」已由 Document/Section 树表达（A1） | owner **之前**的段**不建** FunctionArea，避免与 Section 双轨膨胀 |
| T6 | 约束应是位置谓词，不是名字名单 | 禁止写死「不得叫服务部署」；任意祖先段一律不进 owner scope |

**本阶段范围（只消错，不补全）**：消除倒挂 FA（S5b）；**不**自动补 `Service → 服务部署` 上挂（交给 Section / backbone / 后续 LLM）。

**修改方案（`SectionPathExtractor`）**：

1. 记录 `primary_owner` 的段索引 `owner_idx`。
2. 仅当 `idx > owner_idx` 且该段不是另一个 Tool/Service owner 时，才建 `{primary_owner}::{part}` 及下挂 `belongs_to`。
3. `idx < owner_idx`：跳过 FA（Section 已覆盖）。
4. `has_table` / `defined_in` 等不动。

**验证**：`Apache服务配置 > 服务部署 > 授权服务` 无 `授权服务::服务部署`；`某工具 > 数据规范 > …`（owner 在前）时 owner 之后的 FA 仍可产出；过 S5b。

### 3.3 模型全面本地化（取代「可切换双轨」）

#### FR-M1 目标运行时契约

| 项 | 要求 |
|----|------|
| 默认抽取环境 | `RAG_CONFIG=config-local.ini`（或等价：provider=ollama + 约定本地 model） |
| 配置入口 | `[graph_extraction.llm]` 的 provider / model / base_url / `num_ctx` / `num_predict`（D2 新增）；禁止业务代码写死外部模型名 |

#### FR-M2 本地可用性（硬要求）

- Ollama 不可达或模型未拉取：抽取批次仍完成；LLM 段记 diagnostic；规则兜底继续且须满足 S5。
- 不得因单 chunk JSON 失败中断整批。
- 本地失败率高时，纪要必须写明「结果≈规则路径 / 本地未达标」，**禁止**改用 mix 结果宣称「改造已验证」。

#### FR-M3 本地验收协议（唯一主路径）

固定 chunk 列表（建议 ≤15，含「服务部署」多样叶子，**须含**「授权服务」类非 `…配置` 叶子与「HTTPD服务配置」类合法叶子）：

1. `config-local` + `--no-llm` → S5 / S5b。
2. 确认专包已停叠（Phase 1.5）后：`config-local` 开 LLM → 记 raw JSON 成功率、`done_reason`、可用候选 → S6。
3. （可选摸底）mix → 仅附录，不更新 S6/S7。
4. **禁止**自动 apply。
5. S2 仅在步骤 2 达「可用」后做跨品类审阅。
#### FR-M4 退出外部依赖（结项条件）

同时满足：

1. S5、S6「可用」以上、S8 勾选；
2. 日常抽图操作说明只描述本地启动与模型拉取；
3. 团队约定：新试抽 / 扩面默认禁止依赖外部 API Key。

未满足前，状态保持「本地化进行中」，不得写「已支持本地化完成」。

### Phase 1.5 — 专包停叠（Phase 2 前置，可与 Phase 1 同 PR 或紧随）

**目的**：本地 JSON 试验前去掉品类叠加，缩短 prompt，避免「专包残留」干扰截断诊断。

### Phase 2 — 本地 LLM 结构化输出达标（本地化主攻）

**根因分层（2026-08-11 受控实验已收口，证据见 §2.4）**：

| 层级 | 状态 | 说明 |
|------|------|------|
| A. 输出截断 | **已实证（主因的表现层）** | `done_reason=length`；截断前前缀均为合法 JSON → `format:"json"` 一直生效，「模型不会 JSON」不成立 |
| B. 未传 `num_predict` | **证伪为单独主因** | B 组显式 `num_predict=2048` 与线上等价组逐字节相同——窗口不扩，生成上限再大也无位置可用；但落码时仍应显式设置，作为输出上限的明确契约 |
| C. `num_ctx` 过小 | **已实证为决定性变量** | 默认 4096 被 ≈4k token 的 prompt 占满（4052+44=4096）；单改 `num_ctx=16384` 即完整合法 JSON。长正文 chunk 还会连 prompt 前向截断（加重形态） |

**第一性顺序（更新）：D1 已收口（§2.4）→ D2 落码 `num_ctx` + `num_predict`（主项）→ 同批复测 → 仍不达标才 D3 减负 → D4 仅结构边界可修 → D5 换更大本地模型。禁止先写万能 JSON 修复器掩盖截断。Phase 2 开始前须完成 Phase 1.5 停叠。**

在 Phase 1（及 1.5）通过后，按序执行：

| # | 措施 | 内容 | 判定 |
|---|------|------|------|
| D1 | **观测收口 + 固化**（分析已完成） | 根因分析见 §2.4，不再重复实验；本步只做**落码固化**：`llm_extractor` 失败 diagnostic 增记 `done_reason` / `eval_count` / `prompt_eval_count` / raw 首尾各 200 chars；`pipeline` counts 增 `llm_json_ok` / `llm_json_failed`（raw 口径，供 S6 直接读数） | 复测批 diagnostic 可直接分辨截断 vs 语法错 |
| D2 | **落码修复（必做主项）** | ① `llm_http.chat()` / `_chat_ollama` 增加 `num_ctx` 透传（并入 Ollama `options`；OpenAI/Google 路径忽略该参数）；② `GraphLLMExtractorConfig` 与 `[graph_extraction.llm]` 新增 `num_ctx`（建议默认 **16384**，显存紧张可降 8192——固定开销 ≈4k token，8192 仍可给输出留 ≥3k）与 `num_predict`（建议 2048）；③ `_call_llm_with_retries` 传入两参；④（可选保险，收益未实证）同时显式覆盖 `presence_penalty=0`，消除 Modelfile 泄漏。显存对照 `[gpu_agent.model_vram]`；实测 9b @16k 单发 ≈37s 可用 | 同批 raw JSON 成功率（预期直接冲击 S6「可用」档） |
| D3 | **prompt 减负（辅助，量化目标）** | 固定开销实测 ≈13.1k chars：v3 模板 7687 + backbone 2996 + universal 2396。若 D2 后成功率或速度仍不达标，按刀口收益排序：backbone_context 压缩 > v3 模板去与 universal 重复的内嵌 few-shot > universal 预算下调。保持 prompt_version=v3 口径，升 v4 须另测（FR-E4）；每刀 local 同题对照 | 同批复测 |
| D4 | **轻量修复兜底** | 仅当截断点落在**结构边界**（完整 value 之后）时做尾部括号/引号闭合；**中段 `Unterminated string` 判定为不可修，必须重抽/加长，禁止瞎补**。修复成功计 `llm_json_repaired`，**不计入** S6 raw 成功率 | 垫底 |
| D5 | **换/加大本地模型** | D2–D3 后 raw 成功率仍 &lt;70% 才走；仍限 Ollama + GpuMonitor；**不**以降为 4b 作为优化手段（已试更差）。注意 §2.4 副发现：JSON 合法后还有**第二层质量缺陷**（类型误判/方向颠倒/漏 Procedure 叶），若 raw 成功率已高而**可用候选**仍低，问题在 D3/FR-E3（示例与 prompt），换模型收益有限 | S6 |

约束：**禁止**用 mix 验收代替本阶段；每步用同一固定 chunk 集 `config-local` 复测。
