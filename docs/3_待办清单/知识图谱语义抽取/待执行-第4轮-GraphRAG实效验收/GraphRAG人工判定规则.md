# GraphRAG 人工判定规则

- **记录日期**：2026-07-16
- **用途**：第 4 轮 A/B 验收时，统一人工判断口径

## 1. 命中判定

| 判定 | 业务含义 | 规则 |
|------|----------|------|
| 完全命中 | 用户可以直接用答案完成任务 | 命中标准证据，答案覆盖主要要点，来源与问题实体一致 |
| 部分命中 | 有帮助但不完整 | 命中部分证据或只覆盖部分要点，需要继续追问 |
| 未命中 | 不能支持回答 | 未命中标准 chunk，或答案与问题实体/配置/流程不对应 |
| 错误命中 | 图谱扩展带偏 | graph-on 引入无关或相反证据，导致答案错误 |

## 2. 图谱增强有效的判定

graph-on 相对 baseline 记为“有效提升”，至少满足一项：

1. 标准证据从 top4+ 提前到 top3。
2. baseline 未命中，graph-on 命中。
3. baseline 只命中章节泛化内容，graph-on 命中具体业务实体、配置项、步骤或依赖。
4. graph-on 让答案覆盖更多 `answer_key_points`，且没有引入错误证据。

## 3. 不算有效提升的情况

1. 两组都命中同一证据，排序和答案质量没有实质差异。
2. graph-on 只增加相邻 chunk，但没有进入最终回答证据。
3. graph-on 命中了实体名称，但证据不支持答案。
4. graph-on 引入更多内容导致答案更长，但业务要点没有增加。

## 4. 错误 chunk 判定

以下情况记为“图谱扩展引入错误 chunk”：

1. 产品、模块或流程归属错误。
2. 配置项名称相似但属于不同场景。
3. 步骤顺序或依赖关系被错误合并。
4. 旧版本/历史内容覆盖当前有效内容。
5. graph-on 的错误证据进入最终答案，而 baseline 没有该错误。

## 5. 抽检要求

| 项 | 要求 |
|------|------|
| 抽检题数 | 至少 10 题 |
| 覆盖意图 | 至少 3 类意图 |
| 必查项 | graph-on 优于 baseline 的题、graph fallback 的题、疑似错误 chunk 的题 |
| 记录 | 写入 `GraphRAG_A_B验收报告模板.md` 的人工抽检表 |
