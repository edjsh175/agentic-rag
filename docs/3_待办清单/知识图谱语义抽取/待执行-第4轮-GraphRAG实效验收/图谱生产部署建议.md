# 图谱生产部署建议

- **记录日期**：2026-07-16
- **适用范围**：第 3 轮重建完成、第 4 轮 GraphRAG 验收前后的生产口径

## 1. 推荐配置口径

```ini
[graph_retrieval]
enabled = true

[graph_extraction.llm]
enabled = false
```

业务含义：

1. `graph_retrieval.enabled = true` 表示问答时允许使用已审核、已入库的可信图谱增强检索。
2. `graph_extraction.llm.enabled = false` 表示生产服务常驻运行时不自动做全库 LLM 抽取。
3. 全库 LLM 构建应在维护窗口通过 CLI 执行，并保留备份、日志、审批和验收报告。

## 2. 维护窗口 SOP

| 阶段 | 要求 |
|------|------|
| 执行前 | 停止后端、评估进程和其他占用 `chroma_db` / `rag_relational.db` 的任务 |
| 备份 | 生成 timestamped 备份；不得覆盖 `pre_round3` 或 `half_execute_aborted` |
| dry-run | chunk 变更后必须重新 dry-run |
| execute | 使用 `rebuild-safe --execute --include-llm`，禁止人工绕过保护集 |
| 审批 | 含 LLM 的候选禁止 `approve-all` |
| 验收 | audit、quality、Task 8.1 gate、主干 40/40、§10 指标均通过后再进入 GraphRAG A/B |

## 3. 风险说明

| 风险 | 说明 | 控制方式 |
|------|------|----------|
| LLM 抽取成本高 | 全库 chunk 多，执行时间长 | 只在维护窗口执行 |
| 错误事实污染图谱 | 低置信或冲突候选可能带偏检索 | 分拆审批、主干冲突拒收、低置信 deferred |
| 运行时资源争用 | 后端服务、评估和重建同时访问正式库会增加锁风险 | 执行前停占用进程 |
| 回滚误操作 | 覆盖错误备份会丢失可恢复点 | 保护 `pre_round3` 和 `half_execute_aborted` |

## 4. 上线判定

1. 第 3 轮通过：图谱可以作为可信候选进入 GraphRAG 实效验收。
2. 第 4 轮通过：可以把“GraphRAG 对至少 2 类意图有效提升”写入交付结论。
3. 第 4 轮未通过：仍可保留图谱管理能力，但不宣称图谱增强问答已达标。
