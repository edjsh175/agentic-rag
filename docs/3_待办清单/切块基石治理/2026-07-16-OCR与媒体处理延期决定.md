# OCR 与媒体处理延期决定

## 决定状态

- 决定日期：2026-07-16
- 状态：已确认，第二阶段实施必须遵守
- 适用范围：文档解析、目录扫描、上传入库和受控重建

## 本阶段决定

1. 本阶段不实现 OCR，不调用 OCR 服务或视觉模型。
2. 无可提取文本的 PDF 页面不得生成可检索 Chunk，必须以 `PDF_PAGE_REQUIRES_OCR` 记录页码并进入待处理队列。
3. 禁止将“等待 OCR”“OCR 待处理”等占位文本写入知识库或用于检索。
4. 独立图片、视频和文档内嵌媒体全部延期。本阶段只记录文件或所在页、幻灯片及 reason code，不生成视觉描述。
5. PDF 表格结构化恢复延期。本阶段只保留文本解析器能够可靠提取的普通文本，不声明表格结构关系。
6. 第二阶段可以继续处理同一 PDF 中有可靠文本的其他页面；该文件同时属于“已处理”和“部分页面待 OCR”。

## 运行时处置

| 内容 | 本阶段行为 | reason code |
|---|---|---|
| 无文本 PDF 页面 | 不生成 Chunk，记录页码并排队 | `PDF_PAGE_REQUIRES_OCR` |
| 独立图片或视频 | 不解析、不调用视觉模型，整文件排队 | `MEDIA_PROCESSING_DEFERRED` |
| 文档内嵌媒体 | 文本继续处理，媒体位置单独排队 | `EMBEDDED_MEDIA_PROCESSING_DEFERRED` |
| PDF 表格 | 仅保留可靠普通文本，不恢复结构 | 后续任务，不生成伪结构记录 |

所有排队和排除记录写入版本化的 `ingestion_decisions.json`。正式库不得出现 OCR 占位 Chunk。

## 后续实现准入条件

OCR 与媒体能力重新启动前，必须同时补齐：

- OCR 置信度与低置信度隔离规则；
- 页面版面、阅读顺序和原始区域血缘；
- 媒体哈希、Section 锚点及可重复处理标识；
- 图片、视频和 PDF 表格的独立黄金样本与隔离评测；
- 正式写库前的 0G、FR-10、OCR 范围和 Go 清单审批。

在这些条件满足前，OCR 和媒体证据不得进入正式 Chroma。
