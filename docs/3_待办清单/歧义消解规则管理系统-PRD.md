## 一、项目概述

### 1.1 项目背景

歧义消解规则（Disambiguation Rules）定义了在出现特定歧义触发词（如“管线”）时，向用户提问的话术模板以及选项对应的分类/实体过滤条件。
当前规则硬编码在 `disambiguation_rules.json` 静态文件与代码逻辑中，存在以下缺点：
* **无法在线动态扩充**：业务新增歧义同义词时必须修改源码或配置文件并重启后端。
* **缺少数据分析**：无法统计哪些歧义规则最常被触发、哪些规则的提问选项选得最多。

### 1.2 项目目标

构建**歧义消解规则管理系统**：
1. **持久化数据表**：创建 SQLite `disambiguation_rules` 数据表，并将静态 JSON 迁移至数据库。
2. **规则动态加载与优先级引擎**：后端的 `QueryClarificationService` 优先从数据库中读取并按优先级匹配规则。
3. **可视化规则管理界面**：管理员可在前端进行增删改查、开关控制与触发计数（`hit_count`）查看。

### 1.3 系统角色定义

| 角色 | 职责 |
|------|------|
| **系统管理员** | 维护歧义消解规则（新建规则、设置提问模板、定义选项过滤） |
| **智能体服务** | 提问时匹配数据库中的规则并递增 `hit_count` |

## 三、数据层详细设计

### 3.1 关系数据库表结构：`disambiguation_rules`

| 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `id` | VARCHAR(36) | 是 | UUID | 主键 |
| `trigger_entity` | VARCHAR(200) | 是 | — | 触发歧义的实体或关键词（支持逗号分隔别名） |
| `ask_question` | VARCHAR(500) | 是 | — | 向用户提问的话术模板 |
| `context_options_json` | TEXT | 是 | `[]` | 选项 JSON 数组（包含 `label` 与 `filter`） |
| `priority` | INT | 是 | 100 | 优先级（数值越大优先匹配） |
| `is_active` | BOOLEAN | 是 | 1 | 是否启用（0 停用，1 启用） |
| `hit_count` | INT | 是 | 0 | 成功触发的总次数 |
| `created_by` | VARCHAR(50) | 是 | 'admin' | 创建人 |
| `created_at` | TIMESTAMP | 是 | Current | 创建时间 |
| `updated_at` | TIMESTAMP | 是 | Current | 修改时间 |

### 3.2 `context_options_json` 示例结构

```json
[
  {
    "id": "a",
    "label": "运维后台配置",
    "filter": {
      "doc_category": "部署运维",
      "entity_name": "飞行物体配置"
    }
  },
  {
    "id": "b",
    "label": "二次开发调用",
    "filter": {
      "doc_category": "二次开发",
      "entity_name": "FlightObjectAPI"
    }
  }
]
```


## 四、功能详细设计与后端 API

### 4.1 数据迁移与热加载

* **数据迁移**：系统启动时若检测到 `disambiguation_rules` 表为空，自动解析 `data/disambiguation_rules.json` 文件导入初始规则。
* **内存热缓存**：规则写入 DB 后更新 Redis/内存缓存，避免每次检索均发生物理 SQL 查询。

### 4.2 API 接口定义

#### 接口 1：获取规则列表
* **HTTP 请求**：`GET /api/disambiguation/rules`
* **Query Params**：`is_active=1`
* **Response**：
```json
{
  "total": 5,
  "rules": [
    {
      "id": "rule-001",
      "trigger_entity": "飞行物体,飞行器",
      "ask_question": "“飞行物体”在资料中包含多个方向，请选择：",
      "context_options": [...],
      "priority": 100,
      "is_active": true,
      "hit_count": 128
    }
  ]
}
```

#### 接口 2：新建/修改消解规则
* **HTTP 请求**：`POST /api/disambiguation/rules`
* **Request Body**：
```json
{
  "trigger_entity": "管线",
  "ask_question": "您是指管线发布工具还是管线场景绘制？",
  "context_options": [
    {"label": "管线发布", "filter": {"doc_category": "StampTools"}},
    {"label": "管线绘制", "filter": {"doc_category": "前端开发"}}
  ],
  "priority": 150,
  "is_active": true
}
```


## 五、前端交互与页面设计

### 5.1 规则管理页面 (DisambiguationRulesView)

1. **规则列表表格**：展示触发关键词、提问话术预览、选项个数、触发次数 `hit_count`、启用状态开关 (Switch)。
2. **规则编辑弹窗 (Modal)**：
   * 触发词多标签输入框 (Tag Input)。
   * 提问话术输入框。
   * 选项动态列表（可自由添加/删除选项，配置选项名称及其对应的分类/实体过滤条件）。


## 六、业务流程说明

```
【提问触发】 ──> 提取问题词汇 ──> 匹配 is_active=1 且优先级最高的规则 ──> 命中后 hit_count + 1 ──> 返回选项卡片
```


## 七、非功能性需求与界面规范

* **界面与内容禁用 Emoji 规则**：前端 UI 界面、对话交互卡片、提问话术模板、编辑弹窗及系统日志中，一律禁止使用 Emoji 表情符号，禁止在 `ask_question` 或选项 `label` 中插入 Emoji 字符。
* **高可用**：规则增删改查立即刷新内存缓存，不影响在跑的检索进程。


## 八、实施优先级与验收标准

* **验收标准**：
  1. 管理员能在页面添加新的歧义规则“测试实体”，提问包含“测试实体”时前端能按新填写的选项弹窗。
  2. 开关停用后，该歧义词不再触发反问。
  3. 提问话术与选项内容中无任何 Emoji 符号。
