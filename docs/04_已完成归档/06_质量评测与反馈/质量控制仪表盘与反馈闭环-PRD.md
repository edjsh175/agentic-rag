## 一、项目概述

### 1.1 项目背景

目前系统缺乏对知识库健康状况的宏观监控手段：
* **没有质量可视化面板**：无法直观了解知识库审核进度、重复知识块比例、孤立节点等指标。
* **用户反馈未形成闭环**：用户在对话界面点击“[无用]”按钮后，反馈数据仅作为日志存储，无法反向驱动不良 Chunk 的重审与修复。

### 1.2 项目目标

构建**质量控制仪表盘与反馈闭环系统**：
1. **统一仪表盘 UI**：提供独立的质量监控页面，聚合可视化展示 8 大核心质量指标。
2. **自动化反馈闭环 (Feedback Loop)**：当某个 Chunk 被累计打上 2 次及以上“[无用]”标签时，系统自动将其状态重置为 `review_status=pending`，并推送到审核工作台待复核列表。

### 1.3 系统角色定义

| 角色 | 职责 |
|------|------|
| **系统管理员** | 监控质量仪表盘、查看低质量块预警、触发重复块检测 |
| **业务审核员** | 收到差评预警后，在工作台中重新编辑或剔除低质量 Chunk |
| **普通用户** | 在对话框对回答点击 [有用] / [无用] |

## 四、功能详细设计与后端 API

### 4.1 8 大核心质量指标定义与计算逻辑

| 指标编号 | 指标名称 | 计算公式 / 来源 | 报警阈值 |
|---------|---------|----------------|----------|
| **M1** | 知识块总数 | Chroma 向量库 `collection.count()` | — |
| **M2** | 已审核占比 | `review_status='approved'` 的块数 / 总块数 × 100% | < 70% 警告 |
| **M3** | 待审核数量 | `review_status='pending'` 的块数 | > 50 个 提示 |
| **M4** | 孤立实体数 | 在 `entities` 表中但未在 `entity_chunk_links` 出现的实体数 | > 20 个 警告 |
| **M5** | 孤立块数 | 在向量库中但未关联任何实体的 Chunk 数 | > 100 个 警告 |
| **M6** | 块重复率 | 文本相似度 (SimHash) > 0.95 的 Chunk 对数 / 总块数 × 100% | > 5% 警告 |
| **M7** | 7日无结果率 | 7天内检索返回 Chunk 0 条的问题数 / 7天总提问数 × 100% | > 10% 报警 |
| **M8** | 7日用户满意率 | 7天内 `rating='up'` 的次数 / 7天总反馈次数 × 100% | < 80% 报警 |

### 4.2 反馈闭环自动化逻辑 (Feedback Loop)

1. 当用户提交 `rating='down'` 的反馈时，提取 `referenced_chunk_ids` 中的所有 Chunk。
2. 将这些 Chunk 在 `user_feedbacks` 中的差评计次 `down_count` 加 1。
3. 若某个 Chunk 的 `down_count >= 2`：
   * 自动调用 `ChunkAdminService` 将该 Chunk 的 `metadata.review_status` 置为 `pending`。
   * 自动在 metadata 中标记 `review_reason = '用户反馈差评累计2次，等待重新审核'`。
   * 在质量仪表盘“待复核预警列表”中置顶显示。

## 五、前端交互与页面设计

### 5.1 质量控制仪表盘页面 (QualityDashboardView)

1. **顶部指标卡片区**：4 个大字号卡片展示：已审核占比 (带环形图)、7日满意率 (带上升/下降趋势)、孤立实体数、待审核块数。
2. **中部图表区**：
   * 左侧：7日满意率与无结果率折线趋势图。
   * 右侧：各分类文档占比饼图。
3. **底部预警列表**：展示触发“差评重审预警”和“高重复率”的 Chunk 列表，提供 `一键跳转到审核` 按钮。


## 六、业务流程说明

```
【用户点击[无用]】 ──> 写入 user_feedbacks ──> 计算该 Chunk 差评数 ──> >=2 次 ──> 自动重置为 pending ──> 仪表盘预警
```


## 七、非功能性需求与界面规范

* **界面与内容禁用 Emoji 规则**：前端 UI 界面、仪表盘图表、预警信息、按钮文本及系统日志中，一律禁止使用 Emoji 表情符号，按钮统一使用 [有用] / [无用] 等纯文本标点或矢量 Icon，禁止使用手势/脸部 Emoji。
* **后台计算**：SimHash 块重复率检测使用异步 Cron 定时任务（每夜 2:00 运行），不占用实时问答 CPU。


## 八、实施优先级与验收标准

* **验收标准**：
  1. 仪表盘能够正确计算并展示 8 大质量指标。
  2. 对某回答连续点 2 次差评后，对应的知识块在后台状态自动变为 `pending`，且在仪表盘预警列表中显示。
  3. 仪表盘全页面无任何 Emoji 字符。
