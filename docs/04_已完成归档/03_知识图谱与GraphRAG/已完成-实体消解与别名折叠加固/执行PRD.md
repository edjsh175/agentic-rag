## 1. 问题本质

用户看到 `StampTools` 与 `StampGIS Tools` 被当成两个实体，不是「少写了一个 if」，而是：

**系统里没有单一的「实体身份」权威。**

当前身份规则散落在多处，且互不一致：

| 位置 | 实际做了什么 | 问题 |
|------|----------------|------|
| 首抽 LLM | 按 chunk 抽名，可参考主干，但不负责判重 | 任务是抽取，不是身份裁决 |
| catalog 归一 | 只折**实体候选名** | 关系端点、别名侧未走同一入口 |
| EntityResolution | 读正式库算 reuse/alias/duplicate | 结果只写标注，**不改变候选命运** |
| 审批安全门 | 部分拦 diagnostic | alias/reuse 仍可批准成新实体 |
| Apply | 按字面 `entities.name` 插入 | 不认 alias，可把别名再建成实体 |

根因一句话：**抽取、消解、审批、落库对「同一个现实世界对象」没有统一合约。**

补丁式演化（多处加判断、多轮特判）只会让身份规则继续分叉。应按从零设计回答：

> 实体身份应由哪个模块单独负责？所有路径是否都必须经过它？

## 2. 从零设计：身份子系统

### 2.1 职责划分

```text
抽取器（规则 / 首抽 LLM）
  └─ 只产出「表面名 + 类型 + 证据」
        ↓
EntityIdentityService（唯一身份入口）
  └─ 归一表面名 → 判定相对已有图/本批的身份
  └─ 确定性不足时，可调用 IdentityArbiter（LLM 候选对仲裁）
        ↓
Staging 候选（身份结论已是一等字段，决定可否建实体）
        ↓
Review（只审「新身份 / 新别名 / 吃不准」；不审已被折叠的重复实体）
        ↓
Apply（只按身份结论写库；查实体必经同一 resolve）
```

| 模块 | 负责 | 不负责 |
|------|------|--------|
| **抽取器** | 从文本提出称谓与证据 | 决定是否与已有实体同指 |
| **EntityIdentityService** | 名称归一、查权威别名、批内去重、输出身份结论 | 调 LLM 生成新事实边 |
| **IdentityArbiter（LLM）** | 对**未决候选对**裁决 same/different/unsure | 全图扫描、直接写正式库、覆盖 `different_from` |
| **Staging / Review / Apply** | 执行身份结论 | 再发明一套名字匹配 |

问答侧读图（intent / 扩召回）继续只消费正式库；建设侧写图前必须先过身份服务。

### 2.2 身份结论（业务合约）

对每一个「名称 + 类型」输入，身份服务只允许输出下列之一：

| 结论 | 含义 | Staging 后果 |
|------|------|----------------|
| `bind` | 已是某正式/本批实体（同名或已知别名） | **禁止**再开实体候选；证据可挂 link；别名可补录 |
| `alias_of` | 同指已有 canonical，表面名应进 aliases | 实体候选不成立；生成/保留 alias 候选 |
| `new` | 确认新身份 | 允许实体候选 |
| `conflict` | 同名异型、或违反 `different_from` 等硬约束 | 拒绝，记原因 |
| `uncertain` | 确定性无法裁决 | 可进 LLM 仲裁；仍不确定则 pending 人工，**禁止** approve-all |

`resolution_action` 若保留，必须是上述结论的存储名，且 **必须驱动候选状态**，不得只做展示字段。

### 2.3 名称权威源（单一来源，分层查阅）

查阅顺序固定，禁止各模块自选子集：

1. **硬约束**：产品主干 `different_from` → 不得判同指  
2. **官方别名**：主干 / `domain_catalog` 的 canonical↔alias  
3. **正式图**：`entities.name` + `aliases`（比较键统一：空白归一 + casefold）  
4. **本批已接受身份**：同一 extract batch 内已 `bind`/`new` 的名称  
5. **未决**：进入 IdentityArbiter 或人工  

业务别名只维护在 catalog/主干（及落库后的 `aliases`），不在抽取 prompt、审批 UI、Apply 里各写一份。

### 2.4 LLM 仲裁的定位

允许且需要 LLM，但只作为身份服务的**可选后端**，不是并行旁路。

| 原则 | 规则 |
|------|------|
| 何时用 | 仅当结论将为 `uncertain`，或批内/库内出现「同类型、轻量相似、权威源未收录」的候选对 |
| 何时不用 | 权威源已能 `bind`/`alias_of`；或命中 `different_from` |
| 输入 | 两名称、类型、短证据、相关主干别名/`different_from`；不喂全库 |
| 输出 | `same` / `different` / `unsure` + canonical（须为已有名或二者之一）+ confidence |
| 落地 | 映射回 §2.2 结论；低置信/`unsure` → `uncertain`；**不得**自动 apply |
| 开关 | 默认关；与首抽 `--include-llm` 解耦，避免「开判重＝全库重抽」 |

首抽 LLM 与仲裁 LLM 任务不同：前者抽称谓，后者判同指。不要把判重塞回抽取 prompt 指望「下次抽干净」。

## 3. 必须成立的不变量

实现完成且可验收，当且仅当下列不变量成立（比「修了哪几个文件」更重要）：

1. **单一入口**：凡写入实体、别名、关系端点、chunk link 所涉及的名称，Apply 与 Staging 均经 `EntityIdentityService.resolve`（或等价唯一函数）。  
2. **别名不可实体化**：若名已是某实体的 alias（或权威源别名），Apply **不得**再 INSERT 同名实体。  
3. **结论必生效**：`bind` / `alias_of` / `conflict` 的实体候选不可被批准为新实体。  
4. **别名全局唯一**：同一 alias 字符串至多指向一个实体。  
5. **同指表达唯一**：同指关系用 `aliases`（或等价）；禁止「双实体 + `alias_of` 边」表达同一对象。  
6. **端点与实体同策**：关系/别名 payload 中的名称与实体候选使用同一套 resolve。  
7. **CLI 与 API 同策**：审批后的端点校验、级联拒绝共用一套逻辑。  
8. **比较键一致**：归一与指纹、库查、批内去重使用同一比较键（含 casefold）。

触发例（说明不变量，非特例清单）：权威源已声明 `StampGIS Tools → StampTools` 时，任意路径都不得再产生第二个 Product 节点。

## 4. 范围

| 做 | 不做 |
|----|------|
| 建立统一的实体身份服务，并让 Staging / Review / Apply 服从其结论 | 在 pipeline / applier / governance / LLM 各加互不相干的特判 |
| 将 LLM 仲裁收进身份服务 | 全图两两比对；LLM 直写正式库 |
| 名称权威源分层统一 | 问答检索策略、生产开图 |
| Schema 约束与身份合约对齐（别名唯一等） | 保留「只标注不生效」的旧消解语义 |
| 用行为不变量验收 | 堆叠易过期的逐步补丁工单当作长期架构 |

历史脏数据清理可复用同一 `resolve` 做只读审计；不作为本设计的主路径，也不应用一次性脚本代替身份服务。

## 5. 落地策略（如何改，而不堆补丁）

### 5.1 优先重构，而非旁路

- **收敛**：现有 `EntityResolutionService`、`CandidateNormalizer` 中与身份相关的逻辑，应并入或委托给 `EntityIdentityService`，避免长期双轨。  
- **删除无价值残留**：不再保留「resolution 仅供展示」的行为；安全门与身份结论重复时，以身份服务为准，去掉重复规则副本。  
- **临时兼容**：若需短期适配旧 payload 字段名，须注明废弃期限，最终只保留 §2.2 结论枚举。

### 5.2 建议交付顺序（按依赖，不是按漏洞编号）

1. **身份服务 + 比较键 + 权威源查阅顺序**（不变量 1、8）  
2. **Staging / Apply 服从结论**（不变量 2、3、6）  
3. **LLM 仲裁接入身份服务**（`uncertain` 路径）  
4. **Schema 与审批路径对齐**（不变量 4、5、7）  

每一步结束时，对应不变量应可测；不要先加开关绕过，再指望后续补上。

### 5.3 文档与代码

- 本 PRD 只固定原则、合约、不变量与决策。  
- 类名、CLI 子命令、prompt 文件名以实现为准，不在此维护易过期清单。  
- 注释只解释「为何必须经身份服务 / 为何 LLM 不能覆盖 different_from」，不复述代码步骤。

## 7. 风险

| 风险 | 原则性应对 |
|------|------------|
| 误合并独立产品 | `different_from` 与类型冲突为硬约束，高于 LLM 与相似度启发 |
| 短名误伤 | 不用裸子串当最终裁决；未决走 `uncertain`，不靠特判表堆例外 |
| 仲裁成本 | 只对候选对；禁止全图两两；默认关 |
| 迁移期双轨 | 允许短窗口兼容旧字段，但验收以「单一入口」为准，到期删除旁路 |
