## 6. 漏洞模式归类（新发现 + 已知复现）

| 模式 | 计数（回退+仍 miss） | 代表题 | 是否新产品洞 |
|------|---------------------:|--------|:---:|
| 邻域挤占 | 1 | graphrag-021 | 部分新（021 StampServer 概述；005 已控住） |
| 链接失败/fallback | 3 | graphrag-006, graphrag-007, graphrag-025 | 新扩测暴露：evidence_filtered + no_linked_entity |
| 改写偏锚/实体链偏 | 4 | graphrag-009, graphrag-020, graphrag-030, graphrag-034 | 已知强化：叶子被 Product/主干吞掉 |
| 金标过窄/过宽 | 0 | - | 本轮启发式未主导标记 |
| 跨类目串扰 | 0 | - | 本轮未形成 Hit@3 回退主因 |

### 模式说明

1. **改写偏锚 / 实体链偏（主洞）**  
   查询含宽产品名或主干工具时，EntityLinker 优先锚到 `PipelineBuilder` / `StampWebRTC` / `StampServer`，
   丢掉 Error/Command/环境叶子（020 / 009 / 030 / 034）。融合上限压不住「链错实体」。

2. **链接失败 / fallback**  
   - `graph_evidence_filtered`：实体链上了，但图侧 chunk 被过滤（006 / 007）。  
   - `no_linked_entity`：题面实体名与运行时链接失败（025 HTTPS/私有CA）。

3. **邻域挤占**  
   StampTools 概述（005）在融合上限下已好转；**StampServer 概述（021）仍 miss**——宽 Product × 多链接仍脆弱。

4. **跨类目串扰**  
   041（StampServer WebRTC 部署 vs StampWebRTC 产品）本轮未进入回退/仍 miss 主表；需人工抽检答案语义，单靠 chunk 金标不够。

5. **金标噪声**  
   金标来自 `entity_chunk_links ∩ Chroma`；宽 Product 金标过宽、弱叶子金标过窄时，指标会夸大/低估产品问题。解读时以个案为准。
