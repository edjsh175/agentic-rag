## 一、项目概述

### 1.1 背景与问题

系统已具备 Hybrid 检索、产品主干锚定、图辅助改写、图扩召回融合、意图/阶段扩写、反问卡片（`/query/clarify`）与接口类 DOCX 入库。近期真实需求扩展为：

> 在本地 AI 下，基于知识库（尤其 WebRTC/WebGL 接口说明书）输出**符合产品 API 的二次开发代码示例**（如创建折线并设置线色/线宽、多边形填充等）。

验收与 trace 暴露的问题不是「没有手册」，而是**运行时在主体不明时猜错子图并继续检索**：

| 现象（2026-08-13 qa_traces） | 说明 |
|------------------------------|------|
| 用户问「写一段创建折线的代码，线颜色红色、线宽 3」 | 有写代码意图，但**未点名** StampWebRTC / StampWebGL / StampUtil |
| 现行反问未触发，直接检索 | 预检主要吃「管线 / pipeline」宽词；本问无产品名、aliases 为空，被放行 |
| `backbone_canonical = PipelineWebGL`，`primary_intent = product_intro` | helper **猜锚**到业务应用层管线 WebGL 产品介绍 |
| `graph_rewrite = "PipelineWebGL 创建折线"`（权重约 1.1） | **坏锚 + 高权重改写**把检索拉向错误产品 |
| `planner_stage` ×7：工程设置 / 数据设置 / 编译… | **J2 管线工具**阶段词污染写代码问句 |
| `linked_entities` 含「数据设置」「参数设置」（`name_exact`） | stage 词被 EntityLinker 当实体，图扩召回继续走管线邻域 |
| 命中 Explorer UI、Ax `CreatePolyline`、Canvas/v-charts 博客 | 未落到接口说明书 `createElementLineParams`；Explorer/COM 从字面也可解释该问，必须靠反问区分 |
| 回答变成 Canvas HTML 或错误 COM 接口 | 错误 context 上的错误合成 |

手册与可行性验收表明：WebRTC/WebGL 说明书中**确实存在** `StampUtil.createElementLineParams`、`linecolor`、`linewidth`、`createElementPolygonParams`、`fillcolor` 等——**知识存在，链路未接到**；判定为 `FEASIBLE_WITH_MANUALS`（不必 Vue 整仓源码）。L1 脚本问句常含「StampGIS / 二次开发」，且直接 Hybrid，**不能**当作现网全链路已可用。

产品主干 `product_relation_backbone.json` 中已存在：

- 分层实体「二次开发与集成层」
- 该层下 `SDK`、`COM`；另有 `StampWebRTC`、`StampWebGL` 等产品节点（其 `layer`/`doc_category` 现为「主干」，**尚未**挂到二次开发层）
- `SDK -[belongs_to]-> 二次开发与集成层`；`StampWebGL -[belongs_to]-> WebGL`（与 `PipelineWebGL` 同属 WebGL 兄弟，主干**无** `different_from`）

即：**图里有二次开发锚点，但无产品名的写代码问句被猜到 Pipeline***；「二次开发与集成层」「SDK」等 aliases 偏空；现行反问也不会拦住本问。


### 1.2 第一性原理（设计公理）

| # | 公理 | 含义 |
|---|------|------|
| A1 | 任务决定子图 | 不同任务必须落到图谱中**正确的实体邻域**；错锚会使一切图上能力变成负作用 |
| A2 | 图谱是路由与约束，不是万能事实源 | 二次开发题用图回答「该走哪条 SDK/产品线/文档族」；具体 API 参数仍以接口说明书 chunk 为事实 |
| A3 | 改写必须分意图模板 | J2（管线 procedure）阶段词不得用于二次开发写代码；J3 改写应导向 API/接口文档词 |
| A4 | 证据完整先于生成聪明 | 没有完整 API 代码单元进 context，再好的改写也无法稳定产出合格示例 |
| A5 | 默认不叠加旁路 | 禁止用「关图谱」掩盖错锚；禁止未经验证的独立代码图谱树抢主路径 |
| A6 | 坏锚不得享受高权重改写 | Job=J3 且 canonical ∉ 允许列表时：降权或丢弃 `graph_rewrite`，并关闭图扩召回/融合（图谱仍开，但不信任坏锚产物） |
| A7 | 止血与治本双轨 | 运行时错链（锚定/模板）与证据形态（API 原子切块）并行；不得互相等待对方「全部完成」才验收 |
| A8 | 主体不明禁止**猜正锚** | J3 特征命中但未点名产品/调用面、且无 `clarification_selected` 时：**强制反问**；选定前不得把某一 `canonical` 当作检索正锚，不得写 `graph_rewrite`、不得跑图扩召回/融合；禁止 LLM 猜 `Pipeline*`。**停止的是带锚文档检索，不是图谱候选收集。** |
| A9 | 反问选项由约束子图生成 | 与 J2 同构：`问句 × 产品主干 → seeds`；helper LLM **不发明**不在种子中的实体，只决定是否反问、问法、可选排序。J3 的候选宇宙是**二次开发子图**（见 §3.5），硬排除 D3 Pipeline*。禁止用全库 Hybrid 猜产品来填卡片；禁止把 Phase 0 写死四条菜单当作正式方案。 |

违反 A1–A3、A6、A8、A9 的方案（例如编码路径禁用图谱、主体不明仍**正锚**猜产品并继续检索、用 J2 全族种子灌 J3 卡片、继续全局 `product_intro` + Pipeline stage、或坏锚仍 1.1 权重注入）**不接受**。


### 1.3 任务分层（Job）

| Job | 用户意图 | 正确锚定邻域（示例） | 改写应产出 | 证据主源 |
|-----|----------|----------------------|------------|----------|
| **J1** 产品/关系问答 | A 是什么、属于谁 | 对应 Product/Module | 介绍/关系向 query | 手册说明 + 已审关系 |
| **J2** 配置/工具操作 | 怎么配、怎么编译；或用户在反问中选择 Explorer 操作 | PipelineBuilder 等 Tool；Explorer 操作说明 | 工程设置/数据/编译等阶段词（**仅此 Job**） | 用户手册步骤 |
| **J3** 二次开发代码示例 | 写调用代码、改线面样式参数（用户已点名或已选 SDK 产品线） | **StampWebRTC / StampWebGL**（首期正锚目标）；`SDK` / `二次开发与集成层` 仅作词表/选项辅助，不宜单独当检索锚 | `StampUtil`、API 名、linecolor/linewidth、接口说明书 | 接口说明书完整 API 块（+ Cookbook 对照） |
| **J4** 工程内改 UI（可选后续） | 改 Vue 皮肤/组件 | 样例包或用户粘贴 | 另议 | 非本 PRD 主交付 |

Job 是对 QueryPlanner intent / backbone `primary_intent` 的**门控**，不是第三套各自写 query 的分类器。本 PRD 主交付：**J3 可用且不破坏 J1/J2**。

反问选定 COM/Ax：首期**不按 J3 SDK 正锚验收**（可展示选项并说明暂不覆盖，或二期单列）；禁止静默改锚到 StampWebRTC。


### 1.4 目标

1. **主体不明先反问（A8 / A9）**：无产品名/调用面的写代码问句强制出卡片；选项由二次开发子图生成（与 J2 同构）；**禁止**未选定就正锚检索 / 猜 `Pipeline*`。
2. **正锚（选定后）**：用户点名或 `clarification_selected` 之后，J3 稳定锚到二次开发子图，**禁止**落到 `PipelineBuilder` / `PipelineWebGL` 等工具/管线产品介绍链。
3. **改写扩展**：在保留 J2 模板的前提下，新增 **J3（二次开发/SDK）改写模板**；选定后的 forced anchor **不得**再写 `{canonical} 介绍` / `product_intro`。
4. **坏锚防护**：J3 未落入允许列表时，`graph_rewrite` 降权或丢弃，并关闭图扩召回/融合（A6）。
5. **代码证据治理**：接口说明书（DOCX/PDF）中 API 小节（签名 + 参数 + 示例）原子化入库；Cookbook 对照轨并行。
6. **编码生成契约**：允许基于检索到的 API 合成完整示例；禁止编造未出现的 `StampUtil.xxx`；输出可验收结构。
7. **可观测验收**：qa_traces 可回放 Job、是否反问、选定实体、intent、改写模板、各 kind query、命中文档；J3 题集 API 名/关键参数/完整性达标。
8. **明确不做**：不以关闭 `graph_retrieval` / `query_rewrite` 作为 J3 解决方案；不在本阶段强制上独立「代码调用图谱树」；不灌 Vue 整仓；不在主体不明时用图**猜正锚**（允许用图**收集选项**）；不以「全库文档检索结果」替代主干子图作为卡片选项来源。


### 1.5 非目标

- 整仓 Vue 源码向量化与工程级 Coding Agent。
- 用关系边正文直接当 API 事实来源。
- 一次性重做全部 GraphRAG 生产默认开关策略（生产模板仍可保持审慎；本 PRD 聚焦**能力正确性**与本地/验收路径）。
- 以「通用代码解析平台 / 独立代码图谱」替代本 PRD 的 J3 主路径。
- 两轮反问（产品一轮、调用面一轮）；一张卡片问清即可。

| N3 | 第十节开放项若不定会拖启动 | Phase 0 采用 §十默认值；Cookbook 路径/完整性阈值留给 Phase 2 | §十 |
| N4 | 无「写代码」动作词的样式问句不强制 J3 反问 | 演示与 G0 **只用** `j3-line-style-clarify` → 选定 → G0-A；勿拿「创建多边形并设置填充色」「怎么设透明度」当 Phase 0 J3 成功案例 | §3.4、§七 |

**Phase 0 成功范围**：过 G0-C / G0-A 即可。不要把「选定 StampWebRTC 后立刻吐出可粘贴 `createElementLineParams`」算进 Phase 0——那是证据轨（Phase 2–3）。


## 二、问题根因（因果链）

```text
写折线样式代码（无产品名）
  → 现行反问未触发                              ← 门未关（A8）
  → helper 猜锚 PipelineWebGL + product_intro   ← 主断点
  → graph_rewrite 高权重走管线产品子图           ← 放大器（A6）
  → planner_stage 套用 J2 阶段词
  → EntityLinker 精确命中「数据设置」等
  → 检索远离接口说明书（Explorer / Ax / 博客）
  → 生成无正确 API 上下文 → 胡写 / 拒答式胡说
```

并行次因：

- DOCX 代码示例易碎，即使召回也对「完整可粘贴」不友好。
- 接口说明书 `doc_category` 偏「其他」，二次开发过滤弱；StampWebRTC/WebGL 主干字段现为「主干」，卡片 `doc_category` filter 可能带不上检索枚举。
- 主干「二次开发与集成层」「SDK」等 **aliases 不足**，soft_match 难命中。
- 「WebGL / 折线」字面易与 `PipelineWebGL` 撞车；二者同属 WebGL 兄弟且缺 `different_from`。
- 选定后 `_force_backbone_entity` 现写 `{canonical} 介绍` + `product_intro`，即使正锚也会检索跑偏。


### 2.1 两类失败的分离（避免工程无界）

| 失败类型 | 典型表现 | 主修复阶段 |
|----------|----------|------------|
| **错链型** | 主体不明仍正锚检索、锚到 Pipeline*、stage 污染、Canvas 胡写；或 J3 卡片复用管线全家桶 / 写死菜单与问句无关 | Phase 0–1 止血；**V1.7 D8 纠偏**（子图选项） |
| **证据型** | 手册有 API 但 chunk 半截、参数散落 | Phase 2–3（Cookbook 可提前对照） |

不得用「先做完美切分」阻塞错链止血；也不得宣称 Phase 0 完成后示例完整率已达标。


## 三、目标架构

### 3.1 运行时逻辑（目标态）

```text
Query

        否 → mode=clarify：一张调用面卡片（D8 / A9）
              选项 = 问句 × 二次开发子图 seeds（§3.5）；禁止 Pipeline*
              选定前：不写 graph_rewrite；不跑正锚文档检索 / 图融合（A8）
        是 → 用户选择 / 点名锁定 Job + canonical
              选 StampWebRTC/WebGL StampUtil → Job=J3
              选 Explorer 操作 → 非 J3（操作说明）

  → 改写门控
        Job=J3 且 canonical ∈ D2 → J3 模板（含 forced anchor 路径；禁止「X 介绍」）

  → Hybrid 检索（+ 可选图扩召回；仅正锚后预期正收益）
        J3 可偏好：接口说明书 / content_type=code / Cookbook；filter 以 entity_name 为准
  → 生成
        J3 → 编码契约 Prompt
        其他 → 现有问答契约
```

### 3.3 图谱用法（必须保留）

对 J3，图谱的合法用途：

1. **反问选项种子（A9）**：卡片选项来自主干**二次开发子图**（问句 soft-match + 宽词/家族扩展 + `different_from` 兄弟），**不是**写死菜单，也不是文档检索阶段猜锚。
2. **选定后消歧与路由**：WebRTC vs WebGL、走 StampUtil SDK。
3. **改写约束**：canonical / aliases / 一跳到接口文档产品线名称。
4. **避免易混实体**：补 `different_from`，避免追问时再锚到 Pipeline 工具链。

不合法用途：

- 主体不明时用词表让 LLM **选定** `PipelineWebGL` 当 `backbone_canonical` 并继续检索。
- 用 J2 的「管线」宽词家族扩展把 Pipeline* 灌进 J3 卡片。
- 让 helper **发明**主干中不存在的产品名，或忽略种子另写选项。
- 用「地下基础设施管理 -[belongs_to]-> PipelineWebGL」一类边支撑「如何写折线 API」。
- 在错锚情况下仍高权重注入 `graph_rewrite` 或继续图融合。

说明：当前主干**没有** StampWebGL/WebRTC → SDK / 接口说明书 的边。Phase 0–1 用图做**正锚实体约束**；V1.7 起用图做 **J3 选项生成**（与 J2 同构、换子图）。不声称「图已能路由到 API 块」。若要证明图谱检索正收益，在选定后做 A/B（J3 改写 vs 仅原问）。


### 3.4 J3 特征检测（规则初稿，实施可微调）

**高置信写代码意图**（用于 D7：可能需要反问或进入 J3；**样式词单独不得强制 J3**，以免把 Explorer 标绘操作题判成写代码）：

- 动作（至少一类）：`写代码`、`写一段`、`代码示例`、`二次开发`、`接口调用`、`StampUtil`
- 文档指向：`接口说明书`、`WebRTC接口`、`WebGL接口`

样式/标绘词（`创建折线`、`创建多边形`、`线宽`、`线颜色`、`填充色`、`fillcolor`、`linecolor`、`linewidth`）仅作**加权与弱扩写词典**，不单独强制 Job=J3。

**主体已明确**（可检索、可正锚）当且仅当：

- 问句已点名 D2 产品（`StampWebRTC` / `StampWebGL` / 明确别名），或
- 请求已带 `clarification_selected` / `entity_name` 且属于 D2，或
- 用户显式点名 Pipeline*（走 D3 例外，按点名产品，不按 J3 SDK 白名单硬纠）

否则：D7 强制反问。

显式 J2 保护（避免误伤）：

- 问句同时出现 `PipelineBuilder` / `新建工程` / `工程设置` / `数据编译` 等，且无「写代码/StampUtil」时 → 保持 J2，不走 J3 反问


### 3.5 J3 反问选项（D8 / A9：与 J2 同构，换子图）

**根因（不要再补丁）**：Phase 0 把选项写成死表，是因为当时复用 J2 种子会扩出 Pipeline*。正确修复是**换候选宇宙并硬过滤**，不是取消图谱。

**J2 已验证的机制（保持）**

```text
问句 → 主干 soft-match / 宽词 / 家族扩展 → seeds
     → helper LLM：是否反问 + 问法（忽略其 option_ids，不发明实体）
     → 卡片展示 seeds
```

**J3 正式态：同一骨架，约束子图**

```text
问句（已判 J3 且主体不明）
  → 在二次开发子图内 soft-match + 宽词（二次开发 / 接口 / SDK / StampUtil / WebRTC / WebGL）
  → 家族扩展仅限该子图；`different_from` 兄弟可进入（StampWebGL ↔ 排除 PipelineWebGL）
  → 硬过滤 D3 Pipeline*
  → 任务出口（非 canonical）：
        COM：主干已有 `COM` 节点且命中二次开发层时进入；选定后按 D11
        Explorer：Job 分流哨兵（主干无 StampExplorer，禁止伪造实体）；仅当问句仍可能被理解为桌面操作时附加
  → helper：只写 ask_question / 是否需要问 / 可选排序；不得增删种子外产品名
  → 一张卡片；min_options 仍 ≥ 2，否则不得静默猜锚（可短拒答引导）
```

**二次开发子图（候选宇宙，首期）**

| 进入 | 不进入 |
|------|--------|
| `StampWebRTC`、`StampWebGL`（D2 正锚候选） | `Pipeline*` / `PipelineBuilder` 等 D3 |
| `SDK`、`二次开发与集成层`（选项辅助；**选定后不得单独当检索 canonical**，落到最近 D2 或继续问） | 管线工具 / 发布服务等 J2 邻域 |
| `COM`（调用面出口，不按 J3 SDK 正锚验收） | 任意 Hybrid 文档命中文件名当选项 |

**与「文档检索」的边界**：本步读的是产品主干 JSON / 正式图上的实体与关系，**不是** Chroma/BM25 找说明书 chunk。选定前仍禁止带锚 Hybrid。

**Phase 0 死表的地位**：`j3_clarify_options()` 四条写死菜单是止血实现，V1.7 起为**回滚开关**，不是目标架构。验收以「子图生成 + 无 Pipeline*」为准，不以「文案必须四条原文」为准。

**示例（复现问句，无产品名）**

问「写一段创建折线的代码…」→ 子图因「写代码 / 二次开发」宽词与 SDK 产品别名，至少应给出 StampWebRTC、StampWebGL（可含 COM / Explorer 出口）；**不得**出现 PipelineWebGL。


## 四、功能需求

### FR-0 J3 主体不明强制反问（V1.2；V1.3 补后端门；V1.7 拆「猜正锚」与「出选项」）

- 满足 §3.4 写代码意图且主体不明确时：`needs_clarification=true`，前端展示 D8 卡片。
- 规则强制「要不要问」，不依赖 helper 的 `needs_clarification` 判断；helper 只服务问法/排序（A9）。
- **选定前禁止正锚文档检索**：不跑 `anchor_from_backbone` 猜 canonical、不产 J2 `planner_stage`、不跑图扩召回/融合、不写 `graph_rewrite`。
- 选项**不得**含 Pipeline*（除非问句已点名管线，则不走本 FR，走既有管线反问）。
- **后端门（D10 / N1）**：即使调用方跳过 `/query/clarify`，`/query` 与 `/query/stream` 仍须遵守上款；允许返回 clarify 结构或短拒答；**禁止**静默猜 `Pipeline*`。
- 预检失败可降级，但 J3 无产品名路径**不得**降级为猜正锚；宁可只走 original + 弱扩写且仍禁止 Pipeline* canonical（此降级仅作逃生，正式态应出卡片）。

### FR-0b J3 选项由二次开发子图生成（V1.7）

- 实现必须复用 J2 澄清骨架（`_collect_backbone_seed_names` 一类），**不得**再维护一份与问句无关的正式选项常量作为主路径。
- 种子收集时：
  - 候选宇宙 = §3.5 二次开发子图；
  - 宽词用二次开发/SDK/接口，**不得**把 J2 的「管线 / pipeline」家族扩展套到 J3；
  - 产出后硬丢 D3；
  - `SDK` / `二次开发与集成层` 可出现在卡片，用户选中后不得直接当 Hybrid canonical（映射到 D2 或二次澄清）。
- helper LLM：输入为问句 + seeds JSON；输出不得新增 `entity_name`；现有「忽略 option_ids、返回完整 seeds」策略可保留，或改为只允许对 seeds 排序/隐藏非相关项（隐藏后仍须 ≥2 且不含 Pipeline*）。
- Explorer 哨兵：不是主干实体；仅作 Job 出口；label 可固定，**不得**因此把 D2/COM 也写死。
- 回滚：配置可切回 Phase 0 四条死表；默认关闭该回滚。
- 观测：trace `clarify.options` 记录每个选项的 `source`（`backbone_seed` / `task_exit` / `rollback_static`）。

### FR-1 二次开发子图可锚定（选定后正锚）

- 白名单实体（D2）具备足够 aliases（至少覆盖：二次开发、接口开发、StampUtil、WebRTC 接口、WebGL 接口、SDK 调用等；定稿表见执行清单）。
- **验收对象**是「已点名或已选择」的 J3 题：`backbone_canonical ∈ {StampWebRTC, StampWebGL}`，错误锚到禁止列表为 **0**。
- 无 selected 的原问**不**用本条验收（用 FR-0 / G0-C）。

### FR-2 锚定硬门控

- Job=J3 时：
  - `canonical` 不得落入禁止列表（D3），除非用户显式点名或 forced anchor。
  - `primary_intent` 不得为 `product_intro`（**默认字段名 `sdk_code`**，见 §十）。
- 用户澄清选择实体时，以用户选择为准；选 COM/Explorer 不得改写成 D2 冒充正锚（D11）。

### FR-2b 选定后 forced anchor 的 J3 改写（V1.2）

- `_force_backbone_entity`（或等价路径）在 Job=J3 时必须走 J3 模板。
- **禁止**再产出 `{canonical} 介绍` 且 `backbone_primary_intent=product_intro`。

### FR-3 J3 专用检索改写

- 新增改写模板，输出 1～3 条检索 query，应包含：锚定产品/SDK 名、API 或标绘动作词、样式参数词（如有）。
- **禁止**输出管线工程阶段词（工程设置、数据编译、编译级别等）。
- `graph_rewrite` 可保留 kind；内容必须来自 J3 模板。
- J2 现有 stage/改写仅在 Job=J2 时启用。

### FR-3b 坏锚改写与图融合策略（V1.1，V1.2 补融合）

- 当 Job=J3 且最终 `canonical` ∉ D2：
  - **不得**以高权重注入基于该 canonical 的 `graph_rewrite`；
  - 策略取一：默认 **`drop`**（§十）；可配置改为 `downweight`（权重上限建议 ≤ original）；
  - **不得**跑图扩召回/融合；不得把错误 `relation_summary` 注入回答 prompt；
  - 仍允许基于规则词典的弱扩写（如补 `StampUtil`、`创建折线`），且**不引用** Pipeline* 名。
- planner_stage 词不得进入 EntityLinker。
- trace 必须记录 `graph_rewrite_policy`。

### FR-4 planner_stage 与 Job 绑定

- 「工程设置/数据设置/编译…」仅绑定 J2（或锚定为 PipelineBuilder 等 Tool）。
- Job=J3：不产生上述 stage queries；可选产生接口手册章节向弱提示（环境准备、标绘、创建折线），权重低于 original。

### FR-5 接口手册代码切块（治本）

- 对 WebRTC/WebGL 接口说明书等：将「API 标题 + 参数说明 + 代码示例」尽量保留为原子检索单元。
- 元数据：`content_type=code`（或等价 role）、`api_name`（能解析时）、`doc_category` 对齐 StampWebRTC/StampWebGL/二次开发。
- 与切块基石治理 PRD 对齐；本 PRD 不重复定义通用切块架构，只定义 J3 对证据形态的要求。

### FR-5b Cookbook 对照轨（V1.1 明确；V1.5 路径）

- 允许从说明书抽取 8～15 个 Markdown 样例（折线配色、多边形填充、透明度、Vue 引入 StampUtil 等）入库。
- **存放**：`watch_directory/upload/sdk_cookbook/`（首批 5 篇已落盘，见目录 README）。
- 用途：Phase 0–1 期间验证「正确链路下能生成合格示例」；补 DOCX 半截问题。
- **不得**替代 FR-5 治本立项；执行清单须同时挂 FR-5 与 FR-5b 任务。
- 入库后须 `POST /scan` 且 `review_status=approved`（扫描时避免与后端并发写 `chroma_db`）。

### FR-6 J3 生成契约

- 优先使用 context 中的 API；不得编造未出现的产品私有 API（尤其 `StampUtil.xxx`）。
- 输出结构：适用产品/版本 → API → 完整代码块 → 关键参数说明 → 验证方式；手册未覆盖处明确缺失。
- 通用知识补充不得冒充知识库 API；不得把图谱关系当 API 参数来源。

### FR-7 观测与回归

- qa_trace 必含：`job`、`clarify`（needs / options / selected / **option source**）、`backbone_canonical`、`backbone_primary_intent`、`rewrite_template`、`graph_rewrite_policy`、全部 queries（kind/weight/text）、命中 source 列表。
- 可重复脚本：
  - 澄清：原问 G0-C
  - 锚定/改写：选定后 G0-A；可并行于 `validate_map_style_l1_feasibility.py`（该脚本本身不代替全链路）
  - 生成：API 名/关键参数/代码块完整性（可半自动）
- J1/J2 代表题回归必跑。
