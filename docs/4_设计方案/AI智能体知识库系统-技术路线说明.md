# AI智能体知识库系统 · 技术路线说明

| 文档版本 | 修改日期 | 说明 |
|---------|---------|------|
| V1.0 | 2026-08-10 | 宏观技术方案（现行架构） |


## 1. 总体路线

系统是一套面向 GIS 产品技术资料的 **本地 RAG（检索增强生成）知识库问答** 方案，技术主线为：

```
文档入库 → 结构化分块 → 向量库（事实正文）
                ↘
              图谱库（实体/关系/实体↔块链接）──► 仅辅助检索与排序
                ↘
用户提问 → 混合检索（±图谱）→ 可选精排 → LLM 基于 chunk 原文生成带引用答案
```

三条硬原则：

1. **答案事实来自文本块（chunk）**：LLM 的 context 是检索到的正文；引用编号绑定真实来源。
2. **图谱不充当第二套问答引擎**：只用于实体消歧、扩召回相关块、改写检索 query、对已召回结果加减分。
3. **管线式编排，而非独立 Agent 调度服务**：问答在 FastAPI 单体中按固定阶段执行，失败可降级，不做多轮工具反思循环。

**检索与图谱在架构中的位置（对应原版「工具调用」）**：

| 能力 | 作用 | 是否写入答案事实 |
|------|------|------------------|
| Hybrid 文本检索 | 主召回通道：向量 Similarity ∥ BM25 → RRF；只取 `review_status=approved` | 是（chunk 原文进 context） |
| 图谱扩召回+融合 | 实体链接 → 关系扩展 → `entity_chunk_links` 取块 → 与文本路加权融合（席位控噪） | 否（仍用块原文） |
| 图辅助改写 query | 中量图摘要 → helper LLM 产出额外检索 query | 否 |
| Graph Intent 评分 | alias↑ / `different_from`↓ 等，改已召回块排序（可不依赖开图开关） | 否 |
| 回答侧实体提示 | prompt 消歧提示，声明非事实来源 | 否 |


## 3. 分层架构

| 层 | 技术选型 | 职责 |
|----|---------|------|
| **交互层** | Vue 3 + TypeScript + Vite | 对话（SSE）、审核、图谱画布/候选审批、质量与调试 |
| **服务层** | FastAPI（Python） | 入库扫描、问答管线、审核与图谱管理 API |
| **检索与生成** | LangChain 编排；Embedding / LLM 多 provider（Ollama / OpenAI / Google 等） | Hybrid 召回、可选 Rerank、prompt 组装与流式生成 |
| **向量存储** | ChromaDB | chunk 正文、embedding、章节/分类/审核等元数据 |
| **图谱存储** | SQLite | 实体、别名、关系、实体-chunk 链接、抽取候选 staging |
| **文件与策略** | 本地目录 + JSON | 监视入库目录、产品主干、领域目录、意图策略、反问种子等 |
| **部署** | 本地进程或 Docker 双容器（`rag-service` + `rag-web`） | API 与静态前端分离；可选 gpu-agent 显存监控 |


## 4. 数据技术路线

### 4.1 双存储分工

| 存储 | 存什么 | 在问答中的角色 |
|------|--------|----------------|
| **ChromaDB** | 可检索正文 + 向量 + `section_*` / `doc_category` / `review_status` / `kb_name` 等 | **事实主库**：检索命中后进入 LLM context |
| **SQLite 图谱** | 实体、别名、关系、`entity_chunk_links`、字段/流程、抽取候选 | **结构辅库**：通过链接把「实体邻居」映射回 chunk_id，再回到向量库取文 |

桥接关键：`entity_chunk_links`（实体 → chunk_id）。图侧召回最终仍落到向量库中的文本块。

### 4.2 知识组织

- **两个知识库**：按目录约定分为「已发布文章」「文章附件」，检索可按 `kb_name` 过滤。
- **文档分类**：chunk 级 `doc_category` 枚举（产品/业务域）；领域分层另由 `domain_catalog` 等 JSON 描述，经同步进入图谱建设链路。
- **审核门禁**：新块默认 `pending`；检索默认只使用 `approved`。
- **产品关系主干**：产品/服务等稳定结构以 JSON 主干维护，经审批同步写入正式图谱，供链接与扩展使用。


## 5. 文档入库技术路线

```
监视目录 / 上传 / 博客同步
  → 哈希去重
  → 解析（章节优先；表格转 Markdown；图片/视频经视觉描述）
  → 清洗（域代码、目录噪声等）
  → 分块（标题硬边界 + embedding 语义边界；表格/代码整块保护；异常则滑窗降级）
  → 写入 Chroma（pending）+ 更新文件索引 + 维护 BM25 索引
  → 人工审核通过后进入可检索集合
```

图谱建设与扫描入库**解耦**：规则抽取（章节路径/表字段/配置块等）± LLM 补实 → 候选批次 → 人工审批 → apply 正式库。避免扫描当下直接污染正式关系数据。


## 6. 问答检索技术路线（核心）

### 6.1 主路径：文本 Hybrid RAG

```
提问
  →（可选）歧义预检：选项澄清后再检索
  → 对话上下文化 / 多 query 构造
  → 检索计划（意图 → top_k、是否精排等）
  → Hybrid：向量 Similarity ∥ BM25 → RRF 融合
  →（可选）Cross-Encoder 精排
  → 后处理加权与裁剪（章节/表格结构、token 预算等）
  → LLM 生成（同步或 SSE）+ 确定性引用与证据
```

主路径保证：即使不开图谱，系统仍是完整可用的文本 RAG。

### 6.2 辅路径：图谱四类介入

在主路径关键节点注入，可叠加，均可降级跳过：

| 介入方式 | 技术动作 | 影响对象 |
|----------|----------|----------|
| **Intent 评分** | 用别名、`different_from`、字段/章节等信号对**已召回**块加减分 | 排序 |
| **图扩召回 + 融合** | 问题链实体 → 沿关系扩展 → `entity_chunk_links` 取块 → 与 Hybrid 结果加权融合（限制纯图路席位、保护文本 top1） | 候选集合与排序 |
| **图辅助改写 query** | 中量图摘要（名/别名/兄弟关系类型/路径词等，不喂证据正文）→ 辅助模型改写检索语句并入 Hybrid | 召回 query |
| **回答侧消歧提示** | 已链接实体时，在 system 中附加别名/易混提示，并声明非事实来源 | prompt，不增加事实通道 |

配置上可将「图扩召回/改写」整体关闭；Intent 评分可独立于扩召回开关工作。

### 6.3 生成与治理

- Context **只放**检索得到的 chunk 原文（及显式开启的外部搜索结果）。
- 无足够依据时先给出未命中提示；允许配置「通用知识补充」但与知识库结论分离标注。
- 来源编号、文件名、页码（或「无页码」）、原文片段由后端确定性生成，禁止伪造页码与虚构引用。


## 7. 智能体工作流程

原版为 12 步 Agent（预检得分阈值 → 反问 → 正式检索 → 图谱扩展 → 重排 → 生成 → 偏好记忆）。  
**现状**按下列管线执行（实现入口：`rag.py` 等服务模块）：

| 步骤 | 阶段 | 动作 | 决策点 |
|------|------|------|--------|
| 1 | **感知** | 接收用户问题 + 对话历史（前端/可选后端聊天记录） | 闲聊正则 → 直接 LLM，跳过检索；敏感 → 拒答 |
| 2 | **歧义预检** | `POST /query/clarify`：LLM 主判 + 规则种子降级 | **命中** → 前端反问卡片，用户带过滤条件再问；**否则**继续 |
| 3 | **上下文化** | 历史改写独立问题 + 多 query + 来源锚点；失败启发式 | — |
| 4 | **意图/计划** | QueryPlanner：流程/部署/排错/对比等 → top_k、是否 rerank 等 | — |
| 5 | **图谱准备**（可选） | `graph_retrieval.enabled=true` 时：实体链接 → 关系扩展 → 经 `entity_chunk_links` 取图侧 chunk；可选图辅助改写 query | 失败 → fallback 纯文本路 |
| 6 | **正式检索** | Hybrid：向量 Similarity ∥ BM25 → RRF；过滤 approved；可选 kb/分类/实体锚定 | — |
| 7 | **图谱融合**（可选） | 文本路与图侧块加权融合；`max_graph_only_slots` + `protect_text_top1` 控噪 | 关图则跳过 |
| 8 | **重排序**（可选） | Cross-Encoder Rerank；生产 CPU 默认关，本地可开 | 全局 `reranker.enabled` 三层门控 |
| 9 | **后处理评分** | 结构化加权（表格/章节等）+ **Graph Intent**（alias / `different_from` / field / section） | Intent **不依赖**开图开关 |
| 10 | **上下文组装** | Token 预算裁剪 + 历史摘要；可选联网搜索（显式开启） | — |
| 11 | **生成答案** | chunk 原文（编号）进 prompt；若已链实体可附加**消歧提示（非事实）** → LLM（同步/SSE） | 无依据先输出未命中提示；可选通用知识补充 |
| 12 | **溯源与证据** | 确定性来源引用 + 证据包；可选 QA trace 全流程记录 | — |
| 13 | **反馈** | 有用/无用 → `user_feedbacks` | **无** `user_preferences` 记忆跳过反问 |

与原版步骤 7–9 的对应关系：

- **正式检索** = 现状 Hybrid（主路径）。  
- **图谱扩展** = 现状「先链实体再取块再融合」，不是「仅用已命中 chunk 反查 links 扩 1 跳」这一种写法；并增加图改写 query、Intent 加减分、回答侧消歧提示。  
- **答案依据**始终是 Top 上下文中的 **chunk 文本**，不是关系句子。


## 8. 业务流程详细说明

### 8.1 文档入库流程

```
【开始】
   ↓
① 文档进入 watch_directory / 上传接口 / 博客爬取或发布同步
   ↓
② 系统自动（定时约 30 分钟或 POST /scan）：
   a. SHA-256 哈希去重（移动/重命名可追踪）
   b. 解析（md/docx/txt 优先章节切片；pdf/doc；Excel→Markdown 表；图片/视频→视觉描述）
   c. 清洗（Word 域代码、纯目录/纯链接/噪声）
   d. 分块（章节硬边界 + 语义边界；表格/代码结构保护）
   e. 向量化写入 Chroma，review_status=pending
   f. 更新 file_index；重建 BM25；清查询缓存
   （图谱抽取不在本步自动 apply 进正式库）
   ↓
③ 业务员在【知识块审核工作台】处理 pending：
   - 通过 → approved（可被检索）
   - 驳回 → rejected
   - 可改章节标题、doc_category
   - 无合并/拆分/块内改文 → 切错则驳回后由开发侧重切
   ↓
④ approved 后进入检索集合
   ↓
【结束】
```

### 8.2 用户问答流程（含反问场景）

```
【开始】
   ↓
① 用户在【智能对话页面】输入问题
   ↓
② 闲聊/敏感分流；否则进入问答管线
   ↓
③ 提问前歧义预检（/query/clarify）
   ├─ 命中 → 反问卡片 → 用户选择过滤条件 → 继续
   └─ 未命中 → 继续
   ↓
④ 上下文化 + QueryPlanner
   ↓
⑤ [可选] 图谱准备：链接实体 / 扩召回取块 / 改写检索 query
   ↓
⑥ Hybrid 正式检索（approved + 可选分类/知识库过滤）
   ↓
⑦ [可选] 图侧与文本路融合（席位控噪 + 保护文本 top1）
   ↓
⑧ [可选] Rerank → 后处理（结构化加权 + Graph Intent）
   ↓
⑨ 组装 context（仅 chunk 原文 + 可选实体消歧提示）→ LLM 生成（SSE）
   ↓
⑩ 展示来源/证据；用户反馈有用/无用
   ↓
【结束】
```

### 8.3 图谱维护流程

```
【开始】
   ↓
① 方式一：规则管线 ± LLM 抽取 → extraction_candidates
   - SectionPath / TableField / ConfigBlock 等确定性抽取
   - 可选 LLM 语义补实（配置开关）
   - 指纹去重进批次
   ↓
② 方式二：产品主干 / domain_catalog / Profile 等 JSON 同步进 staging
   ↓
③ 审批：【图谱候选审批台】或 CLI（run_graph_build.py）
   - 分拆审批；禁止对敏感 mode 滥用 --approve-all
   - apply 需三重确认（DB 路径 / 批次 / 备份）
   ↓
④ 写入正式表：entities / aliases / relations / entity_chunk_links / fields / …
   ↓
⑤ 画布：查看、过滤、展开邻居；主干预览改 JSON（不直接当正式写）
   ↓
⑥ 审计 / Stale 清理 / 质量 / Task8.1 Gate 等运维命令
   ↓
⑦ 运行时：仅按配置介入检索管线（Intent / 扩召回融合 / 改写 / 消歧提示）
   ↓
【结束】
```


## 9. 模型与推理路线

| 角色 | 用途 | 接入方式 |
|------|------|----------|
| 主问答 LLM | 最终回答 | 按配置 provider（本地 Ollama 或外部 API） |
| 辅助 LLM | 澄清、改写、摘要、轻量判断 | 可与主模型分离，通常更小/更便宜 |
| Embedding | 入库与向量检索 | 独立模型；变更后需重建向量库 |
| 视觉模型 | 图片/视频帧描述 | 可选 |
| Reranker | Cross-Encoder 精排 | 可选依赖；生产可关，避免 CPU 重负载 |

可选 **GPU 显存监控**：按配置表估计模型占用，在显存不足时推荐或降级到可装下的模型；监控不可用时保守不自动降级。

## 11. 技术路线一览（一张图）

```
┌──────────────┐     ┌─────────────────────────────────────────┐
│  资料文件     │────►│ 入库：解析 → 分块 → Chroma + BM25        │
└──────────────┘     └───────────────┬─────────────────────────┘
                                     │ approved 后可检索
┌──────────────┐     ┌───────────────▼─────────────────────────┐
│  图谱建设     │────►│ SQLite：实体/关系/entity_chunk_links     │
│ 抽取→审批→库  │     └───────────────┬─────────────────────────┘
└──────────────┘                     │ 辅助：链接 / 扩展 / 评分 / 改写
                                     ▼
用户提问 ──► Hybrid 文本检索 ──►（可选图融合/精排）──► LLM（仅 chunk 事实）──► 带引用回答
```

**一句话归纳**：以 **Hybrid 文本检索 + LLM 引用生成** 为骨干，以 **知识图谱为检索增强层**，以 **审核门禁与候选审批** 控制进入正式库与可检索集合的数据质量。
