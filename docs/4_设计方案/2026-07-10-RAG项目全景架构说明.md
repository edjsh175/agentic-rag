# RAG 项目全景架构说明

> **说明（2026-07-28）**：架构主链路仍适用。图增强开关以 config.ini / config-prod.ini 为准（本地可开、生产模板默认关）；细节见 CLAUDE.md「当前运行时架构」。


## 1. 项目定位

本项目是一个本地 RAG 知识库问答系统。

核心目标：

> 使用文档检索提供事实依据，使用知识图谱提供领域结构信息，帮助检索阶段更准确地区分实体、字段、章节和关联关系。

知识图谱不是独立问答来源，而是 RAG 检索增强层。

---

## 2. 当前完整链路

```
用户问题
 ↓
FastAPI
 ↓
RagChain
 ↓
Query Understanding
 ├─ QueryContextualizer
 │   └─ 处理“它/这个/继续”等追问
 ├─ QueryPlanner
 │   └─ 判断问题类型，调整召回策略
 └─ RetrievalIntentResolver
     └─ 读取检索策略 policy
 ↓
检索召回
 ├─ Chroma 向量检索
 ├─ BM25 关键词检索
 └─ Hybrid RRF 融合
 ↓
Graph 增强
 ├─ EntityLinker
 ├─ GraphExpander
 ├─ GraphIntentFactProvider
 └─ GraphFusionScorer
 ↓
Cross Encoder Reranker
 ↓
Prompt 组装
 ↓
Ollama LLM
 ↓
回答 + 来源引用
```

## 3. 数据存储职责

### ChromaDB

负责：

- 文档 chunk
- embedding
- 向量召回

回答事实主要来自这里。

### SQLite Graph DB

负责：

- Entity
- Alias
- Relation
- Section
- Field
- Evidence link

用于：

- 实体消歧
- 字段匹配
- 章节匹配
- sibling 排除
- 检索排序增强

### retrieval_intent_policies.json

运行时策略：

- entity_ref
- intent_terms
- query_hints
- category preference

不保存领域事实。

### retrieval_intent_profiles_v1.json

历史迁移输入。

只用于 Profile → Graph 迁移，不参与生产评分。

## 4. 知识图谱在系统中的作用

例如用户询问：

```
管线点表中的管点编号是什么？
```

Graph 提供：

```
管线点表
 ├─ has_field → 管线点表.管点编号
 ├─ alias → 点数据结构
 ├─ defined_in → 对应章节
 └─ different_from → 管线线表/管线面表
```

这些信息用于帮助排序，而不是替代正文。
