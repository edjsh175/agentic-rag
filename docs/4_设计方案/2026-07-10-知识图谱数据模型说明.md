# 知识图谱数据模型说明

## 1. 图谱定位

当前 Graph DB 是 RAG 的领域事实层。

主要解决：

- 同义词识别
- 实体消歧
- 字段定位
- 章节定位
- 相似实体排除

---

## 2. 核心实体

### Tool

工具或系统。

示例：

```
PipelineBuilder
DOMBuilder
StampTools
```

### DataTable

业务数据表。

示例：

```
管线点表
管线线表
管线面表
```

### Field

字段。

当前规范：

```
{DataTable}.{Field}
```

例如：

```
管线点表.管点编号
```

禁止裸 Field：

```
管点编号
```

### Section

文档章节。

命名：

```
source::section_path
```

例如：

```
StampTools用户手册::PipelineBuilder > 数据规范 > 管线点表
```

---

## 3. 核心关系

### has_table

```
Tool → DataTable
```

表示工具包含哪些数据表。

### has_field

```
DataTable → Field
```

表示表有哪些字段。

### defined_in

```
Entity → Section
```

表示实体来源章节。

### belongs_to

```
Child → Parent
```

例如：

```
PipelineBuilder → StampTools
```

### different_from

表示明确不同。

例如：

```
管线点表 ↔ 管线线表
```

### Alias

不是关系边，而是独立 alias 表。

例如：

```
管线点表
alias:
点数据结构
```

---

## 4. Graph 与 RAG 的关系

Graph 不直接回答问题。

它影响：

- 哪些 chunk 更相关
- 哪些实体不能混淆
- 哪些字段应该匹配
- 哪些章节应该提升权重

最终答案仍需要正文 chunk 支撑。

---

## 5. 当前设计原则

1. canonical 事实只有一份。
2. alias 不创建重复实体。
3. Section 不创建 alias Section。
4. Field 使用 scoped name。
5. pending/rejected 不参与运行时评分。
