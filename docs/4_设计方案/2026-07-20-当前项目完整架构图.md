## 3. 知识库逻辑层与文档树

当前实现没有独立命名为 `DocTree` 的服务或表；文档树由 `watch_directory` 的真实目录、`file_index.json` 和每个 Chunk 的元数据共同表达。知识库是两个固定逻辑分区，而非各自独立的 Chroma 集合。

```mermaid
flowchart TB
    KBAPI["GET /knowledge-bases\n全部知识库 / 文章附件 / 已发布文章"] --> SELECT["问答页知识库选择\nQueryRequest.kb_name"]
    ROOT["watch_directory（物理根目录）"]
    ROOT --> ATTACH["任意非‘已发布文章’目录\n逻辑知识库：文章附件"]
    ROOT --> POSTS["已发布文章/\n逻辑知识库：已发布文章"]
    ATTACH --> ADIR["相对父目录 → kb_path"]
    POSTS --> PDIR["相对父目录 → kb_path"]
    ADIR & PDIR --> FILE["文档文件\nfile_path、file_name、SHA-256"]
    FILE --> INDEX["data/file_index.json\n文件、Chunk ID、分类、Profile、入库时间"]
    FILE --> CLASS["doc_category\n上传显式指定 > 重建继承 > 目录推断 > 其他"]
    FILE --> PROF["document_profile\n显式选择 > 重建继承 > 映射 > section_based"]
    CLASS & PROF --> CHUNK["Chroma Chunk 元数据\nkb_name、kb_path、doc_category、document_profile、\nsection_path、section_index、review_status=approved"]
    SELECT --> FILTER["RagChain 检索过滤\nkb_name + 可选 doc_category"]
    FILTER --> CHUNK
    AUTO["未指定知识库"] --> ROUTE["关键词或 Helper LLM 路由\n文章附件 / 已发布文章 / 不确定时两库合并"]
    ROUTE --> FILTER
```

因此，图中的“知识基底”应理解为：一个 Chroma 向量存储上的两个逻辑知识库，加上目录树、分类、Profile 和审核状态构成的检索范围；不是额外的树数据库或第三个图数据库。

## 4. 问答与检索链路

```mermaid
flowchart TD
    Q["POST /query 或 /query/stream\n问题、历史、知识库、模型、Agent 提示、联网开关"]
    Q --> G{"打招呼或敏感内容？"}
    G -->|"是"| DIRECT["固定简短回复或拒绝"]
    G -->|"否"| PLAN["QueryContextualizer\n追问改写、多查询；QueryPlanner / IntentResolver\n按流程、排错、比较等意图生成检索计划"]
    PLAN --> CACHE["Query Cache（当前关闭）"]
    CACHE --> RET["RetrievalStrategy"]
    RET --> V["Chroma 向量检索\nEmbedding Cache（当前启用）"]
    RET --> K["BM25 关键词检索"]
    V --> FUSE["Hybrid RRF 融合\n当前 method=hybrid"]
    K --> FUSE
    FUSE --> STRUCT["结构化加权\n表格、表头、章节命中（启用）"]
    STRUCT --> GRAPH{"Graph Retrieval（当前启用）"}
    GRAPH -->|"是"| GR["实体链接、图谱上下文、邻居 Chunk 扩展、图谱融合评分"]
    GRAPH -->|"否"| RERANK
    GR --> RERANK["BGE / Cross-Encoder Reranker（当前启用）"]
    RERANK --> QUALITY["检索质量策略\n去重、动态 TopK、阈值、上下文压缩（总开关当前关闭）"]
    QUALITY --> BUDGET["ContextBudgetManager（启用）\nHistoryCompressor（启用）"]
    BUDGET --> EVIDENCE["Evidence Pack：来源、引用编号、冲突与缺口治理"]
    EVIDENCE --> WEBQ{"请求 web_search？"}
    WEBQ -->|"是"| WS["WebSearch；外部来源与知识库来源分开标记"]
    WEBQ -->|"否"| LLM
    WS --> LLM["ChatOllama\n系统提示限制事实仅来自上下文"]
    LLM --> OUT["QueryResponse 或 SSE：token、状态、思考、sources、done"]
```

补充：`POST /query/image` 走视觉模型流式回答；`POST /admin/qa-debug` 使用同一问答链输出可审查的证据链。默认检索仅使用 `approved` Chunk。

## 5. 文档入库、索引与 Chunk 治理

```mermaid
flowchart TD
    SRC["资料来源\n上传文件 / watch_directory / 已发布博客"] --> TRIGGER["/upload、/scan、启动首次扫描、30 分钟定时扫描、发布后扫描"]
    TRIGGER --> SCAN["DirectoryScanner\n递归发现、SHA-256 去重、扩展名分流、删除清理"]
    SCAN --> DEC["Decision Store\n处理、排队、排除、失败的可追溯决定"]
    SCAN --> PROFILE["文档分类 + Document Profile\n显式选择 > 重建继承 > 映射 > 默认"]
    PROFILE --> LOAD["FileLoader\nPDF/Office/文本/Markdown/Excel/HTML/配置/图片/视频"]
    LOAD --> PARSE["Canonical Adapters / Unstructured（配置启用）\n图片或视频帧可调用视觉模型"]
    PARSE --> CHUNK["结构保护分块\n章节、表格、代码块、技术手册合并；\n语义分块失败回退固定分块"]
    CHUNK --> META["统一元数据\nchunk_uid、来源、知识库、分类、Profile、章节、审核状态"]
    META --> STORE["VectorStore 写入 Chroma\nOllama Embedding + 内存 Embedding Cache"]
    STORE --> INDEX["file_index.json、分类映射、Profile 映射"]
    INDEX --> BM["BM25 重建 + Query Cache 失效"]
    CHROMA["Chroma Chunk"] --> ADMIN["ChunkAdminService\n列表、编辑分类/标题、单条或批量审核"]
    ADMIN --> CHROMA
    CHROMA --> STATS["ChunkStatsService / 一致性审计"]
    STATS --> UI["审核台、统计与 API"]
```

重建不直接手工清库：`POST /rebuild` 使用 `RebuildCoordinator`，包含互斥锁、暂存集合、扫描、审计、切换和清理；`/audit/consistency` 提供库一致性检查。切换 embedding 模型后必须执行重建。

## 10. 当前配置开关与边界

| 能力 | 当前 `config.ini` | 架构含义 |
|---|---:|---|
| 主检索 | `hybrid` + `rrf` | 同时使用 Chroma 和 BM25，再做 RRF 融合 |
| Reranker | 开启 | 粗召回后由 BGE 重排为最终上下文 |
| Query Planner | 开启 | 流程、排错、比较等问题可扩大召回与邻居范围 |
| 结构化检索 | 开启 | 表格、表头和章节命中加权 |
| Graph Retrieval | 开启 | 正式图谱用于检索增强，不替代 Chunk 事实来源 |
| 图谱 LLM 抽取 | 关闭 | 代码可用，但不会因当前配置主动调用 LLM 抽取 |
| 检索质量总开关 | 关闭 | 质量策略代码存在，当前不进入主链路 |
| Context Budget / 历史摘要 | 开启 | 对上下文和长对话实施预算控制 |
| Query Cache | 关闭 | 不复用问答检索结果；Embedding Cache 开启 |
| 外部博客同步与发布 | URL 为空 | 启动时及定时任务不会调用外部博客 API |
| 产品主干预览 | 独立 JSON | 与正式 SQLite 图谱、正式图谱 API 和证据链接严格隔离 |
