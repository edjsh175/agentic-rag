# 知识图谱前端展示模式升级 PRD (语义化分层布局)

## 1. 背景与目标
当前图谱采用“力导向图 (Force-Directed)”展示所有的实体和关系，在节点数量增多时，形成了难以阅读的“毛线球效应”，关系线交织混乱，重点不突出。
**核心目标**：针对业务数据的层级特性（总产品 -> 衍生产品 -> 功能层 -> 小内容），引入**语义化分层布局 (Hierarchical Layout)** 和相关减负交互，让图谱变得像架构图一样直观可读，彻底解决视觉混乱问题。同时，保留原有的力导向图视图，供用户自由探索。

## 2. 业务层级映射设计
根据业务数据的组织形式，我们将图谱数据重新分类为 4 个逻辑层级，布局算法将严格按照此层级自上而下（或自左向右）排布：

*   **L0 层：总产品核心 (Root)**
    *   实体类型判定：`entity_type === 'Product'` 且 `name` 包含 `StampGIS`（例如：`StampGIS三维产品`, `StampGIS Client` 等）。
    *   视觉特征：最大尺寸的节点，置于画布最顶端/最左侧，作为一切探索的起点。
*   **L1 层：衍生产品/子系统**
    *   实体类型判定：除 L0 外的其他 `Product` 节点（如 `StampWebRTC`, `StampServer`, `StampTools` 等）。
    *   视觉特征：中大尺寸，紧随总产品之后。
*   **L2 层：功能架构层**
    *   实体类型判定：`Module` (模块), `Service` (服务), `FunctionArea` (功能区), `Tool` (工具), `ManagementModule`, `RenderingSystem` 等。
    *   视觉特征：中等尺寸，按类别分组排列。
*   **L3 层：底层内容层 (叶子节点)**
    *   实体类型判定：`Feature` (特性), `ConfigItem` (配置项), `Field` (字段), `DataTable` (表), `Document` (文档), `Procedure` (流程), `Section` (章节) 等。
    *   视觉特征：小尺寸。为了防止刷屏，初始状态下这部分内容会被**默认折叠聚合**。

## 3. 核心交互特性 (UX)

### 3.1 DAG 渐进式展开 (Progressive Unfolding)
*   **初次加载**：页面不再一口气画出上千个节点。默认只展开 L0 到 L2 层（即看到产品和各大功能模块）。
*   **按需加载 (折叠/展开)**：L2 层的模块节点上会带有 `[+ N]` 的数字角标（如“查询模块 [+15]”）。用户双击该模块，才会向下平滑展开底层的配置项、字段和特性节点。

### 3.2 聚光灯模式 (Spotlight)
*   当鼠标悬浮在某个 L2 的“服务”节点上时，**自动高亮**从“总产品 -> 该服务 -> 该服务下的所有字段”的一条完整链路，图中其他无关的产品和模块自动变暗降噪。

### 3.3 布局一键切换 (Layout Toggle - 满足共存需求)
*   在界面的工具栏中新增一个**布局切换器 (Toggle)**，允许用户在 **“分层组织图 (Dagre Layout)”** 与现有的 **“力导向图 (Force Layout)”** 之间无缝切换。
*   默认进入时使用新的分层组织图。

## 4. 实施技术路径 (AntV G6 方案)
通过对 SQLite `relations` 表的数据探查，确认**当前数据存在“一对多”的父子节点交叉引用（即有向无环图 DAG，而非纯树状结构）**。因此，必须使用支持 DAG 的排版算法。

**改造步骤：**
1.  **引入依赖**：在 Vue 项目 (`web/package.json`) 中引入 `@antv/g6` 引擎。
2.  **数据转换适配层**：
    *   在原有的数据流后面增加一个 Transformer，将扁平的 Nodes/Edges 转换为 G6 支持的数据格式。
    *   识别 `stampgis` 相关的 Product 节点为布局的 `Root`。
3.  **渲染层重写**：
    *   在 `web/src/views/KnowledgeGraphView.vue` 中封装两套逻辑。保留原有的 `d3-force` 逻辑在后台。
    *   使用 G6 的 **`Dagre` 布局算法**实现 DAG 图分层流向。
    *   复用原有的颜色字典 (`utils/graphLabels.ts`) 进行 G6 的 Custom Node 绘制，确保业务标识完全一致。
4.  **交互绑定**：利用 G6 原生的 `collapse-expand` (折叠展开) 和 `activate-relations` (关系高亮) 插件，极低成本实现 UX 特性。

## 5. 开发阶段划分
*   **Phase 1**：集成 AntV G6，实现基础的 Dagre 布局，完成节点颜色的 1:1 还原。同时实现右上角的“布局切换开关”。
*   **Phase 2**：实现 L3 叶子节点的自动折叠/展开逻辑，以及边上的计数角标。
*   **Phase 3**：加入聚光灯（Hover 链路高亮）效果与动画调优。
