### 2. 补齐 `/stats` 的任务要求统计

```text
total_chunks

```

任务文档要求还包括：

```text
Chunk 数量统计
平均 Chunk Token 数
最大/最小 Chunk 长度
Chunk 命中率统计
```

**建议实现方式**：

优先新增独立接口，避免破坏前端已有 `Stats` 类型：

```text
GET /stats/chunks
```

建议返回字段：

```json
{
  "total_chunks": 607,
  "avg_chunk_chars": 0,
  "avg_chunk_tokens": 0,
  "max_chunk_chars": 0,
  "min_chunk_chars": 0,
  "by_file": {},
  "by_file_type": {},
  "by_review_status": {},
  "by_kb_name": {},
  "hit_rate": {
    "available": false,
    "reason": "仅在评估数据集存在并运行评估后可统计"
  }
}
```

**实现注意点**：

- Token 数可以先复用 `ContextBudget` 中的字符估算逻辑，后续再替换为真实 tokenizer。
- Chunk 命中率如果依赖评估集，不应伪造；没有评估结果时返回 `available=false` 和原因。
- 统计应从 Chroma collection 中读取 `documents` 和 `metadatas`。

**验收标准**：

1. 新增接口可正常返回 chunk 长度统计。
2. 能按 `file/source`、`file_type`、`review_status`、`kb_name` 分布统计。
3. 有对应单元测试。
4. 接口文档或交付文档已更新。

当前 `/review/status` 已经在更新 Chroma metadata 后执行：

```text

```

并已有测试：

```text
tests/test_review_status_bm25_sync.py
```

测试结果通过。

**剩余建议**：

`BM25Store.rebuild()` 当前没有用 `_build_lock` 包住整个重建流程，且 `_build_index()` 内部是逐步赋值 `_bm25 / _metadatas / _docs`。极端并发情况下，查询线程可能读到重建过程中的中间状态。

建议改成：

1. rebuild 时加锁。
2. 用局部变量完整构建 `bm25/docs/metadatas`。
3. 构建成功后一次性替换实例字段。
4. 构建失败时保留旧索引或明确清空并记录日志。

**验收标准**：

- 现有 `test_review_status_bm25_sync.py` 继续通过。
- 新增 rebuild 失败或并发场景的单测更好。

## 三、P1：建议尽快补

### 4. 统一同步和异步检索路径

**状态**：未完成。

当前 async 路径主要走：

```text
RetrievalStrategy.aretrieve(...)
```

但同步 `_retrieve()` 在以下场景仍保留老逻辑：

```text
未指定 kb_name 且 _route_query() 无法判断知识库
```

此时会直接调用：

```text
chroma.as_retriever(search_type="mmr", ...)
```

这会导致同步路径、异步路径、评估路径行为不一致。

**建议处理**：

把同步 `_retrieve()` 中的老 MMR 分支替换为：

```text
self._strategy.retrieve(... kb_name="文章附件" ...)
self._strategy.retrieve(... kb_name="已发布文章" ...)
self._merge_multi_kb_docs(...)
```

保持和 async 路径一致。

**验收标准**：

1. 同步 `_retrieve()` 不再直接创建 Chroma retriever。
2. 同步和异步多 KB 检索使用同一套策略参数。
3. `tests/test_rag_stage6.py` 和 `tests/test_retrieval_strategy.py` 继续通过。

### 5. Excel 支持补真实文件集成测试

**状态**：代码已支持基础解析，但真实 fixture 测试不足。

当前代码支持：

```text
.xlsx -> openpyxl
.xls  -> xlrd
```

现有测试主要覆盖：

```text
_rows_to_markdown
扩展名是否在 TEXT_EXTS
detect_category 是否返回 TEXT
Excel Markdown 表格切块
```

仍建议补真实 `.xlsx / .xls` fixture 测试，覆盖：

```text
多 sheet
空表
合并单元格
公式列
日期/数字格式
表头为空
超长表格切块
```

**实现注意点**：

1. `.xlsx` 使用 `data_only=True` 只能读缓存公式结果，不会现场计算公式。
2. 合并单元格默认只有左上角有值，当前没有补齐合并区域值。
3. `_rows_to_markdown()` 当前以第一行列数为列数，第一行为空或后续列更多时可能截断。
4. `.xls` 日期可能是序列号，当前没有看到 `xlrd.xldate_as_datetime` 格式恢复逻辑。

**验收标准**：

- 新增真实文件级测试。
- `.xlsx` 至少覆盖多 sheet、空 sheet、公式缓存、日期/数字、合并单元格。
- `.xls` 至少覆盖基础 sheet 解析和日期/数字格式。
- 超长表格能被按完整行切块并重复表头。
