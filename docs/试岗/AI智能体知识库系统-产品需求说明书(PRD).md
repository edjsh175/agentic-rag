## 一、项目概述

### 1.1 项目背景

当前系统基于Open WebUI + Ollama + Qwen3搭建，已实现基础的RAG（检索增强生成）问答能力。但存在以下核心问题：

| 问题编号 | 问题描述 | 影响 |
|---------|---------|------|
| P1 | 多份手册中相同名词（如“飞行物体”）含义不同，AI回答混乱 | 用户无法获得准确答案 |
| P2 | 知识块按字数硬切分，丢失章节结构语义 | 检索命中率低 |
| P3 | 文档无分类、无关联关系，系统无法理解资料间的逻辑 | 复杂问题无法回答 |
| P4 | 系统不会反问，用户意图不明时只能瞎猜 | 答非所问 |
| P5 | 业务人员无法干预和修正知识数据 | 错误持续存在 |
| P6 | 无空间数据对接能力 | 未来地图展示无法扩展 |

### 1.2 项目目标

构建一个**面向GIS复杂资料的AI智能体知识库系统**，核心能力：

| 目标编号 | 目标描述 | 可量化指标 |
|---------|---------|-----------|
| G1 | 回答准确率提升至85%以上 | 人工抽检100个问题的正确率 |
| G2 | 支持知识块的人工审核与修正 | 业务人员可独立操作，无需开发介入 |
| G3 | 建立文档分类与知识图谱关系 | 复杂问题能跨文档关联回答 |
| G4 | 系统具备主动反问能力 | 歧义问题时弹出选项卡片 |
| G5 | 预留地图展示对接接口 | 空间数据字段已存在，但地图渲染暂不实现 |

### 1.3 系统角色定义

| 角色 | 职责 | 使用频率 |
|------|------|----------|
| **普通用户** | 提问、查看答案、查看溯源路径、反馈答案质量 | 高频 |
| **业务审核员** | 审核知识块、编辑/合并/拆分知识块、建立实体关联 | 中频 |
| **系统管理员** | 管理文档分类、管理用户权限、查看质量仪表盘、版本管理 | 低频 |
| **后台系统** | 自动执行清洗、分块、实体抽取、关联推荐 | 持续运行 |

### 2.2 数据流转总览

| 阶段 | 触发动作 | 数据流转 |
|------|---------|----------|
| **入库** | 业务员上传文档 | 文档 → 清洗脚本 → 结构化分块 → 实体自动抽取 → 存入向量库+关系库 |
| **审核** | 业务员打开审核工作台 | 读取未审核块列表 → 人工编辑/合并/拆分 → 确认关联 → 更新状态为“已审核” |
| **检索** | 用户在对话框提问 | 问题 → Agent规划 → 调用工具（检索/反问/图谱扩展）→ 收集上下文 → 生成答案 |
| **反馈** | 用户点击“答案有用/无用” | 记录反馈 → 定时任务统计 → 低分知识块标记待复核 |


## 三、数据层详细设计

### 3.1 向量数据库（已有，需调整Chunk结构）

**当前问题**：Chunk按固定字数硬切，丢失章节结构。

**改造要求**：每个Chunk入库时，必须包含以下字段：

| 字段名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| `chunk_id` | String | 是 | 全局唯一标识，格式 `chunk-{timestamp}-{seq}` | `chunk-20260629-001` |
| `text` | Text | 是 | 知识块的完整文本内容 | `## 飞行物体配置\n添加一个不带骨骼动画的...` |
| `embedding` | Vector | 是 | 文本的向量表示 | `[0.123, -0.456, ...]` |
| `metadata.source_file` | String | 是 | 来源文件名 | `StampServer_运维管理手册.doc` |
| `metadata.doc_category` | String | 是 | 文档分类（必须匹配分类表） | `运维管理` |
| `metadata.section_title` | String | 是 | 章节全称 | `5.3.1. 飞行物体配置` |
| `metadata.section_level` | Integer | 是 | 标题层级 | `3` |
| `metadata.page_num` | Integer | 否 | 页码 | `42` |
| `metadata.chunk_size` | Integer | 是 | 文本长度（字符数） | `342` |
| `metadata.is_active` | Boolean | 是 | 是否可用（用于数据淘汰） | `true` |
| `metadata.indexed_at` | DateTime | 是 | 入库时间 | `2026-06-29 10:00:00` |
| `metadata.review_status` | Enum | 是 | `pending` / `approved` / `rejected` | `approved` |
| `metadata.reviewed_by` | String | 否 | 审核人 | `zhangsan` |
| `metadata.reviewed_at` | DateTime | 否 | 审核时间 | `2026-06-29 14:00:00` |

### 3.3 数据淘汰与版本管理机制

| 机制 | 说明 | 操作方式 |
|------|------|----------|
| **软删除** | 知识块不物理删除，仅将 `is_active` 设为 `false` | 管理员在后台操作 |
| **版本标记** | 每个知识块记录 `source_file` 和 `indexed_at`，同一文件名不同版本共存 | 系统自动处理 |
| **版本切换** | 新版本入库后，旧版本自动标记 `is_active=false` | 管理员可手动切换 |
| **定期清理** | 被标记为 `is_active=false` 超过180天的块，可物理删除 | 系统定时任务 |


## 四、智能体核心功能设计

### 4.1 智能体工作流程

**当用户提问时，智能体按以下流程执行**：

| 步骤 | 阶段 | 动作 | 决策点 |
|------|------|------|--------|
| 1 | **感知** | 接收用户问题 + 对话历史 + 用户ID | — |
| 2 | **意图识别** | 识别问题类型：`配置类` / `概念类` / `报错类` / `操作步骤类` / `空间查询类` | — |
| 3 | **快速预检** | 执行一次轻量向量检索（Top 3），获取初步匹配得分 | — |
| 4 | **确定性判断** | 评估最高得分是否 ≥ 阈值（默认0.75） | **是** → 跳到步骤7；**否** → 继续 |
| 5 | **冲突/歧义检测** | 检查是否命中 `disambiguation_rules` 表 | **是** → 调用反问工具，等待用户选择；**否** → 继续 |
| 6 | **信息缺口检测** | 检查问题是否缺少必要上下文（如操作系统、版本号） | **是** → 调用反问工具；**否** → 继续 |
| 7 | **正式检索** | 执行完整检索：向量检索（带元数据过滤）+ BM25关键词检索 | — |
| 8 | **图谱扩展** | 用命中的 `chunk_id` 查询 `entity_chunk_links`，扩展1跳关联知识块 | — |
| 9 | **重排序** | 将向量检索结果 + 图谱扩展结果合并，按综合得分排序，取Top 5 | — |
| 10 | **生成答案** | 将Top 5知识块作为上下文，送入LLM生成最终答案 | — |
| 11 | **溯源输出** | 在答案旁展示“知识路径图”，列出本次使用的所有知识块和关联关系 | — |
| 12 | **记忆存储** | 记录本次交互（用户ID、问题、选中的选项等）存入 `user_preferences` | — |

### 4.2 反问工具的行为规范

当智能体决定调用反问工具时，必须按以下规范执行：

| 规范项 | 要求 |
|--------|------|
| **反问触发条件** | ① 预检得分＜阈值（0.75）；② 命中歧义规则表；③ 明显缺少必要上下文 |
| **反问格式** | 必须提供可点击的选项按钮，而非开放式提问 |
| **选项数量** | 2~4个选项，超过4个则先展示前4个，再提供“其他”选项 |
| **选项内容** | 每个选项必须包含：显示文本 + 对应的过滤条件（JSON格式） |
| **超时处理** | 用户30秒未选择，智能体自动选择“综合回答”模式，合并所有选项的结果 |
| **记忆应用** | 如果当前用户在 `user_preferences` 中有历史选择记录，智能体可跳过反问，直接应用历史偏好 |

## 六、业务流程详细说明

### 6.1 文档入库流程

```
【开始】
   ↓
① 业务员在【文档管理页面】上传PDF/Word
   ↓
② 系统自动执行（后台）：
   a. 格式标准化（去页眉页脚、去版权声明、统一标点）
   b. 结构化分块（按章节标题切分，每个最末级标题下内容为一个块）
   c. 为每个块生成元数据（文件名、分类、章节标题、页码）
   d. 去重检测（SimHash算法，相似度>0.85的块丢弃）
   e. 向量化（通过Embedding模型生成向量）
   f. 存入向量数据库（ChromaDB/Qdrant），状态设为 `review_status=pending`
   g. 异步执行：实体自动抽取（调用LLM提取实体名称，去重后存入 `entities` 表，置信度>0.7自动关联）
   ↓
③ 业务员收到通知：“文档【xxx.doc】已处理完成，共生成N个知识块，待审核”
   ↓
④ 业务员在【知识块审核工作台】审核每个知识块：
   - 通过：点击“通过”，状态变为 `approved`
   - 编辑：修改文本内容
   - 合并：合并到上一个块
   - 拆分：在光标位置切开
   - 驳回：说明原因，状态变为 `rejected`
   - 关联实体：将该块关联到已有实体或新建实体
   ↓
⑤ 全部审核完成后，该文档的知识块正式生效（可被检索）
   ↓
【结束】
```

### 6.2 用户问答流程（含反问场景）

```
【开始】
   ↓
① 用户在【智能对话页面】输入问题
   ↓
② 智能体执行：
   a. 意图识别（配置类/概念类/报错类/操作步骤类/空间查询类）
   b. 快速预检（向量检索Top 3，获取得分）
   c. 判断最高得分是否 ≥ 0.75
   ↓
③ 【分支1：得分≥0.75，无歧义】
   → 直接执行正式检索 → 生成答案 → 展示溯源路径
   ↓
④ 【分支2：得分<0.75】
   a. 检查是否命中 `disambiguation_rules` 表
   b. 如果命中 → 调用反问工具，前端展示选项卡片
   c. 用户点击选项 → 智能体获取过滤条件
   d. 带着过滤条件执行正式检索 → 生成答案
   ↓
⑤ 【分支3：得分中等且有用户历史偏好】
   → 直接应用历史偏好过滤 → 执行正式检索 → 生成答案
   ↓
⑥ 用户反馈：[有用] / [无用]
   ↓
⑦ 记录反馈到系统，定时统计
   ↓
【结束】
```

### 6.3 图谱维护流程

```
【开始】
   ↓
① 方式一：系统自动抽取（文档入库时异步执行）
   - 用LLM提取文档中的命名实体
   - 与 `entities` 表去重：存在则增加关联计数，不存在则新建（标记 `created_by=system_auto`）
   - 自动推荐关系：根据共现频率生成候选关系（标记 `confidence_source=ai_auto`）
   ↓
② 方式二：业务员在【知识块审核工作台】手动关联
   - 在审核知识块时，从下拉框选择已有实体，或输入名称新建
   - 点击“关联”，写入 `entity_chunk_links` 表
   ↓
③ 方式三：业务员在【图谱画布】上操作
   - 双击画布创建新实体节点
   - 拖拽连线建立实体间关系
   - 从侧栏拖拽知识块到节点，建立实体-块关联
   - 合并节点（拖A到B）
   - 删除/隐藏节点
   ↓
④ 所有人为操作记录 `created_by=用户名`，同时保留AI的建议（不改动AI数据，只是覆盖）
   ↓
⑤ 系统定时统计：孤立实体数、孤立块数、关联覆盖率 → 展示在仪表盘
   ↓
【结束】
```


## 七、与现有Open WebUI的集成方案

### 7.1 集成策略

| 现有组件 | 集成方式 | 说明 |
|---------|---------|------|
| Open WebUI 前端 | **保留** | 保留对话界面，但新增独立的“审核工作台”和“图谱画布”页面（可嵌入或独立部署） |
| Open WebUI 对话API | **保留** | 用户提问仍走原有接口 |
| Open WebUI 知识库API | **替换数据源** | 知识库数据改为读取重构后的Chunk数据（通过API查询新数据库） |
| Ollama + Qwen3 | **保留** | 继续作为LLM推理后端 |
| Open WebUI Pipelines | **扩展** | 在Pipelines中实现智能体的规划、工具调用、反问逻辑 |
| 现有2469个Chunks | **迁移** | 迁移到新数据结构，旧数据标记 `is_active=false`，逐步替换 |

### 7.2 新增独立服务

| 服务 | 职责 | 部署方式 |
|------|------|----------|
| **智能体调度服务** | 实现Agent Core（意图识别、规划、工具调用、反思） | 独立FastAPI服务，Open WebUI通过Pipelines调用 |
| **知识管理服务** | 文档上传、清洗、分块、入库、审核、版本管理 | 独立FastAPI服务 |
| **图谱管理服务** | 实体/关系的增删改查、画布数据读写 | 独立FastAPI服务 |
| **前端页面（审核台+画布）** | 独立于Open WebUI的新页面 | 可独立部署，也可嵌入Open WebUI的iframe |


## 八、非功能性需求

### 8.1 性能要求

| 指标 | 要求 |
|------|------|
| 普通问答响应时间 | ≤ 5秒（含检索+生成） |
| 含反问的问答响应时间 | 反问卡片展示 ≤ 2秒；用户选择后答案生成 ≤ 5秒 |
| 知识块审核页面加载 | ≤ 3秒 |
| 图谱画布渲染 | 支持至少500个节点 + 1000条边，帧率 ≥ 30fps |
| 文档入库处理 | 100页PDF ≤ 3分钟 |

### 8.2 可用性要求

| 指标 | 要求 |
|------|------|
| 系统可用性 | ≥ 99.5%（每月停机 ≤ 3.6小时） |
| 数据备份 | 每日自动备份向量库 + 关系库 |
| 模型容错 | 单个模型异常时，系统自动切换备选模型 |

### 8.3 安全要求

| 要求 | 说明 |
|------|------|
| 用户认证 | 继承Open WebUI现有认证体系 |
| 操作日志 | 所有知识块编辑、图谱修改操作记录操作人、时间、变更内容 |
| 数据隔离 | 不同用户的知识库数据隔离（后续考虑） |
| 敏感数据过滤 | 自动检测并脱敏上传文档中的敏感信息（如IP、密码） |

### 8.4 可扩展性要求

| 扩展方向 | 预留方式 |
|---------|----------|
| 地图展示 | 向量库元数据已预留 `geo_wkt`、`geo_bbox`、`place_name` 字段 |
| 多用户租户 | 未来可增加 `tenant_id` 字段隔离数据 |
| 多模态（图片识别） | 当前已有 Qwen3-VL，可后续集成到智能体工具集 |
| 外部数据源 | 已预留“开源生态”分类，可接入GitHub等外部源 |
