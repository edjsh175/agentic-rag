# 新资料入库清单

## 1. 入库前盘点

- 按产品、模块、版本、部署环境、文档类型分组。
- 同一主题存在多版文档时，只保留当前生效版本；历史版单独隔离。
- 文件命名建议包含产品、版本、环境，例如 `StampServer_V5_Rocky9_部署手册.docx`。

## 2. 入库前清洗

- `.doc` 优先转成 `.docx` 后再入库。
- 扫描版 PDF 先确认可复制文本；抽取质量差时先 OCR。
- 去掉目录页、无效附录、纯链接页、模板页和明显噪声内容。
- 涉及客户名、测试账号、内网地址、项目专属配置时先脱敏。

## 3. 推荐入库方式

- 需要 `doc_category` 时，优先走 `/upload`。
- 大批量试入库时，先选 20 到 30 份代表性资料，不要直接全量导入。
- 当前阶段默认统一进入 `文章附件` 知识库。

## 4. 入库后检查

- 抽样检查 chunk 内容，确认没有 `HYPERLINK`、`PAGEREF`、纯目录块和乱码块。
- 检查 metadata 至少包含 `chunk_id`、`source`、`kb_name`、`review_status`。
- 新 chunk 默认是 `pending`，需要通过 `/review/status` 批量改成 `approved` 后才会参与默认检索。

## 5. 评测建议

- 先跑标准评测集，再跑难例评测集。
- 难例至少覆盖标准问法、口语化、错别字/简称、版本歧义四类。
- 如果指标下降，先区分是语料问题还是检索策略问题，不要直接改默认策略掩盖问题。
