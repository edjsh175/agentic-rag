## 一、项目概述

### 1.1 背景与问题

本地化抽取已能稳定出 JSON，规则也已禁止「正文扫标题造 Procedure」。但审图仍出现「同名实体」：

以《StampTools用户手册》**DOMBuilder** 章为锚点（2026-08-14 对照正式库 + 手册原文）：

| 手册结构 | 图上实际 | 问题 |
|----------|----------|------|
| H3 **工程设置**（分区）→ 正文「新建工程 / 继续工程」 | FunctionArea `DOMBuilder::工程设置` **且** 有正确 Procedure「新建工程 / 继续工程」 | 分区本身正确；流程叶正确 |
| H3 **数据设置**（分区）→ 正文「数据管理 / 空间参考 / …」 | FunctionArea `DOMBuilder::数据设置` **又** Procedure「数据设置」，再挂 Step | **同一章两种类型** |
| H3 **编译级别** | DOMBuilder 邻域缺失 | 漏抽（角色未进导航） |
| H3 **数据编译**（正文：「影像数据的编译发布包括编译和发布两个阶段」） | 三个 Procedure：数据编译过程 / 数据编译发布 / 影像数据的编译发布 | **一章多名** |
| 各子工具均有「工程设置 / 数据设置」 | `DEMBuilder::数据设置` 等与 DOMBuilder 并存；画布 `getShortLabel` 去掉 `工具::` | **合法不同实体，显示撞名** |

这不是快照幂等失效（那是批次复用）。库的唯一约束是 **整名** 唯一：`DOMBuilder::数据设置` 与裸名 `数据设置` 可以同时存在。前端再裁短名，审图者看到两个「数据设置」（功能 + 流程），以及发虚的其它工具同名功能区。

### 1.2 根因（第一性）

产品图缺少一条硬契约：

> **`section_path` 上的每一段，在产品图里最多一种角色。**

现状是双轨各说各话：

1. **规则**把「…设置 / …规范」建成 FunctionArea（`{Owner}::{leaf}`，`display_name=leaf`）。  
2. **LLM**只拒绝「祖先章节当 Procedure」，**叶子已是功能区时不拦**，再用短名建 Procedure。  
3. **画布**把限定名裁成短名，跨工具功能区看起来像克隆。

universal 示例已写「`{Tool} > 工程设置` 只抽新建工程 / 继续工程，不要把章节本身抽成流程」——这是 few-shot，不是门禁。LLM 未遵守时仍可入库。

「数据编译过程」等近义名 **不是** 手册有三章，而是 Procedure 名称未强制等于路径叶子或正文独立标题。用模糊近义合并会掩盖这个问题，并误伤真不同流程。

### 1.3 第一性原理（设计公理）

| # | 公理 | 含义 |
|---|------|------|
| A1 | **最小关系主干** | 图只保留导航骨架；GUI 标签、参数说明留在 chunk |
| A2 | **路径段类型独占** | 同一路径段不得同时是 FunctionArea 与 Procedure/Step |
| A3 | **章节 ≠ 操作** | 功能分区（设置/规范/级别）是 FunctionArea；可执行操作才是 Procedure |
| A4 | **流程名必须可核对** | Procedure 名称 = 路径叶子（且该叶子不是 FA）**或** 正文独立操作标题（与 ChapterLeaf「新建工程」同构） |
| A5 | **限定名是身份** | FunctionArea 真名保持 `{Owner}::{leaf}`；多工具同名章节是文档体例，不是重复实体 |
| A6 | **显示不得撒谎** | 画布不得把不同 Owner 的功能区显示成同一个短名而不给所属工具 |
| A7 | **事实通道不变** | 回答仍依据 chunk；本 PRD 不改 GraphRAG 生产关图政策 |

违反 A2/A4/A5 的方案（近义聚类当主方案、FA 与 Procedure 并类、取消限定名、只改 UI）不在本 PRD 接受范围内。

### 1.4 目标

1. **抽取契约**：路径段分类结果对规则与 LLM **同一份、互斥**。  
2. **流程准入**：Procedure/Step 必须是操作标题，不能是已定性为 FunctionArea 的短名。  
3. **画布诚实**：FunctionArea 始终能看出所属 Tool/Service。  
4. **锚点验收**：DOMBuilder 邻域按手册可审阅通过；不默认 apply。

### 1.5 非目标

| 非目标 | 说明 |
|--------|------|
| 模糊近义合并 Procedure | **明确不做**；用 A4 标题约束代替 |
| FunctionArea 与 Procedure 合成一类 | 章节与操作语义不同 |
| 取消 `Owner::leaf` 限定名 | 会把各工具「数据设置」合成一团，更错 |
| 只改展示、不改抽取 | 检索仍会吃到错误 Procedure |
| 全库自动 apply / 生产开图 | 仍走既有门禁与第 4 轮结论 |
| 主问答 `num_ctx`、新品类专包 | 不在本 PRD |
| 把 Section 树画进产品图以「消除短名」 | 产品图 / 文档图分离不变 |


## 二、现状基线（2026-08-14）

### 2.1 已有、可复用

| 能力 | 位置 | 缺口 |
|------|------|------|
| FunctionArea 由路径段规则创建；LLM 禁止新建 FA | `SectionPathExtractor` / `llm_extractor` `function_area_readonly` | 未禁止 LLM 用 **同一短名** 建 Procedure |
| 祖先路径段不得作 Procedure | `ancestor_section_as_procedure` | **叶子等于当前 FA 短名时不拦截** |
| ChapterLeaf：正文独立行「新建工程 / 继续工程」 | `chapter_leaf_extractor.py` | LLM 路径无同等硬约束 |
| FA 真名 `{Owner}::{part}` + `display_name` | `SectionPathExtractor` | 画布 `getShortLabel` 遇 `::` 只留后段 |
| 实体表 `UNIQUE(name)` | `graph_schema.py` | 整名不冲突 ≠ 短名不重复显示 |

### 2.2 手册锚点（DOMBuilder）

摘自 `StampTools用户手册.docx`：

```
H2 DOMBuilder
  H3 工程设置     → FunctionArea；正文「新建工程」「继续工程」→ Procedure
  H3 数据设置     → FunctionArea；其下界面块不进产品图
  H3 编译级别     → FunctionArea（或仅 Section；不得变 Procedure）
  H3 数据编译     → 操作叶 Procedure（名称对齐叶子「数据编译」或正文主句标题，只留一个）
```

TerrainBuilder 下 DEMBuilder / TINBuilder / TINIncise 重复同一套 H3 标题：各工具各有一份 FA，**库内不合并，画布必须能区分**。


## 三、功能需求

### FR-T1 路径段类型独占（抽取契约，根因）

对每个 chunk 的 `section_path` 分段，先分类再抽取。分类器输出对 **规则与 LLM 共用**：

| 判定 | 产品图角色 | 示例 |
|------|------------|------|
| 能力分区 | **仅** FunctionArea `{Owner}::{leaf}` | 工程设置、数据设置、数据规范、编译级别 |
| 操作叶 | **仅** Procedure（真名为叶子短名，不与 FA 抢同一短名） | 新建工程、继续工程、数据编译、…安装/配置/部署 |
| 其它 | 不进产品图（文档 Section 可照旧） | 概述、简介、界面小节名 |

约束：

- 某段一旦为 FunctionArea，**禁止**再为该短名创建 Procedure / Step（不论 LLM 还是规则兜底）。  
- 某段一旦为操作叶 Procedure，**禁止**再为该段创建 FunctionArea。  
- 分类实现应集中一处（扩展现有 `FunctionAreaClassifier` 或并列 `PathSegmentRole`），禁止规则一套、LLM 一套。  
- 「编译级别」这类 `…级别` 与「…设置/规范」同属能力分区，不得当 Procedure。

### FR-T2 Procedure / Step 名称必须是操作标题

LLM（及规则兜底）产出的 Procedure 名称仅当：

1. 等于当前路径 **叶子**，且该叶子角色是操作叶（不是 FA）；或  
2. 正文中 **独立成行** 的操作标题（与 `ChapterLeafExtractor._has_standalone_title` 同构），且该标题不是任何已存在 FA 的 `display_name`。

Step 默认不进入产品图，除非后续另立 PRD。本轮：**拒绝**把「数据管理 / 空间参考 / 参数设置 / 按范围发布」等 FA 内界面块抽成 Step。

不满足则 diagnostic 拒绝，不进 pending 主干。  
**禁止**用字符串相似度合并「数据编译过程 / 影像数据的编译发布」。

### FR-T3 universal 示例与门禁一致

`pattern_universal_v1` 已有「工程设置下只挂新建/继续工程」。本轮补一条 **BAD**：

- 不要把 `{Tool} > 数据设置` 的叶子抽成 Procedure；该叶子只应作为已有 FunctionArea。  
- 不要把 FA 内 GUI 小节抽成 Step/ConfigItem。

示例是教学；**FR-T1/T2 门禁才是法律**。不得只改 prompt 不改代码拦截。

### FR-D1 FunctionArea 画布必须显示所属工具

`getShortLabel` / 图谱节点标题：

- FunctionArea：不得只显示 `数据设置`。至少一种：`{Owner} · {leaf}` 或保留 `Owner::leaf` 的 Owner 可见。  
- 其它类型维持现有短名策略（文档 Section 仍可取路径叶子）。  
- 侧栏详情仍展示完整 `name`。  
- 检索/库存储 **不改** 限定名格式。

验收：同一画布中 `DOMBuilder::数据设置` 与 `DEMBuilder::数据设置` 肉眼可区分。

### FR-C1 已入库脏数据另案、不阻塞门禁合入

门禁合入后，DOMBuilder 邻域（及同类 Tools 章）的历史脏节点：

- 裸名 Procedure「数据设置」（若对应 FA 已存在）  
- 同一叶子衍生的多个编译 Procedure  
- 挂在错误 Procedure 下的 Step  

处理方式：定向重抽 staging → 人工审 → apply（confirm 三件套）。  
**禁止**未合门禁就全库重 apply。本 PRD 不把「正式库已干净」当作 Phase 1 出口。

## 五、分阶段计划

### Phase 1 — 类型独占 + 操作标题门禁（优先）

1. 集中路径段角色分类（FA / 操作叶 / 其它）。  
2. LLM 校验：扩展现有 `ancestor_section_as_procedure`，覆盖 **当前叶子及 owner 下已有 FA display_name**。  
3. 拒绝 FA 内 GUI 小节作为 Step。  
4. 单测 S1–S3、S4。  
5. 必要时同步 universal BAD 例（FR-T3）。

**出口**：新抽取不再产生「数据设置」双类型；不 apply。

### Phase 2 — 功能区短名展示

1. 改 `getShortLabel` 或图谱节点专用标签：FunctionArea 带 Owner。  
2. 前端单测 S6。  

**出口**：审图不再把跨工具 FA 误认为克隆。可与 Phase 1 同一 PR。

### Phase 3 — 锚点复测与可选清理

1. `config-local` 对 DOMBuilder（建议含 DEMBuilder 对照）定向抽，勾选 S5。  
2. 若需更新正式库：review → apply + confirm；范围仅脏邻域，禁止顺手全库。  

**出口**：锚点审阅通过。≠ 生产开图。≠ 全库重建。


## 六、验收与审阅清单（人工）
