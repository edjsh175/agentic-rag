# RAG 知识库系统功能增强需求

## 一、项目目标

在现有 RAG 知识库系统基础上，进一步提升系统的文件兼容能力、文档解析能力、检索准确率以及大模型回答质量，打造一个稳定、高效、可扩展的企业级知识库问答平台。

---

# 二、功能扩展

## 1. 扩展文件格式支持

### 目标

提升系统对各类业务文档的兼容能力，满足企业多场景知识沉淀需求。

### 支持文件类型

* PDF
* Word（.doc/.docx）
* Excel（.xls/.xlsx）
* Markdown（.md）
* Text（.txt）

# 三、文档解析能力增强

## 1. 文档切块（Chunk）优化

### 目标

提高知识召回质量，减少上下文丢失和语义断裂。

### 优化内容

#### 支持多种切块策略

* 固定长度切块
* 滑动窗口切块
* 按标题切块
* 语义切块
* 混合切块策略

#### 切块参数可配置

* chunk_size
* chunk_overlap
* separator

#### 增强能力

* 自动识别标题层级
* 表格完整保留
* 代码块完整保留
* 上下文关联切块
* 大文档自动切块优化

#### 输出统计

* Chunk 数量统计
* 平均 Chunk Token 数
* 最大/最小 Chunk 长度
* Chunk 命中率统计

# 五、Prompt 工程优化

## 1. 系统 Prompt 规范

### 回答原则

#### 禁止幻觉

* 如果知识库中没有明确答案，必须明确告知用户：
  “当前知识库中未查询到相关内容。”

#### 禁止编造

* 不允许凭空生成不存在的信息。
* 不允许推测数据库或文档中未出现的内容。

#### 引用溯源

* 回答必须附带引用来源：

  * 文件名称
  * 页码
  * 文档片段

#### 回答优先级

1. 知识库内容
2. 历史上下文
3. 大模型通用知识（可配置关闭）

#### 回答规范

* 回答简洁明确
* 保留关键专业术语
* 支持 Markdown 输出
* 支持代码高亮
* 支持表格输出

---

## 2. Token 管理优化

### 增加 Token 预算控制

支持配置：

* 最大上下文长度
* 回答预留 Token
* 历史消息压缩
* 自动裁剪 Context

避免出现：

* Context Length Exceeded
* Requested Tokens Exceed Context Window
