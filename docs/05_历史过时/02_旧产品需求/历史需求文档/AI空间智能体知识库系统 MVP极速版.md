## 一、核心策略调整

### 1.1 与原PRD的核心差异

| **MVP极速版
|------|---------------------|--------------------------|
| 数据库表 | 6张表 | **3张表**（实体表、关系表、关联表，合并文档分类到元数据） |
| 前端页面 | 8个页面 | **3个页面**（对话页+审核台+图谱画布，全部嵌入Open WebUI） |
| 智能体能力 | 完整ReAct架构 | **Prompt驱动的轻量Agent**（反问通过System Prompt实现，不开发独立调度服务） |
| 图谱能力 | 完整增删改+合并+版本快照 | **仅查看+拖拽连线+添加节点**，不做合并、不做版本快照 |
| 质量控制 | 仪表盘+自动检测 | **仅审核状态标记**，无仪表盘 |
| 空间预留 | 完整geo字段 | **元数据中保留geo_wkt字段，但不开发任何空间功能** |

### 1.2 MVP必须完成的核心目标

| 目标编号 | 目标描述 | 验收标准 |
|---------|---------|----------|
| M1 | 新文档入库时按章节结构切分，生成带完整元数据的知识块 | 上传一份Word手册，生成的知识块按标题组织，元数据包含文件名、分类、章节名 |
| M2 | 知识块可人工审核（通过/驳回/编辑标题和分类） | 审核工作台中可看到待审核列表，点击通过后该块可被检索 |
| M3 | 图谱画布可查看实体关系，可拖拽新增节点和连线 | 画布上能看到AI自动抽取的实体，用户可拖拽连线建立关系 |
| M4 | 检索时支持按产品/业务域过滤 | 用户在对话界面下拉选择“StampServer”或“博客”等业务域，结果只返回该业务域下的块 |
| M5 | 智能体具备基础反问能力 | 问“飞行物体”时，AI能识别歧义并通过Prompt方式反问用户选择 |
| M6 | 与现有Open WebUI无缝集成 | 对话仍走Open WebUI，新功能以独立页面嵌入或新开标签页方式访问 |


## 二、简化后的数据层设计

### 2.1 向量数据库（元数据调整）

**只增加3个关键字段**，其余保持原有结构：

| 字段名 | 必填 | 说明 |
|--------|------|------|
| `metadata.doc_category` | 是 | 产品/业务域分类，可选值：`StampServer`/`StampTools`/`StampWebRTC`/`实景三维`/`耕地保护`/`矢量瓦片`/`基础环境`/`博客`/`其他` |
| `metadata.section_title` | 是 | 章节全称（用于溯源展示） |
| `metadata.review_status` | 是 | `pending`/`approved`/`rejected`，新入库默认为`pending` |
| `metadata.geo_wkt` | **预留** | 字段存在，填NULL，暂不开发 |

### 2.2 关系数据库（仅3张表）

#### 表1：实体表 `entities`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| name | VARCHAR(200) | 实体名称（唯一） |
| entity_type | VARCHAR(20) | `功能模块` / `数据文件` / `配置项` / `API接口` |
| doc_category | VARCHAR(50) | 所属分类（冗余字段，便于快速过滤） |
| created_by | VARCHAR(50) | `system` 或 `admin` |
| created_at | TIMESTAMP | 创建时间 |

#### 表2：关系边表 `relations`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| source_id | UUID | 源实体ID |
| target_id | UUID | 目标实体ID |
| relation_type | VARCHAR(20) | `依赖` / `被使用于` / `包含` / `平级` |
| created_by | VARCHAR(50) | `system` 或 `admin` |

#### 表3：实体-知识块关联表 `entity_chunk_links`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| entity_id | UUID | 实体ID |
| chunk_id | VARCHAR(100) | 对应向量库中的chunk_id |
| link_type | VARCHAR(20) | `主要描述` / `间接提及` |

### 2.3 数据淘汰机制（MVP简化）

- 不开发版本管理界面
- 删除文档时，标记对应chunk的 `review_status = 'rejected'`，检索时过滤
- 后台定时任务每周清理 `review_status='rejected'` 且超过30天的chunk（可选）


## 三、智能体实现策略（简化）

### 3.1 不开发独立调度服务

**改用Open WebUI的System Prompt + Function Calling机制**：

```text
【系统提示词（嵌入到Open WebUI的通用助手设置中）】

你是一个专业的GIS系统技术文档助手。在回答用户问题时，请严格遵循以下规则：

1. 如果用户的问题指向不明确（如“飞行物体”在运维手册和开发手册中都有），你必须先反问用户，提供选项让用户选择，格式如下：
   “您的问题【XXX】在资料中有多个含义，请选择您要查询的方向：
   A. 【选项1描述】
   B. 【选项2描述】
   请回复 A 或 B。”

2. 用户回复选择后，你才基于对应的知识库内容进行回答。

3. 回答时必须引用来源，格式：【文档名 - 章节名】。

4. 如果检索到的知识块得分较低（即与问题不相关），请直接告知用户“未找到相关信息，建议换个问法”。
```

**反问逻辑的维护**：业务人员直接在对话中告诉AI“当问到XX时，给出A/B选项”，由AI自行学习。暂不开发歧义规则管理界面。

### 3.2 分类过滤的实现

- 前端对话页面增加一个下拉菜单：[全部] / [StampServer] / [StampTools] / [StampWebRTC] / [实景三维] / [耕地保护] / [矢量瓦片] / [基础环境] / [博客] / [其他]
- 用户选择后，在检索请求的metadata中附加 `doc_category` 过滤条件
- 使用Open WebUI的 `/api/v1/retrieval` 接口时，在请求体中传递 `metadata_filter` 参数


## 四、前端页面清单（3个页面）

### 页面1：智能对话页面（保留Open WebUI，新增分类下拉）

| 改动项 | 说明 |
|--------|------|
| 分类下拉 | 在输入框上方增加下拉菜单，可选全部/StampServer/StampTools/StampWebRTC/实景三维/耕地保护/矢量瓦片/基础环境/博客/其他 |
| 溯源展示 | 答案底部用引用样式展示【文档名 - 章节名】来源列表（Open WebUI原生功能即可实现） |
| 反问交互 | AI返回反问文本时，用户直接在输入框中回复 A/B/C（纯文本，暂不做按钮卡片） |

### 页面2：知识块审核工作台（新增独立页面）

**URL**：`/admin/chunks`（独立页面，可嵌入Open WebUI的iframe或新开标签页）

| 功能区域 | 内容 |
|---------|------|
| **筛选栏** | 按文档分类下拉筛选；按审核状态筛选（全部/待审核/已通过/已驳回）；按文件名搜索 |
| **列表区** | 表格展示：序号、文件名、章节名、内容预览（80字）、状态标签、操作按钮 |
| **详情/编辑区** | 点击行展开或侧滑出详情，显示完整内容，提供：通过、驳回、编辑分类（下拉修改）、编辑章节标题 |
| **批量操作** | 全选 → 批量通过 / 批量驳回 |

**注意**：MVP版本不做“合并”和“拆分”功能。如果块切错了，业务人员直接驳回，开发人员重新切分。

### 页面3：图谱画布（新增独立页面）

**URL**：`/admin/knowledge_graph`（独立页面）

| 功能区域 | 内容 |
|---------|------|
| **画布区** | 使用开源库（推荐 **AntV G6** 或 **vis-network**），渲染实体为节点，关系为连线 |
| **智能解析按钮** | 点击后，后端调用LLM扫描所有 `review_status='approved'` 的chunk，抽取实体和关系，生成初始图谱布局 |
| **手动添加** | 双击画布空白 → 弹出输入框，输入实体名称和分类 → 节点出现 |
| **手动连线** | 从一个节点拖拽到另一个节点 → 弹出选择关系类型（依赖/被使用于/包含/平级） |
| **查看关联块** | 点击节点 → 右侧面板显示该实体关联的所有知识块列表（文件名、章节） |
| **搜索高亮** | 搜索框输入关键词 → 画布匹配的节点高亮闪烁 |

**注意**：MVP版本不做“合并节点”、“版本快照”、“批量导入导出”。


## 五、业务流程（极致简化版）

### 5.1 文档入库流程

```
用户上传PDF/Word
  ↓
后端脚本执行：
  【清洗】用python-docx/pdfplumber提取文本，去除页眉页脚（简单规则）
  【分块】按段落分割，识别标题行（如“5.3.1.”或“##”），按标题组织
  【元数据】填充 doc_category（用户上传时选择）、section_title
  【入库】存入向量库，review_status = 'pending'
  【异步】调用LLM抽取实体，存入entities表（created_by='system'）
  ↓
审核工作台出现待审核条目
```

### 5.2 用户问答流程

```
用户提问 + 选择分类过滤（可选）
  ↓
系统执行检索（带doc_category过滤）
  ↓
如果有结果 → 返回答案 + 来源
  ↓
如果无结果 → 提示“未找到”
  ↓
【System Prompt驱动的反问】
当问题包含“飞行物体”等已知歧义词时，AI自动反问（无需额外代码）
```


## 六、技术选型建议

| 技术领域 | 选型 | 理由 |
|---------|------|------|
| **后端框架** | FastAPI | AI训练数据多，代码生成准确；性能好 |
| **前端框架** | React + Ant Design | 组件丰富，开发速度快 |
| **图谱库** | AntV G6 | 国产开源，文档全，AI生成代码质量高；支持拖拽、连线、高亮 |
| **向量库** | ChromaDB（现有） | 保持Open WebUI兼容 |
| **关系库** | SQLite（MVP够用） | 单机部署，无需额外服务；后续可迁移到PostgreSQL |
| **分块库** | `unstructured` + `pdfplumber` | 组合使用，AI生成的代码示例多 |
| **LLM调用** | Ollama（现有） | 保持现有qwen3:30b |
| **嵌入模型** | qwen3-embedding（现有） | 保持现有 |



## 八、风险与应对

| 风险 | 应对措施 |
|------|----------|
| 4周时间不够 | MVP可砍掉“图谱画布”的智能解析功能，改为手动录入；先只做“审核工作台+分类过滤+Prompt反问” |
| AI生成的G6代码不工作 | 先用G6官方Demo改，让AI帮改配置参数，不追求复杂交互 |
| 分块效果差 | 先用 `unstructured` 默认配置，不优化规则；后续再迭代 |
| 反问不稳定（Prompt方式） | 在System Prompt中明确写出歧义词列表和对应选项；后续再开发硬编码规则表 |


## 九、交付验收标准

| 验收项 | 验收方式 | 标准 |
|--------|---------|------|
| 文档入库 | 上传3份不同分类的Word/PDF | 生成的知识块包含正确的 `doc_category` 和 `section_title` |
| 审核工作台 | 打开页面查看并操作 | 可看到待审核列表；点击“通过”后状态变更；检索时只返回已通过的块 |
| 分类过滤 | 在对话页面选择分类后提问 | 返回结果只属于该分类 |
| 图谱画布 | 打开画布页面 | 能看到AI抽取的实体节点；双击可新增节点；拖拽可连线 |
| 反问能力 | 提问“飞行物体怎么配置” | AI反问“请问您是指运维手册还是开发手册中的？” |
| 旧数据兼容 | 提问已迁移的旧chunk内容 | 能返回正确结果，或提示“未找到” |
