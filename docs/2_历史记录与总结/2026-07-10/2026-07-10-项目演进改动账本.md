# 项目演进改动账本

## 目的

记录从知识图谱建立以来的重要架构变化，避免只看到代码修改而不了解业务原因。

---

# 阶段 1：RAG 基础能力建设

完成：

- 文档解析
- Chunk 切分
- Chroma 向量检索
- BM25
- Hybrid Search
- Reranker
- 评估体系

目标：

提升“找到正确文档”的能力。

---

# 阶段 2：知识图谱建设

引入 SQLite Graph DB。

目标：

解决纯向量检索无法处理的问题：

- 同义词
- 实体关系
- 字段归属
- 章节归属

建立：

```
Entity
Relation
Alias
Evidence Link
```

---

# 阶段 3：Graph Phase B

加入规则抽取：

```
SectionPathExtractor
TableFieldExtractor
ConfigBlockExtractor
```

采用：

```
extract
 ↓
review
 ↓
apply
```

避免自动污染正式图谱。

---

# 阶段 4：Task 8.1

问题：

原先领域事实存在于 Profile JSON，Graph 和 Profile 双维护。

风险：

- 两套事实源不一致
- 修改困难
- 无法审计

改为：

运行时：

```
policy JSON
+
Graph approved facts
```

不再读取 legacy domain facts。

---

# 阶段 5：Task 8.2

解决正式 Graph 和迁移逻辑不一致。

主要修复：

## Field

旧：

```
管点编号
```

新：

```
管线点表.管点编号
```

## Section

旧迁移可能创建裸路径。

统一使用：

```
source::section_path
```

## Alias

旧方案容易创建重复 Section。

新方案：

```
canonical Section
+
approved alias
```

运行时派生匹配。

---

# 当前理解

这些修改不是为了增加功能，而是在解决：

```
测试数据形态
≠
正式 Graph 数据形态
```

的问题。
