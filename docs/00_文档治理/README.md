### 为什么不把“证据”单独做一级目录

一个任务包的 PRD、阶段总结、fixture、审计 JSON、评测报告必须能一起回放。将 JSON / CSV / PDF 统一搬进“证据目录”会切断 provenance。因此一级状态仍由**任务状态**决定，文件角色只作为元数据：

- 主文档 / PRD
- 阶段总结 / 决策记录
- 验收证据 / 评测快照
- fixture / 原始材料
- 迁移占位 / 兼容入口

## 7. 后续文档治理铁律

1. 新 PRD 必须有 `状态`、`基线日期`、`被谁替代/替代谁`。
2. 新版本生效时，旧版本当天改为“历史过时”，不得多个“终态版”并存。
3. 实施完成必须用代码路径 + 测试/验收结果结项，不以 PRD 文案自称“完成”为准。
4. “待执行”目录只能存在真正未开始的工作；已有代码落地必须转“实施中”。
5. 迁移占位文件只允许短期兼容，最终统一删除；禁止长期形成两套导航。
6. 任何架构图必须标注源码基线日期；超过重大架构变更后自动降级为历史快照。
