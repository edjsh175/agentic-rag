## 一、项目概述

### 1.1 背景与问题

08-13 已做到：无产品名的写代码问句强制出 J3 卡、选定后走 J3 改写、手册 API 可同块召回。2026-08-14 按该 PRD 题集实机验证时，**点名产品后的一轮直达失败**：

| 问句 | Job 层（正确） | 澄清层（错误） |
|------|----------------|----------------|
| 在 StampWebRTC 中，如何用代码初始化并加载 StampUtil？ | `j3`，`subject_clear=true`，`needs_j3_clarify=false`，hint=`StampWebRTC` | `needs_clarification=true`，`reason=multi_entity_match`，**15** 项，含 `PipelineWebRTC` / `PipelineWebGL` |
| 使用 StampWebGL 接口写一段创建折线的代码… | 同上，hint=`StampWebGL` | **13** 项，同样含 Pipeline* |
| 写一段创建折线的代码…（无产品名） | `j3`，需反问 | J3 卡 6 项、**无** Pipeline*（08-13 目标仍成立） |
| 如何通过代码修改多边形的填充颜色并设置透明度？ | `job=other`（手段词未命中） | 不出卡、不走 J3 |
| 在 PipelineBuilder 中如何新建工程？ | `j2`（保护词正确） | 通用卡 **11** 项（含 StampWebGL/WebRTC） |
| StampWebRTC 是什么 | `other` | 通用卡 **15** 项 |
| WebGL 客户端主要提供哪些三维展示功能？ | `other` | 3 选 1（WebGL / PipelineWebGL / StampWebGL）——**这条家族歧义合理** |

线上 Helper LLM 开启时，点名 WebRTC 的问法被写成「您指的是 StampWebRTC 这个产品还是其他相关的模块或工具？」；`llm_enabled=false` 时问法换成「问题可能对应多个产品/模块…」。**要不要问、选项清单，两条路径结果一样。**

### 1.2 根因（第一性）

现行反问用的是错误规则：

> 家族扩展后种子数 ≥ 2 ⇒ 必须问用户。

这把**图谱密度**（`Stamp*` / `WebRTC*` / 管线家族邻居多）当成了**用户不确定性**。

正确规则只有一条：

> 问句 + 已选项，能否唯一确定「本 Job 合法的检索 canonical」？
> - 能，且合法 → 不问，直接检索
> - 能，但对本 Job 非法 → 不问也不按该锚检索（改道或短拒答）
> - 不能 → 只在本 Job 的合法子图里问

08-13 的 J3 门只在 `needs_j3_clarify=true` 时截断。点名 D2 后该标志为 false，流程落入 [`query_clarification.py`](../../../rag_knowledge/services/query_clarification.py) 通用 `_collect_backbone_seed_names`，再按种子数量出卡。于是 J3 已经排除的 Pipeline* 从侧门回到卡片。

这不是「J3 特例」，J2「在 PipelineBuilder 中如何新建工程」、J1「StampWebRTC 是什么」是同一类错。真正仍该问的是**家族宽词**（如只说「WebGL」），不是**具体 canonical**。

### 1.3 第一性原理（设计公理）

| # | 公理 | 含义 |
|---|------|------|
| A1 | 反问只绑定开放变量 | 卡片解决「本次检索该用哪个合法 canonical」；不枚举图邻居 |
| A2 | 指称唯一且合法 → 零反问 | 问句或已选项已写出具体产品/工具名，且该名对本 Job 合法 → `needs_clarification=false` |
| A3 | 指称唯一但非法 → 不检索 | J3 点名 Pipeline* 等 D3：不得因「点了名」而正锚检索；改道 J3 卡或短拒答 |
| A4 | 未绑定只问合法子图 | J3 未点名：强制出卡（08-13 A8 保留）；硬排除 Pipeline*；家族宽词只出该家族合法项 |
| A5 | 一套裁决者 | Job 完成绑定后，通用主干预检 / Helper LLM **不得**再把 `needs_clarification` 改回 true |
| A6 | 选项必须结束不确定或改 Job | 可提交项：绑定 D2，或 COM 短拒答，或 Explorer 改 J2。`SDK` / `二次开发与集成层` 不是答案 |
| A7 | 拒答诚实 | 能力边界不得冒充「未查询到相关内容」；「其他」不能空锚放行检索 |

违反 A2/A5 的方案（点名仍家族全列、Helper 否决已绑定的 Job）不接受。  
违反 A3 的方案（naive「点了名就一律不问」从而放行 J3×Pipeline*）不接受。  
违反 A4 的方案（无产品写代码静默猜 WebRTC/WebGL、或关图谱）不接受。

### 1.4 目标

1. **绑定函数成为唯一反问裁决**：废除「种子 ≥ 2 ⇒ 反问」。
2. **点名合法锚一轮直达**：StampWebRTC/WebGL 写代码、PipelineBuilder 操作、StampWebRTC 是什么，均不再弹卡。
3. **非法锚不静默正锚**：J3×Pipeline* 不得写入 `backbone_canonical`。
4. **J3 卡可提交项收口**：仅 D2 + COM + Explorer；D2 排前；无 Pipeline*、无层名/SDK 可提交项。
5. **手段词覆盖口语**：「通过代码」「用代码」进入 J3；单独样式词仍不强制 J3（08-13 N4 保留）。
6. **COM /「其他」诚实**：范围拒答；自定义输入必须映射或再问/短拒答。

### 1.5 非目标

| 非目标 | 说明 |
|--------|------|
| 重开 08-13 改写 / api_doc 切块 / Cookbook 入库 | 已结项；本文不推翻 G2/G3 历史落盘 |
| 关闭 `graph_retrieval` / `query_rewrite` | 与 08-13 已否定方案相同 |
| 两轮反问（产品一轮、调用面一轮） | 一张卡问清 |
| 静默分类 WebRTC vs WebGL | 无产品名时仍强制反问 |
| 对接口说明书套 StampTools LLM 抽图 | 08-13 Phase 4；本文不立项 |
| 本 PRD 内改 `config-prod.ini` 开图 | 生产开图仍走既有决策 |
| 把 G3 历史 4/4 改判 FAIL | 副轨可加严抽样，不回溯否定结项 |

## 三、目标架构

```text
Query
  → 规则判定 Job（手段词 + J2 保护词 + 点名实体）
  → 绑定 canonical（问句点名 或 卡片已选）
        未绑定 + Job=J3     → 只出二次开发子图卡
                              可提交：StampWebRTC / StampWebGL / COM / Explorer
        未绑定 + 家族宽词   → 只出该家族合法选项（如 WebGL 三选 1）
        已绑定且合法        → 禁止任何反问，进入该 Job 模板检索
        已绑定但对 Job 非法 → 禁止按该锚检索；J3×Pipeline* → 改道 J3 卡或短拒答
  → Helper LLM 只写问法 / 排序，不得否决「已绑定合法」
  → J3 生成（副轨）：手册 api_doc 为主；不得与 Cookbook 缝同一可粘贴块
```

「具体 canonical」：主干上的 Product/Tool 正式名或其明确别名（`StampWebRTC`、`PipelineBuilder`）。  
「家族宽词」：`WebGL`、`WebRTC`、`管线`、`pipeline` 等可对应多个具体产品的表面词。


## 四、功能需求

### FR-1 绑定函数（根因）

新增（或等价收口）单一函数，输入：问句、`entity_name`、`clarification_selected`、已判定 Job。输出：`{bound, canonical, legal}`。

- **废除**「家族扩展种子数 ≥ 2 ⇒ 反问」作为是否出卡的主条件。
- 比较题仍走 `_is_explicit_comparison`（两边都写出则不问）。
- `analyze()` 必须先问绑定函数，再决定出哪张卡或放行。Job 已绑定且 `legal=true` 时，**禁止**进入 `_collect_backbone_seed_names` / `_analyze_via_llm` / `_analyze_backbone_fallback`。

落点：`query_clarification.py` `analyze()`；绑定逻辑可放 `sdk_code_job.py` 或与 `backbone_guard` 共用的指称解析，但**只允许一处裁决**。

### FR-2 点名合法锚零反问

下列问句 `needs_clarification=false`，且不得出现 Pipeline* 选项：

| 题 | 期望 canonical |
|----|----------------|
| 在 StampWebRTC 中，如何用代码初始化并加载 StampUtil？ | StampWebRTC |
| 使用 StampWebGL 接口写一段创建折线的代码… | StampWebGL |
| 在 PipelineBuilder 中如何新建工程？ | PipelineBuilder |
| StampWebRTC 是什么 | StampWebRTC |

家族宽词仍问，例如：「WebGL 客户端主要提供哪些三维展示功能？」→ WebGL / StampWebGL / PipelineWebGL（≥2 且均属该家族，合理）。

### FR-3 非法锚不检索

Job=J3 且问句点名 D3（`PipelineWebGL` 等）：

- **不得** `backbone_canonical` 落入 Pipeline*
- **不得** 开启图扩召回 / 融合（08-13 A6 保持）
- 允许：改道到 FR-4 的 J3 卡（说明当前点名不是 SDK 调用面），或短拒答后引导选 D2
- **禁止**：因「点了名」而按 Pipeline* 做写代码检索

### FR-4 未绑定 J3 卡

无产品名、手段词命中（含 FR-5）时，**仍强制出卡**（08-13 A8）。

可提交项（顺序固定）：

1. StampWebRTC 二次开发（StampUtil）
2. StampWebGL 二次开发（StampUtil）
3. COM / Ax 接口（首期仅 StampUtil）→ 选定后短拒答
4. Explorer / 桌面端操作（不是写代码）→ 只切 Job=J2，不伪造 canonical

约束：

- 不含任何 `Pipeline*`
- **不含** `SDK`、`二次开发与集成层` 可提交项（可作分组文案，不可 `entity_name` 提交）
- 优先序必须按上表生效（修复正式名 vs casefold `seen` 的匹配 bug）
- 选 SDK/层名若仍从旧客户端传入：继续当辅助项，**不得当检索 canonical**，必须再问 D2（与 08-13 一致）

### FR-5 手段词

在 `_J3_ACTION_PATTERNS`（或绑定函数的 Job 判定）纳入工具性标记，至少：

- 已有：`写代码`、`写一段`、`代码示例`、`示例代码`、`二次开发`、`接口调用`、`StampUtil`、`接口说明书`
- 新增：`通过代码`、`用代码`

仍不单独强制 J3（N4）：`创建折线`、`填充色`、`透明度`、`linecolor` 等样式/标绘词。  
不把光杆「代码」当作手段词（避免「代码在哪 / 代码报错了」）。

### FR-6 拒答与「其他」

- COM 短拒答**禁止**以「当前知识库中未查询到相关内容。」为首句。改为能力范围说明：首期仅 StampUtil（StampWebRTC / StampWebGL），请改选对应选项或查阅 COM/Ax 手册。
- 前端「其他（自定义输入）」：提交前将文本映射到已知选项的 `entity_name`；无法映射则不出检索，返回再问或短拒答。
- 后端：仅有 `clarification_selected`、无合法 `entity_name` 时，**不得**视为已绑定而跳过 D10 禁猜。无法绑定则短拒答或等价于未选定。

### FR-7 证据体裁（副轨，不挡 Phase 0）

J3 生成 context 不得把 Cookbook 教程碎片与手册 API 缝进**同一段**可粘贴代码（例如 `<script src="pixelstreaming.js">` 与 `import StampUtil from "@/utils/StampUtil"` 与 `StampAPI.initVideoPlayer` 拼成一块）。

- 手册 `api_doc` 为治本；Cookbook 为对照轨（08-13 D4 不变）
- Phase 0 **不以**本条为门禁
- 若做：G3 增加「单一运行时」抽样；**不**把 08-13 `eval_j3_e2e_20260814-111803.json` 的 4/4 改判为失败
