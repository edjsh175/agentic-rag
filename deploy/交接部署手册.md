# RAG 知识库问答系统 交接部署手册

文档日期：2026-08-13
适用对象：负责系统首次部署的实施人员（无需具备 Docker 或编程基础）。
使用说明：请严格按照章节顺序执行；每条命令请逐条复制执行；任一步骤执行失败时，请立即停止并反馈交付方，切勿跳步或自行调整。

---

## 0. 系统架构概览

```text
用户浏览器
    → http://<业务机IP>:18080/
         → rag-web 容器（前端页面）
              → rag-service 容器（问答服务，端口 10605）
                   → 算力机 Ollama :11434（大模型推理）
                   → 算力机 Rerank :8001（精排服务）
```

部署需准备两台服务器（物理机或虚拟机均可）：

| 服务器 | 职责 | 建议操作系统 |
|---|---|---|
| **业务机** | 运行 Docker 中的 RAG 前后端服务；存放业务文档 | Linux（x86_64） |
| **算力机** | 运行 Ollama 与 Rerank 服务 | Windows 或 Linux 均可（配备 GPU 更佳） |

业务机须能够访问算力机的 `11434` 与 `8001` 端口。

## 2. 部署前准备工作

### 2.1 人员与权限要求

- 业务机：具备 `sudo` 权限的账号（或 root）
- 算力机：可安装软件并开放防火墙端口
- 请预先记录以下两个 IP 地址：
  - 业务机 IP：`__BIZ_HOST__`（示例：`192.168.1.10`）
  - 算力机 IP：`__OLLAMA_HOST__` / `__RERANK_HOST__`（通常为同一台，示例：`192.168.1.20`）

下文所有 `__OLLAMA_HOST__`、`__RERANK_HOST__`、`__BIZ_HOST__` 占位符，请统一替换为实际 IP（无需保留尖括号）。

### 2.2 磁盘空间要求

| 位置 | 建议空闲 |
|---|---|
| 业务机 `/data` | ≥ 50 GB（镜像 + 后续文档 + 向量库） |
| 算力机（模型） | ≥ 80 GB（视模型大小而定） |

### 2.3 网络连通性自检（在业务机执行）

将 `__OLLAMA_HOST__` 替换为算力机实际 IP 后执行：

```bash
ping -c 2 __OLLAMA_HOST__
```

验证标准：应能正常 ping 通。部分网络环境禁用 ICMP 协议，此时 ping 不通不代表后续操作失败，最终以 curl 验证结果为准。

## 3. 业务机：安装 Docker

请以 root 或具有 sudo 权限的账号登录业务机。

### 3.1 检查是否已安装

```bash
docker --version
docker compose version
```

验证标准：两条命令均能输出版本号。如已安装，请直接跳至第 4 章。

### 3.2 安装（以 Debian / Ubuntu 为例）

如命令执行报错，请记录完整错误信息并反馈交付方，切勿擅自更换软件源或尝试其他安装方式。

```bash
apt-get update
apt-get install -y ca-certificates curl
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc
```

若为 Ubuntu，继续执行：

```bash
. /etc/os-release
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu ${VERSION_CODENAME} stable" > /etc/apt/sources.list.d/docker.list
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
systemctl enable --now docker
docker --version
docker compose version
```

若为 RHEL / CentOS / 麒麟等发行版，请联系交付方提供对应安装包，或使用内部已批准的 Docker 安装方式。安装完成后同样执行：

```bash
systemctl enable --now docker
docker --version
```

## 6. 业务机：配置文件 IP 配置

请编辑配置文件：

```bash
vi /data/rag_python/config.ini
```

（如不熟悉 `vi` 编辑器，可使用 `nano /data/rag_python/config.ini`。）

### 6.1 替换两处占位符

请在文件中搜索并替换：

| 占位符 | 替换为 |
|---|---|
| `__OLLAMA_HOST__` | 算力机 IP（运行 Ollama 的服务器） |
| `__RERANK_HOST__` | 算力机 IP（运行 Rerank 的服务器，通常与上相同） |

修改完成后应类似：

```ini
[ollama]
base_url = http://192.168.1.20:11434

[reranker]
base_url = http://192.168.1.20:8001
```

### 6.2 配置注意事项

1. 严禁将地址写为 `http://127.0.0.1:11434` 或 `http://localhost:11434`（在 Docker 容器内，该地址指向容器自身，而非算力机）。
2. 地址必须包含 `http://` 协议头及端口号。
3. 修改完成后，请勿先行重启相关服务，后续将统一启动。

配置检查：

```bash
grep -nE 'base_url|^llm |^embedding |^helper_llm|^vision ' /data/rag_python/config.ini
```

验证标准：应能看到实际 IP，且包含：

```text
embedding = qwen3-embedding
llm = deepseek-r1:14b
helper_llm = gemma3:4b
vision = qwen3-vl:8b
```

## 7. 算力机 A：安装 Ollama 并拉取模型

以下操作在算力机执行。

### 7.1 安装 Ollama

- Windows：打开 [https://ollama.com/download](https://ollama.com/download) 完成安装，安装完成后确认托盘或服务正常运行。
- Linux：

```bash
curl -fsSL https://ollama.com/install.sh | sh
systemctl enable --now ollama
```

### 7.2 配置局域网访问（必要步骤）

Ollama 默认仅监听本机地址，需调整配置以允许业务机访问。

**Linux 示例**（按实际发行版调整）：

```bash
mkdir -p /etc/systemd/system/ollama.service.d
cat >/etc/systemd/system/ollama.service.d/override.conf <<'EOF'
[Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"
EOF
systemctl daemon-reload
systemctl restart ollama
```

**Windows**：请在系统环境变量中新增 `OLLAMA_HOST=0.0.0.0:11434`，随后重启 Ollama 应用/服务；并在防火墙中放行 TCP **11434** 端口。

### 7.3 所需模型清单（与配置文件一致）

请在算力机执行以下命令（需联网，各模型体积较大，请耐心等待下载完成）：

```bash
ollama pull deepseek-r1:14b
ollama pull qwen3-embedding
ollama pull gemma3:4b
ollama pull qwen3-vl:8b
```

用途对照：

| 模型 | 用途 |
|---|---|
| `deepseek-r1:14b` | 主问答 |
| `qwen3-embedding` | 向量化 / 建库 |
| `gemma3:4b` | 辅助（改写等） |
| `qwen3-vl:8b` | 视觉 / 图谱抽取辅助 |

### 7.4 Ollama 安装验证

算力机本机执行：

```bash
ollama list
curl -s http://127.0.0.1:11434/api/tags
```

业务机执行（将 IP 替换为算力机地址）：

```bash
curl -s --max-time 5 http://__OLLAMA_HOST__:11434/api/tags
```

验证标准：返回 JSON，且包含上述四个模型名称。
若业务机访问失败，请检查算力机防火墙配置，及 `OLLAMA_HOST` 是否设置为 `0.0.0.0`。

## 8. 算力机 B：部署 Rerank 服务

Rerank 服务可与 Ollama 部署于同一台算力机。以下以 **Windows** 环境为例（与现网部署一致）；Linux 环境请将盘符路径替换为对应目录。

### 8.1 目录结构（请预先创建）

请在算力机创建以下目录结构：

```text
D:\rag_rerank\
  Python311\          （便携 Python 3.11，或使用系统 Python）
  venv\               （虚拟环境，下一步创建）
  models\bge-reranker-v2-m3\   （模型文件，由交付方提供或按说明下载）
  app\server.py       （从交接包 rerank_service/server.py 拷入）
  run_offline_158.bat
  start_hkcu_158.bat
```

请将交接包内的 `rerank_service/server.py` 及 bat 脚本拷贝至对应位置。
模型目录 `models\bge-reranker-v2-m3\` 须为完整的本地模型文件，部署时采用离线模式，严禁运行时从 HuggingFace 在线下载。

### 8.2 创建虚拟环境并安装依赖（仅首次部署时执行）

在算力机 PowerShell / CMD 中执行（路径按实际调整）：

```bat
D:\rag_rerank\Python311\python.exe -m venv D:\rag_rerank\venv
D:\rag_rerank\venv\Scripts\python.exe -m pip install -U pip
D:\rag_rerank\venv\Scripts\python.exe -m pip install fastapi uvicorn pydantic torch --index-url https://download.pytorch.org/whl/cpu
D:\rag_rerank\venv\Scripts\python.exe -m pip install transformers FlagEmbedding
```

如交付包内已包含构建完成的 `venv`，可跳过本步骤，以包内说明为准。

### 8.3 启动脚本内容核对

`run_offline_158.bat` 应类似：

```bat
@echo off
setlocal
set RERANK_MODEL=D:\rag_rerank\models\bge-reranker-v2-m3
set RERANK_USE_FP16=false
set HF_HUB_OFFLINE=1
set TRANSFORMERS_OFFLINE=1
set HF_HUB_DISABLE_TELEMETRY=1
cd /d D:\rag_rerank\app
D:\rag_rerank\venv\Scripts\python.exe -m uvicorn server:app --host 0.0.0.0 --port 8001
```

关键要求：

1. `RERANK_MODEL` 必须指向本地模型目录。
2. 必须设置 `HF_HUB_OFFLINE=1`。
3. 服务须监听 `0.0.0.0:8001`。

### 8.4 启动

推荐方式：

```bat
D:\rag_rerank\start_hkcu_158.bat
```

或直接执行：

```bat
D:\rag_rerank\run_offline_158.bat
```

### 8.5 防火墙

请放行入站 TCP **8001** 端口。

### 8.6 Rerank 验证

算力机本机执行：

```bat
curl http://127.0.0.1:8001/health
```

业务机执行：

```bash
curl -s --max-time 5 http://__RERANK_HOST__:8001/health
```

验证标准：返回 JSON 中包含 `"status":"ok"`（或同等成功标识）。

提示：如服务器重启后未配置开机自启动，需重新执行启动脚本。

## 9. 业务机：加载镜像并启动容器

以下操作均在业务机执行。

### 9.1 加载镜像

```bash
docker load -i /data/rag_python/rag-backend.tar
docker load -i /data/rag_python/rag-web.tar
docker images
```

验证标准：可看到以下镜像：

- `rag-backend:cpu-http-reranker`（或包内说明的后端标签）
- `rag-web:latest`（或包内说明的前端标签）

如标签不同，请将后续命令中的镜像名称替换为 `docker images` 输出中的实际名称。下文默认：

- 后端：`rag-backend:cpu-http-reranker`
- 前端：`rag-web:latest`

### 9.2 创建专用网络

```bash
docker network create rag-net 2>/dev/null || true
```

### 9.3 启动后端 rag-service

如存在旧容器，请先停止并删除：

```bash
docker rm -f rag-service 2>/dev/null || true
```

启动命令（请勿拆分换行；路径为固定规范）：

```bash
docker run -d \
  --name rag-service \
  --restart unless-stopped \
  --network rag-net \
  -p 10605:10605 \
  -e RERANKER_ENABLED=true \
  -e PYTHONUNBUFFERED=1 \
  -v /data/rag_python/watch_directory:/app/watch_directory \
  -v /data/rag_python/chroma_db:/app/chroma_db \
  -v /data/rag_python/logs:/app/logs \
  -v /data/rag_python/config.ini:/app/config.ini:ro \
  -v /data/rag_python/data:/app/data \
  -v /data/rag_python/scrape_article:/app/scrape_article \
  -v /data/rag_python/scrapingImages:/app/scrapingImages \
  rag-backend:cpu-http-reranker \
  python run.py
```

等待约 30～60 秒（首次启动可能更久）：

```bash
for i in $(seq 1 30); do
  curl -fsS --max-time 3 http://127.0.0.1:10605/health && break
  sleep 3
done
curl -fsS http://127.0.0.1:10605/health; echo
```

验证标准：返回 JSON 含 `"status":"ok"`，且 `"llm"` 字段为 `deepseek-r1:14b`（或配置文件中指定的模型）。

如启动失败：

```bash
docker ps -a --filter name=rag-service
docker logs rag-service --tail 100
```

请将完整日志反馈交付方，并暂停后续操作。

### 9.4 启动前端 rag-web

```bash
docker rm -f rag-web 2>/dev/null || true

docker run -d \
  --name rag-web \
  --restart unless-stopped \
  --network rag-net \
  -p 18080:80 \
  -v /data/rag_python/scrapingImages:/data/scrapingImages:ro \
  rag-web:latest
```

验证：

```bash
curl -fsS -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18080/
curl -fsS http://127.0.0.1:18080/api/health; echo
```

验证标准：第一行返回 `200`；第二行返回健康检查 JSON。

浏览器访问：`http://__BIZ_HOST__:18080/`

## 10. 使用自有资料重建向量库

交接包内不含可用的向量库数据，必须使用自有资料完成建库。

### 10.1 上传业务文档

将待入库文件拷贝至：

```text
/data/rag_python/watch_directory/
```

示例：

```bash
# 假设资料位于 U 盘 /tmp/docs
cp -a /tmp/docs/. /data/rag_python/watch_directory/
find /data/rag_python/watch_directory -type f | head
```

支持常见文档类型：pdf / docx / doc / txt / md / xlsx 等（详见配置 `[scanner] file_types`）。

### 10.2 执行受控重建（首次部署建议使用）

该操作将清空当前向量库与文件索引，并进行全量扫描。
`approve_all_chunks=true`：新入库内容将直接进入可检索状态（否则默认为 pending 状态，检索时无法命中）。

```bash
curl -fsS -X POST http://127.0.0.1:10605/rebuild \
  -H "Content-Type: application/json" \
  -d '{"confirmation":"REBUILD_KNOWLEDGE_BASE","approve_all_chunks":true}'
echo
```

验证标准：返回成功 JSON（执行过程中请勿中断）。
当资料较多或算力机向量化速度较慢时，该过程可能需要数十分钟至数小时。可另开终端窗口查看进度日志：

```bash
tail -f /data/rag_python/logs/rag.log
```

### 10.3 确认向量库数据

```bash
curl -fsS http://127.0.0.1:10605/stats; echo
```

验证标准：`total_chunks` **大于 0**。若仍为 `0`：

1. 确认 `watch_directory` 目录中确实存在文件
2. 查看 `rag.log` 是否报告 Ollama / embedding 相关错误
3. 确认业务机可访问 `http://__OLLAMA_HOST__:11434/api/tags`

### 10.4 日常增量入库（无需每次重建）

新增文件放入 `watch_directory` 后：

```bash
curl -fsS -X POST http://127.0.0.1:10605/scan; echo
```

提示：普通扫描新增的内容默认可能为 `pending` 状态，若问答检索仍无法命中，需通过审核接口处理，或再次采用带 `approve_all_chunks` 的重建策略（请按贵方管理制度执行）。

## 12. 常见问题排查

| 现象 | 排查方向 |
|---|---|
| health 接口失败 | `docker ps -a`；`docker logs rag-service --tail 100` |
| 页面可访问但接口返回 502 | 检查 `rag-service` 是否在同一 `rag-net` 网络；后端是否 healthy |
| stats 持续为 0 | 是否已执行第 10 章重建；文档是否已放入 `watch_directory`；Ollama embedding 是否连通 |
| 有检索来源但「模型未返回有效答案」 | 算力机 Ollama 是否正常运行；主模型是否已拉取；显存是否充足 |
| Rerank 超时 / 报错 | 算力机 `:8001` 健康检查；config 中 `timeout=120`；容器环境变量 `RERANKER_ENABLED=true` |
| 容器内无法连接模型 | config 是否误写 `localhost`；是否误写为业务机自身 IP |
| 修改 config 后不生效 | 执行 `docker restart rag-service` 后重新验证 health |
| 服务器重启后 Rerank 服务消失 | 重新执行 `start_hkcu_158.bat` |

日志位置：

```bash
tail -n 100 /data/rag_python/logs/rag.log
tail -n 50 /data/rag_python/logs/rag_error.log
```
