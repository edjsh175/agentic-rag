# RAG 知识库问答系统 —— 交接部署手册（傻瓜版）

文档日期：2026-08-13
读者：拿到交接包、从零部署的人员（默认不懂 Docker / 编程）。
原则：按章节顺序做；每一步只复制文档里的命令；某步失败就停，不要跳步。

---

## 0. 最终长什么样（先看一眼）

```text
你的浏览器
    → http://<业务机IP>:18080/
         → rag-web 容器（网页）
              → rag-service 容器（问答 API，端口 10605）
                   → 算力机 Ollama :11434（大模型）
                   → 算力机 Rerank :8001（精排）
```

你需要准备两台机器（可以是两台物理机 / 虚拟机）：

| 称呼 | 干什么 | 系统建议 |
|---|---|---|
| **业务机** | 跑 Docker 里的 RAG 前后端；放你们自己的文档 | Linux（x86_64） |
| **算力机** | 跑 Ollama + Rerank 服务 | Windows 或 Linux 均可（有 GPU 更好） |

业务机必须能访问算力机的 `11434` 和 `8001` 端口。

## 2. 提前准备什么

### 2.1 人员与权限

- 业务机：能 `sudo` 的账号（或 root）
- 算力机：能安装软件、能开防火墙端口
- 一张纸记下两个 IP：
  - 业务机 IP：`__BIZ_HOST__`（示例：`192.168.1.10`）
  - 算力机 IP：`__OLLAMA_HOST__` / `__RERANK_HOST__`（通常是同一台，示例：`192.168.1.20`）

下文凡是 `__OLLAMA_HOST__`、`__RERANK_HOST__`、`__BIZ_HOST__`，请全部换成你们的真实 IP（不要带尖括号）。

### 2.2 磁盘建议

| 位置 | 建议空闲 |
|---|---|
| 业务机 `/data` | ≥ 50 GB（镜像 + 日后文档 + 向量库） |
| 算力机（模型） | ≥ 80 GB（视模型大小而定） |

### 2.3 网络自检（业务机上执行）

把 `__OLLAMA_HOST__` 换成算力机 IP 后再跑：

```bash
ping -c 2 __OLLAMA_HOST__
```

期望：能 ping 通（有的环境禁 ping，不通也不代表后面一定失败，以 curl 为准）。

## 3. 业务机：安装 Docker

用 root 或 `sudo -i` 登录业务机。

### 3.1 检查是否已安装

```bash
docker --version
docker compose version
```

期望：两行都打印出版本号。若已有，跳到第 4 章。

### 3.2 安装（Debian / Ubuntu 示例）

若命令报错，把完整报错发给交付方；不要自行换源乱试。

```bash
apt-get update
apt-get install -y ca-certificates curl
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc
```

若是 Ubuntu，继续：

```bash
. /etc/os-release
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu ${VERSION_CODENAME} stable" > /etc/apt/sources.list.d/docker.list
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
systemctl enable --now docker
docker --version
docker compose version
```

若是 RHEL / CentOS / 麒麟等，请交付方另行提供对应安装包，或使用其内部已批准的 Docker 安装方式。装好后同样执行：

```bash
systemctl enable --now docker
docker --version
```

## 6. 业务机：只改配置里的 IP（填空）

编辑配置：

```bash
vi /data/rag_python/config.ini
```

（不会用 `vi` 可用 `nano /data/rag_python/config.ini`。）

### 6.1 全文替换两处占位符

在文件中搜索并替换：

| 占位符 | 改成 |
|---|---|
| `__OLLAMA_HOST__` | 算力机 IP（跑 Ollama 的那台） |
| `__RERANK_HOST__` | 算力机 IP（跑 Rerank 的那台，通常与上相同） |

改完后应类似：

```ini
[ollama]
base_url = http://192.168.1.20:11434

[reranker]
base_url = http://192.168.1.20:8001
```

### 6.2 三条铁律

1. **禁止**写成 `http://127.0.0.1:11434` 或 `http://localhost:11434`（在 Docker 容器里这是容器自己，不是算力机）。
2. 必须带 `http://` 和端口。
3. 改完先不要重启容器以外的东西；后面统一启动。

检查：

```bash
grep -nE 'base_url|^llm |^embedding |^helper_llm|^vision ' /data/rag_python/config.ini
```

期望：能看到你们的真实 IP，以及：

```text
embedding = qwen3-embedding
llm = deepseek-r1:14b
helper_llm = gemma3:4b
vision = qwen3-vl:8b
```

## 7. 算力机 A：安装 Ollama 并拉取模型

在**算力机**上操作。

### 7.1 安装 Ollama

- Windows：打开 [https://ollama.com/download](https://ollama.com/download) 安装，装完确认托盘或服务在跑。
- Linux：

```bash
curl -fsSL https://ollama.com/install.sh | sh
systemctl enable --now ollama
```

### 7.2 允许局域网访问（重要）

默认 Ollama 有时只监听本机。需要让业务机能连。

**Linux 示例**（按实际发行版调整）：

```bash
mkdir -p /etc/systemd/system/ollama.service.d
cat >/etc/systemd/system/ollama.service.d/override.conf <<'EOF'
[Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"
EOF
systemctl daemon-reload
systemctl restart ollama
```

**Windows**：在「系统环境变量」中新增 `OLLAMA_HOST=0.0.0.0:11434`，然后重启 Ollama 应用/服务；防火墙放行 TCP **11434**。

### 7.3 必拉模型清单（与 config 一致）

在算力机执行（联网；每个模型体积很大，请耐心等待）：

```bash
ollama pull deepseek-r1:14b
ollama pull qwen3-embedding
ollama pull gemma3:4b
ollama pull qwen3-vl:8b
```

用途对照：

| 模型 | 用途 |
|---|---|
| `deepseek-r1:14b` | 主问答 |
| `qwen3-embedding` | 向量化 / 建库 |
| `gemma3:4b` | 辅助（改写等） |
| `qwen3-vl:8b` | 视觉 / 图谱抽取辅助 |

### 7.4 验收 Ollama

在**算力机本机**：

```bash
ollama list
curl -s http://127.0.0.1:11434/api/tags
```

在**业务机**（把 IP 换成算力机）：

```bash
curl -s --max-time 5 http://__OLLAMA_HOST__:11434/api/tags
```

期望：返回 JSON，且包含上面四个模型名。
若业务机 curl 失败：查算力机防火墙 / `OLLAMA_HOST` 是否为 `0.0.0.0`。

## 8. 算力机 B：部署 Rerank 服务

Rerank 与 Ollama 可在同一台算力机。下面以 **Windows** 路径为例（与现网一致）；Linux 把盘符路径改成对应目录即可。

### 8.1 目录布局（建好这些文件夹）

在算力机建立：

```text
D:\rag_rerank\
  Python311\          （便携 Python 3.11，或改用系统 Python）
  venv\               （虚拟环境，下一步创建）
  models\bge-reranker-v2-m3\   （模型文件，由交付方提供或按说明下载）
  app\server.py       （从交接包 rerank_service/server.py 拷入）
  run_offline_158.bat
  start_hkcu_158.bat
```

把交接包里的 `rerank_service/server.py` 以及 bat 脚本拷到对应位置。
模型目录 `models\bge-reranker-v2-m3\` 必须是**完整本地模型**，部署时设离线，禁止运行时去拉 HuggingFace。

### 8.2 创建虚拟环境并装依赖（仅首次）

在算力机 PowerShell / CMD（路径按实际）：

```bat
D:\rag_rerank\Python311\python.exe -m venv D:\rag_rerank\venv
D:\rag_rerank\venv\Scripts\python.exe -m pip install -U pip
D:\rag_rerank\venv\Scripts\python.exe -m pip install fastapi uvicorn pydantic torch --index-url https://download.pytorch.org/whl/cpu
D:\rag_rerank\venv\Scripts\python.exe -m pip install transformers FlagEmbedding
```

若交付包内已有装好的 `venv`，可跳过本步，以包内说明为准。

### 8.3 启动脚本内容（核对）

`run_offline_158.bat` 应类似：

```bat
@echo off
setlocal
set RERANK_MODEL=D:\rag_rerank\models\bge-reranker-v2-m3
set RERANK_USE_FP16=false
set HF_HUB_OFFLINE=1
set TRANSFORMERS_OFFLINE=1
set HF_HUB_DISABLE_TELEMETRY=1
cd /d D:\rag_rerank\app
D:\rag_rerank\venv\Scripts\python.exe -m uvicorn server:app --host 0.0.0.0 --port 8001
```

要点：

1. `RERANK_MODEL` 必须指向本地模型目录。
2. `HF_HUB_OFFLINE=1` 必须有。
3. 监听 `0.0.0.0:8001`。

### 8.4 启动

推荐：

```bat
D:\rag_rerank\start_hkcu_158.bat
```

或直接：

```bat
D:\rag_rerank\run_offline_158.bat
```

### 8.5 防火墙

放行入站 TCP **8001**。

### 8.6 验收 Rerank

算力机本机：

```bat
curl http://127.0.0.1:8001/health
```

业务机：

```bash
curl -s --max-time 5 http://__RERANK_HOST__:8001/health
```

期望：JSON 里带 `"status":"ok"`（或同等成功字段）。

**注意**：机器重启后，若未做开机自启，需要再执行一次启动 bat。

## 9. 业务机：加载镜像并启动容器

以下全部在**业务机**执行。

### 9.1 加载镜像

```bash
docker load -i /data/rag_python/rag-backend.tar
docker load -i /data/rag_python/rag-web.tar
docker images
```

期望：能看到类似：

- `rag-backend:cpu-http-reranker`（或包内写明的后端标签）
- `rag-web:latest`（或包内写明的前端标签）

若标签不同，把下面命令里的镜像名改成 `docker images` 里看到的名字。下文默认：

- 后端：`rag-backend:cpu-http-reranker`
- 前端：`rag-web:latest`

### 9.2 创建专用网络

```bash
docker network create rag-net 2>/dev/null || true
```

### 9.3 启动后端 rag-service

若已有旧容器先停掉：

```bash
docker rm -f rag-service 2>/dev/null || true
```

启动（一行不要拆错；路径固定）：

```bash
docker run -d \
  --name rag-service \
  --restart unless-stopped \
  --network rag-net \
  -p 10605:10605 \
  -e RERANKER_ENABLED=true \
  -e PYTHONUNBUFFERED=1 \
  -v /data/rag_python/watch_directory:/app/watch_directory \
  -v /data/rag_python/chroma_db:/app/chroma_db \
  -v /data/rag_python/logs:/app/logs \
  -v /data/rag_python/config.ini:/app/config.ini:ro \
  -v /data/rag_python/data:/app/data \
  -v /data/rag_python/scrape_article:/app/scrape_article \
  -v /data/rag_python/scrapingImages:/app/scrapingImages \
  rag-backend:cpu-http-reranker \
  python run.py
```

等待约 30～60 秒（首次可能更久）：

```bash
for i in $(seq 1 30); do
  curl -fsS --max-time 3 http://127.0.0.1:10605/health && break
  sleep 3
done
curl -fsS http://127.0.0.1:10605/health; echo
```

期望：JSON 含 `"status":"ok"`，且 `"llm"` 为 `deepseek-r1:14b`（或你们在 config 里写的模型）。

若失败：

```bash
docker ps -a --filter name=rag-service
docker logs rag-service --tail 100
```

把日志发给交付方，不要继续。

### 9.4 启动前端 rag-web

```bash
docker rm -f rag-web 2>/dev/null || true

docker run -d \
  --name rag-web \
  --restart unless-stopped \
  --network rag-net \
  -p 18080:80 \

```

期望：第一行 `200`；第二行健康检查 JSON。

浏览器打开：`http://__BIZ_HOST__:18080/`

## 10. 用你们自己的资料重建向量库

交接包**不含**可用的 `chroma_db`。必须用你们的文档建库。

### 10.1 放入文档

把要入库的文件拷到：

```text
/data/rag_python/watch_directory/
```

示例：

```bash
# 假设资料在 U 盘 /tmp/docs
cp -a /tmp/docs/. /data/rag_python/watch_directory/
find /data/rag_python/watch_directory -type f | head
```

支持常见类型：pdf / docx / doc / txt / md / xlsx 等（见 config `[scanner] file_types`）。

### 10.2 执行受控重建（推荐首次部署用这一条）

会清空当前向量库与文件索引，再全量扫描。
`approve_all_chunks=true`：新入库块直接可检索（否则默认 pending，页面会「查不到」）。

```bash
curl -fsS -X POST http://127.0.0.1:10605/rebuild \
  -H "Content-Type: application/json" \
  -d '{"confirmation":"REBUILD_KNOWLEDGE_BASE","approve_all_chunks":true}'
echo
```

期望：返回成功 JSON（不要中途 Ctrl+C）。
资料多、算力机 embedding 慢时，可能要数十分钟到数小时。可另开窗口看日志：

```bash
tail -f /data/rag_python/logs/rag.log
```

### 10.3 确认库里有数据

```bash
curl -fsS http://127.0.0.1:10605/stats; echo
```

期望：`total_chunks` **大于 0**。若仍是 `0`：

1. 确认 `watch_directory` 里真有文件
2. 看 `rag.log` 是否报 Ollama / embedding 失败
3. 确认业务机能访问 `http://__OLLAMA_HOST__:11434/api/tags`

### 10.4 以后只加文件（不必每次 rebuild）

新文件放进 `watch_directory` 后：

```bash
curl -fsS -X POST http://127.0.0.1:10605/scan; echo
```

注意：普通扫描新增的块默认可能是 `pending`，若问答仍搜不到，需走审核接口或再次使用带 `approve_all_chunks` 的重建策略（按你们管理制度执行）。

## 12. 出问题先看这里（高频）

| 现象 | 先查什么 |
|---|---|
| health 失败 | `docker ps -a`；`docker logs rag-service --tail 100` |
| 页面开了但接口 502 | `rag-service` 是否在同一 `rag-net`；后端是否 healthy |
| stats 一直 0 | 是否执行过第 10 章重建；文档是否在 `watch_directory`；Ollama embedding 是否通 |
| 有检索来源但「模型没有返回有效答案」 | 算力机 Ollama 是否在跑；主模型是否已 pull；显存是否不够 |
| Rerank 超时 / 报错 | 算力机 `:8001` health；config `timeout=120`；容器 env `RERANKER_ENABLED=true` |
| 容器里连不上模型 | config 是否误写 `localhost`；是否写成了业务机自己的 IP |
| 改完 config 不生效 | `docker restart rag-service` 后再测 health |
| 机器重启后 Rerank 没了 | 再跑一次 `start_hkcu_158.bat` |

日志位置：

```bash
tail -n 100 /data/rag_python/logs/rag.log
tail -n 50 /data/rag_python/logs/rag_error.log
```
