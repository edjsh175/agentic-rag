## RAG 知识库问答系统 —— 通用 Docker 部署手册

面向：拿到本仓库源码后，在**任意 Linux 服务器**上完成构建与上线的人员。
不绑定特定内网 IP、账号或现有公司机房拓扑。

若你在维护**已知现网**（构建机 / 公司 Nginx:8004 等），请改看：
[`部署手册（Docker）.md`](./部署手册（Docker）.md)

---

### 0. 你要达成的结果

部署完成后应具备：

1. 后端 API 可访问（默认容器端口 `10605`）
2. 前端页面可打开，且 `/api/` 能转到后端
3. 持久化数据（配置、向量库、业务 data）在宿主机目录，容器删了数据还在
4. LLM / Embedding 服务（通常是 Ollama）从**容器网络**可达

---

### 1. 架构选型（先选一种前端方案）

本仓库同时支持两种前端托管方式，**二选一**即可。

#### 方案 A：双容器（推荐给「干净服务器 / 从零部署」）

```text
浏览器 → 宿主机端口（如 80 或 18080）
         → 容器 rag-web（static_server.py：静态页 + /api 反代）
              → 容器 rag-service:10605
```

- 仓库已有：`web/Dockerfile`、`web/static_server.py`、`docker-compose.yml`
- 优点：少改宿主机 Nginx，跟 compose 一起起停
- 前提：目标机可构建或可导入镜像；构建前需先有 `web/dist`

#### 方案 B：宿主机 Nginx/Caddy + 仅后端容器（适合已有 Web 入口）

```text
浏览器 → 宿主机 Web 服务器（任意端口 / HTTPS）
         ├─ 静态目录（放入 web/dist 内容）
         └─ /api/ 反代 → 127.0.0.1:10605（或宿主机映射的后端端口）
              → 容器 rag-service
```

- 优点：沿用公司已有域名、证书、端口策略
- 只需部署/升级 `rag-service` 镜像 + 覆盖静态文件

两种方案的**后端镜像、配置、数据目录约定相同**。

### 2. 前置条件

#### 2.1 服务器

| 项 | 要求 |
|---|---|
| OS | Linux x86_64（推荐） |
| Docker | 20+，可用 `docker` |
| Compose | `docker compose` 插件，或独立 `docker-compose` |
| 磁盘 | 镜像约数 GB；另为 `chroma_db` / `data` 预留空间 |
| 网络 | 能访问 Ollama（或其它 LLM API）；构建时能拉基础镜像（或离线 load） |

检查：

```bash
docker --version
docker compose version
# 若提示 unknown command / 权限不够：
# ls -la /usr/libexec/docker/cli-plugins/docker-compose
# chmod +x /usr/libexec/docker/cli-plugins/docker-compose
```

#### 2.2 构建机（可与服务器同一台）

- 有本仓库源码
- 若走方案 A 或需生成静态站：需 Node.js 18+（用于 `npm ci && npm run build`）
- 后端镜像构建：需 Docker，基础镜像 `python:3.11-slim`

#### 2.3 模型服务

默认走 Ollama：

- 在某台机器安装并拉取模型，例如：`qwen3-embedding`、问答模型、可选视觉模型
- 在配置里填写**容器能访问到的地址**，例如 `http://192.168.x.x:11434`
- **禁止**写成 `http://localhost:11434`（在容器内 localhost 指向容器自身）

### 3. 目录与占位符约定

下文使用占位符，部署时请统一替换：

| 占位符 | 含义 | 示例 |
|---|---|---|
| `<REPO>` | 源码根目录 | `/opt/rag` |
| `<BASE>` | 宿主机持久化根目录 | `/data/rag_python` |
| `<WATCH>` | 待入库文档目录 | `/data/docs` |
| `<OLLAMA>` | Ollama 根 URL | `http://10.0.0.8:11434` |
| `<WEB_HOST_PORT>` | 方案 A 对外端口 | `80` 或 `18080` |
| `<SERVER_IP>` | 服务器 IP 或域名 | `app.example.com` |

建议首次创建：

```bash
sudo mkdir -p <BASE>/{chroma_db,logs,data,scrape_article,scrapingImages}
sudo mkdir -p <WATCH>
```

### 4. 准备配置文件

1. 复制生产模板：

```bash
cp <REPO>/config-prod.ini <BASE>/config.ini
```

2. 用编辑器修改至少这些项：

```ini
[ollama]
base_url = <OLLAMA>          ; 容器可达，禁止 localhost

[model]
embedding = qwen3-embedding  ; 与 Ollama 中实际模型名一致
llm = <你的问答模型名>
helper_llm = <轻量辅助模型名>
vision = <视觉模型名或留空策略按你们环境>

[vector_store]
persist_directory = /app/chroma_db

[scanner]
watch_directory = /app/watch_directory

[path]
data_dir = /app/data
log_dir = /app/logs

[server]
host = 0.0.0.0
port = 10605

[relational_db]
db_path = /app/data/rag_relational.db

[reranker]
enabled = false              ; 从零默认关；开本地权重需 INSTALL_RERANKER=true
; 若用外部 GPU 机 HttpRerank（推荐瘦镜像），改为：
; enabled = true
; type = http
; base_url = http://<GPU_HOST>:8001
; timeout = 120

[graph_retrieval]
enabled = false              ; 从零部署建议先关；图谱数据就绪后再开
query_rewrite_enabled = false

[graph_extraction.llm]
enabled = false              ; 语义抽取出入库管线，不等于问答开关
```

3. （可选）博客同步、外链等按你们业务填写 `[blog_publish]`；没有就留空或删掉无效 URL。

更完整的能力开关样例可参考 `deploy/config-206-aligned.ini`（含完全体 B：开图 + HttpRerank），但**不要照抄其中的内网 IP / 模型名**，按本机 Ollama 实际模型改。HttpRerank 服务说明见 `deploy/rerank_service/README.md`。

### 5. 准备 data 目录（关键）

Compose/挂载会把宿主机 `<BASE>/data` **完全覆盖**容器内 `/app/data`。

首次部署请放入至少：

```text
agents.json
domain_catalog.json
retrieval_intent_policies.json
document_profile_map.json
file_index.json          ; 可先为空对象 {}，随后由扫描生成
rag_relational.db        ; 可无空库，由程序初始化；或从已有环境拷贝
```

这些文件可从仓库 `data/` 目录拷贝模板（按你们发布包实际内容为准）。

```bash
# 示例：从源码带的模板拷贝（路径以仓库为准）
cp <REPO>/data/agents.json <BASE>/data/
cp <REPO>/data/domain_catalog.json <BASE>/data/
cp <REPO>/data/retrieval_intent_policies.json <BASE>/data/
cp <REPO>/data/document_profile_map.json <BASE>/data/
# file_index / db 按是否有存量数据决定
```

**禁止**用空目录覆盖已有正式环境的 `data/`、`chroma_db/`。

### 6. 构建前端产物（方案 A 与方案 B 都需要）

在能跑 Node 的机器上：

```bash
cd <REPO>/web
npm ci
npm run build
```

确认存在：

```text
web/dist/index.html
web/dist/assets/
```

注意：`web/.dockerignore` **不得**排除 `dist/`（当前仓库已按「预构建打入镜像」调整）。若你改回排除 `dist`，方案 A 镜像会缺前端。

### 7. 编写 / 调整 docker-compose（通用模板）

仓库根目录 `docker-compose.yml` 里的 volume 路径是**某套现网示例**，拿到源码后请改成你的 `<BASE>` / `<WATCH>`。

通用示例（方案 A）：

```yaml
version: "3.8"

services:
  rag-service:
    build:
      context: .
      dockerfile: Dockerfile
      args:
        INSTALL_RERANKER: "false"
    image: rag-backend:cpu-no-reranker
    container_name: rag-service
    restart: unless-stopped
    environment:
      RERANKER_ENABLED: "false"
    volumes:
      - <WATCH>:/app/watch_directory
      - <BASE>/chroma_db:/app/chroma_db
      - <BASE>/logs:/app/logs
      - <BASE>/config.ini:/app/config.ini:ro
      - <BASE>/data:/app/data
      - <BASE>/scrape_article:/app/scrape_article
      - <BASE>/scrapingImages:/app/scrapingImages
    ports:
      - "10605:10605"
    healthcheck:
      test:
        [
          "CMD",
          "python",
          "-c",
          "import urllib.request; urllib.request.urlopen('http://127.0.0.1:10605/health', timeout=5)",
        ]
      interval: 10s
      timeout: 5s
      retries: 12
      start_period: 40s

  rag-web:
    build:
      context: ./web
      dockerfile: Dockerfile
    image: rag-web
    container_name: rag-web
    restart: unless-stopped
    depends_on:
      rag-service:
        condition: service_healthy
    ports:
      - "<WEB_HOST_PORT>:80"
    volumes:
      - <BASE>/scrapingImages:/data/scrapingImages:ro
```

方案 B：可删掉 `rag-web` 服务，只保留 `rag-service`，前端交给宿主机 Nginx。

### 8. 构建与启动

在 `<REPO>` 下：

```bash
# 建议加 --pull=false，避免错误 HTTP 代理导致重复拉基础镜像失败
docker compose build --pull=false
docker compose up -d
docker compose ps
```

后端默认镜像名：`rag-backend:cpu-no-reranker`（`INSTALL_RERANKER=false`，不装 torch/Reranker）。

若只构建后端：

```bash
docker compose build rag-service --pull=false
```

### 9. 方案 B：宿主机 Nginx 示例

静态文件：

```bash
sudo mkdir -p /var/www/ragWeb
sudo rsync -a --delete <REPO>/web/dist/ /var/www/ragWeb/
```

Nginx 片段示例：

```nginx
server {
    listen 443 ssl;
    server_name <SERVER_IP>;

    # ssl_certificate ...;
    # ssl_certificate_key ...;

    root /var/www/ragWeb;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:10605/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

然后：

```bash
nginx -t && systemctl reload nginx
```

### 10. 验收

```bash
# 后端
curl -s http://127.0.0.1:10605/health

# 方案 A（端口按你的映射）
curl -s http://127.0.0.1:<WEB_HOST_PORT>/api/health
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:<WEB_HOST_PORT>/

# 方案 B
curl -s http://127.0.0.1/api/health          # 或 https://<SERVER_IP>/api/health
```

期望：

1. JSON 含 `"status":"ok"`，且 `models.llm` / `embedding` 与 config 一致
2. 前端首页 200，刷新子路由不 404
3. 浏览器能完成一次问答（需 Ollama 模型已拉取且可达）
4. `docker logs rag-service` 无持续报错

容器内测 Ollama：

```bash
docker compose exec rag-service \
  python -c "import httpx; print(httpx.get('<OLLAMA>/api/tags', timeout=5).status_code)"
```

应返回 `200`。

### 11. 离线 / 跨机交付（无构建环境时）

在有 Docker 的构建机：

```bash
docker compose build --pull=false
docker save rag-backend:cpu-no-reranker -o rag-backend.tar
# 方案 A 再导出：
docker save rag-web -o rag-web.tar
```

拷到目标机：

```bash
docker load -i rag-backend.tar
docker load -i rag-web.tar   # 若需要
```

目标机仍需：`docker-compose.yml`（或等价 `docker run`）、`<BASE>/config.ini`、`<BASE>/data`、`<BASE>/chroma_db`（可空库起步）。
然后 `docker compose up -d`（不再 build）。

### 12. 日常升级

#### 12.1 只升级前端

```bash
cd <REPO>/web && npm ci && npm run build
# 方案 A：重建 rag-web 并 up
docker compose build rag-web --pull=false && docker compose up -d rag-web
# 方案 B：rsync dist 到静态目录
rsync -a --delete <REPO>/web/dist/ /var/www/ragWeb/
```

#### 12.2 升级后端

```bash
cd <REPO>
docker compose build rag-service --pull=false
docker compose up -d rag-service
```

或离线：`docker load` 新镜像后替换容器。建议先：

```bash
docker rename rag-service rag-service_old_YYYYMMDD
```

再启动新容器，便于回滚。

#### 12.3 改配置

改的是宿主机 `<BASE>/config.ini`，然后：

```bash
docker restart rag-service
```

---

### 13. 回滚

```bash
docker stop rag-service
docker rename rag-service rag-service_failed
docker rename rag-service_old_YYYYMMDD rag-service
docker start rag-service
```

前端：用升级前的静态目录备份 `rsync` 回去。
配置：恢复 `config.ini.bak_*` 后 `docker restart rag-service`。

### 14. 依赖与镜像原则（勿踩坑）

1. **默认不装本地 Reranker 权重**：`INSTALL_RERANKER=false`；`requirements-base.txt` 不要写 `unstructured[pdf]`（会另路拉 torch）。
2. 生产要开 Reranker，有两条路：
   - **HttpRerank（推荐瘦镜像）**：镜像含 `HttpReranker` 客户端即可；`[reranker] type=http` + `base_url=http://<GPU>:8001`；`-e RERANKER_ENABLED=true`；**不必** `INSTALL_RERANKER=true`。见 `deploy/rerank_service/README.md`。
   - **本地 Cross-Encoder**：重建镜像 `INSTALL_RERANKER=true`、挂载模型目录，并设 `RERANKER_ENABLED=true` / `[reranker] enabled=true`（`type=bge` 等）。
3. Chroma 版本锁定：`chromadb==0.6.3`、`langchain-chroma==0.2.3`；不要用其它环境的 Python 去写同一 `chroma_db`。
4. Embedding 模型变更后必须重建向量库（chunk ID 会变）。
5. 图谱：`graph_retrieval.enabled` 控制运行时扩召回；`graph_extraction.llm` 控制抽入库，二者不是一回事。从零部署建议先关扩召回，待图谱数据就绪再开。

### 15. 故障排查速查

| 现象 | 排查 |
|---|---|
| `/health` 不通 | `docker ps` / `docker logs rag-service`；端口映射；启动是否卡在首次扫描 |
| 页面开但 API 失败 | 方案 A 看 `static_server` 是否指向 `rag-service`；方案 B 看 Nginx `proxy_pass` |
| 问答报连接失败 | config 里 Ollama 是否写成 localhost；容器内 curl `<OLLAMA>/api/tags` |
| `reranker failed` / timed out | Http 模式查 `<RERANK_HOST>:8001/health` 与 `timeout`；本地模式查模型挂载与 `INSTALL_RERANKER` |
| 构建失败拉不下镜像 | 检查 Docker proxy/镜像加速；改用 `--pull=false` 或离线 load |
| Intent/图谱异常 | 是否空 `data/` 覆盖；是否缺 `retrieval_intent_policies.json` 等 |
| `docker compose` 不可用 | 安装或 `chmod +x` CLI 插件 |

### 16. 交付检查清单（通用）

- [ ] `<BASE>/config.ini` 已按本环境改好，`base_url` 非 localhost
- [ ] `<BASE>/data` 含必要 JSON（非空目录覆盖事故）
- [ ] `rag-service` Up，`/health` 返回 ok
- [ ] 前端可打开，`/api/health` 正常
- [ ] 容器内可访问 Ollama（或配置的 LLM API）
- [ ] Reranker 策略与镜像一致（默认关；HttpRerank 则需客户端代码 + 外部 `:8001`，不必装本地 torch）
- [ ] 有配置/静态/旧容器备份或回滚步骤
- [ ] 文档中占位符均已替换为实际值
